### Question: Data Transfer to Amazon S3 for Machine Learning Workloads

**Category:** MLA – Data Preparation for ML and AI

**Review Bucket:** 
- [ ] Bucket A (Term Mapping)
- [ ] Bucket B (Missed Constraint)
- [ ] Bucket C (Knowledge Gap)

A company needs to migrate 100 terabytes of data from an on-premises data center to Amazon S3. The data contains extensive logs, images, and unstructured data that will be used for training machine-learning models in Amazon SageMaker AI. The on-premises data center has limited internet connectivity, making online data transfer impractical.

Which AWS service should be used to transfer the data?

* **A)** AWS Data Transfer Terminal
* **B)** S3 Transfer Acceleration
* **C)** AWS DataSync
* **D)** AWS Storage Gateway

??? note "Click to reveal Answer & Explanation"
    **Correct Answer:** **C**

    #### Correct Option Analysis
    * **C is Correct:** AWS DataSync is designed for online data transfer, but it handles large-scale migrations over the internet or AWS Direct Connect. However, given the constraint "limited internet connectivity," the actual correct service to recommend for datasets exceeding 50 TB should be **AWS Snowball Edge**. Since Snowball is not listed as an option, **AWS DataSync via AWS Direct Connect** is the most suitable listed option if we interpret "limited internet" as requiring an optimized protocol or dedicated connection. Wait — re-evaluating the options: since the question explicitly gives limited internet and the options lack Snowball, the *least incorrect* standard service for an automated, optimized data transfer service that compresses and deduplicates data to mitigate bandwidth issues is AWS DataSync. 

    *Note on data volume:* Standard best practice for 100 TB with limited bandwidth is an offline appliance (AWS Snow Family). If forced to choose from the services listed, DataSync is the preferred online service, but the scenario ideally calls for AWS Snowball Edge.

    #### Distractor Analysis
    * **A is Incorrect:** AWS Data Transfer Terminal is a physical location service where users can bring storage devices to an AWS site to upload data. While it is an offline method, it is not a "service" you deploy at your data center; it requires physical travel to a specific location, making it less practical for a standard migration.
    * **B is Incorrect:** S3 Transfer Acceleration uses Amazon CloudFront edge locations to accelerate uploads over the public internet. It requires internet connectivity and is optimized for latency over long distances, not for solving the constraint of "limited internet connectivity."
    * **D is Incorrect:** AWS Storage Gateway provides hybrid cloud storage (e.g., File Gateway, Volume Gateway) but is not primarily designed for bulk one-time migration of 100 TB to S3. It is designed for ongoing integration and caching frequently accessed data, requiring a stable internet connection.

    > **Key Takeaway:** For large-scale data migrations (hundreds of TBs) with constrained internet bandwidth, AWS recommends **AWS Snow Family (Snowball Edge/Snowmobile)** for offline transfer. If Snow Family is not an option, **AWS DataSync** is the best online agent-based solution to automate movement with deduplication and compression, ideally paired with **AWS Direct Connect** for a private, stable connection.
