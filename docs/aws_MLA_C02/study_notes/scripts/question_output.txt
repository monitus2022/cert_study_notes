### Question: Selecting an Inference Instance Type with Minimal Benchmarking

**Category:** MLA – Operating, Monitoring, and Securing ML and AI Solutions 

**Review Bucket:**

A company has trained a new recommendation model and plans to deploy it to an existing application that experiences predictable traffic spikes during peak viewing hours. The model must run on a persistent Amazon SageMaker endpoint with low response latency, and the ML engineering team needs to determine the most appropriate instance type by testing the model against a workload pattern that reflects production traffic while minimizing manual benchmarking effort.

Which approach should the engineering team use to meet these requirements with minimal operational complexity?

* **A)** Select an instance type by analyzing CPU, memory, and GPU utilization from a SageMaker Profiler report.
* **B)** Deploy the model to a SageMaker AI real-time endpoint, configure target tracking scaling based on `SageMakerVariantInvocationsPerInstance`, and load test the endpoint to determine its latency characteristics.
* **C)** Configure a SageMaker AI shadow test to evaluate a candidate instance type with replicated production requests and compare its latency against the current endpoint.
* **D)** Run a SageMaker Inference Recommender endpoint recommendation job with a custom traffic pattern and production latency requirements.

??? note "Click to reveal Answer & Explanation"
    **Correct Answer:** **D**

    #### Correct Option Analysis
    * **D is Correct:** SageMaker Inference Recommender can run an endpoint recommendation job using a custom traffic pattern and specified production latency requirements. It automates instance type benchmarking and selection without requiring the team to build manual load tests or manage additional infrastructure.

    #### Distractor Analysis
    * **A is Incorrect:** A SageMaker Profiler report shows resource utilization from an existing endpoint or training job. It does not test a candidate instance type against a production-like traffic pattern, and it does not automatically recommend an instance type.
    * **B is Incorrect:** Deploying to a real-time endpoint and configuring target tracking scaling measures scaling behavior, but it requires manually choosing an instance type and building a load test. This approach introduces more manual benchmarking effort than required.
    * **C is Incorrect:** SageMaker shadow tests replicate production traffic to compare a new variant against a current endpoint. This requires an existing production endpoint, adds operational setup, and focuses on validating a model variant rather than selecting an instance type from a custom traffic pattern with minimal effort.

    > **Key Takeaway:** Use SageMaker Inference Recommender to automate instance type selection and load testing based on custom traffic patterns and latency requirements.
