# Skill 4.2.6: Optimize infrastructure costs by selecting purchasing options.

## Task 4.2: Operating, Monitoring, and Securing ML and AI Solutions - Optimize and manage ML and AI infrastructure costs and performance.

### Core Concept: Match Commitment to Billing Unit

> **Primary Exam Gotcha:** Purchasing options cover **specific services**. A commitment is NOT a universal discount. The #1 distractors are applying Compute Savings Plans to SageMaker AI or EC2 Instance Savings Plans to SageMaker AI.

---

### AWS Purchasing Options Decision Matrix

| Purchasing Option | Covers | Best For | Does NOT Cover |
|---|---|---|---|
| **SageMaker AI Savings Plans** | SageMaker AI instance usage (`ml.*`): Real-Time Inference, Batch Transform, Training, Processing, Notebooks | Steady, year-round SageMaker workloads (up to 64% savings) | EC2, Lambda, Fargate, Bedrock token usage |
| **Compute Savings Plans** | EC2, AWS Lambda, AWS Fargate (any region, any family) | Flexible compute across services; interruptible/train-test workloads | SageMaker AI `ml.*` instances |
| **EC2 Instance Savings Plans** | EC2 only, locked to specific instance family + region | Long-running, inflexible EC2 workloads | SageMaker AI, Lambda, Fargate |
| **On-Demand** | All services (no commitment) | Variable, experimental, intermittent workloads | N/A (no discount) |
| **Spot Instances** | Spare EC2 capacity (up to 90% off) | Fault-tolerant, interruptible training jobs with checkpointing | Production inference baselines (capacity can be reclaimed) |
| **Amazon Bedrock Provisioned Throughput** | Dedicated FM inference capacity (model units) | Predictable, high-volume FM inference | On-demand token pricing (no commitment required) |
| **Amazon Bedrock Batch Inference** | Token-based FM inference with asynchronous processing | Large, non-urgent prompt evaluation jobs | Real-time, latency-sensitive requests |

---

### SageMaker AI Savings Plans – Key Facts

- **Commitment type:** Dollar-per-hour ($/hr) spend commitment
- **Term options:** 1-year or 3-year
- **Savings:** Up to 64% vs. On-Demand
- **Flexibility:** Applies across SageMaker instance types, sizes, and regions
- **Coverage:** Real-Time Inference, Batch Transform, Training, Processing, Studio Notebooks, Data Wrangler

> **Hard Rule:** Only `ml.*` SageMaker instances qualify. Standard EC2 instances used for a custom inference stack (e.g., ECS with `c5.*`) fall under **Compute Savings Plans**, not SageMaker AI Savings Plans.

---

### Bedrock Pricing Modes – Purchasing Equivalents

| Bedrock Mode | Billing Unit | Purchasing/Usage Trigger | Use Case |
|---|---|---|---|
| **On-Demand** | Per token (input/output) | No commitment; pay per request | Variable, intermittent, experimental traffic |
| **Provisioned Throughput** | Per model unit per hour (fixed) | Commit to model + throughput level | Steady, predictable, high-volume FM traffic |
| **Batch Inference** | Per token (discounted vs. on-demand) | Submit async jobs | Large offline evaluation; tolerance for delays |
| **Prompt Caching** | Cached input tokens at reduced rate; cache writes at premium | Enable stable prefix (minimum length required) | Repeating, static system prompts/instructions |

> **Exam Gotcha:** Provisioned Throughput translates the "Savings Plans" concept to Bedrock, but it is **not** a Savings Plan. The unit changes from instance hours (SageMaker) to model units (Bedrock).

---

### When to Use What (Decision Logic)

**Steady SageMaker AI inference baseline → SageMaker AI Savings Plans**  
**EC2-based custom ML stack (ECS/EKS) → Compute Savings Plans**  
**Interruptible training job with checkpointing → EC2 Spot Instances**  
**SageMaker Training job with no checkpointing → On-Demand or Savings Plans (do NOT use Spot)**  
**Predictable Bedrock FM traffic → Provisioned Throughput**  
**Experimental/variable Bedrock traffic → On-Demand (do NOT commit)**  
**Large async FM jobs → Bedrock Batch Inference**

---

### Anti-Patterns & Distractors

- **Applying Compute Savings Plans to SageMaker endpoints** – Wrong. Compute Savings Plans do NOT cover `ml.*` instance usage.
- **Applying EC2 Instance Savings Plans to SageMaker training jobs** – Wrong. EC2 Instance Savings Plans are locked to standard EC2 instances only.
- **Using Spot Instances for a production serving baseline** – Wrong. Spot capacity can be reclaimed with a 2-minute warning, invalidating a serving guarantee.
- **Using a Budget to reduce costs** – Wrong. AWS Budgets tracks and alerts; it provides **no discount**.
- **Committing to Provisioned Throughput for intermittent traffic** – Wrong. You pay for reserved model units regardless of utilization; variable traffic belongs on On-Demand.
- **Treating Savings Plans as a service-agnostic discount** – Wrong. Each plan has explicit coverage boundaries.

### Key Data Points & Quotas

| Item | Value |
|---|---|
| SageMaker AI Savings Plans max savings | Up to 64% |
| Compute Savings Plans max savings | Up to 66% (EC2), 17% (Lambda) |
| EC2 Instance Savings Plans max savings | Up to 72% |
| Spot Instance max savings | Up to 90% |
| Provisioned Throughput billing granularity | Per hour per model unit |
| Savings Plans term options | 1-year or 3-year |

### Study Focus Commands

**Memorize this coverage mapping:**

- **SageMaker AI Savings Plans** → SageMaker `ml.*` instances ONLY
- **Compute Savings Plans** → EC2 + Lambda + Fargate (NOT SageMaker)
- **EC2 Instance Savings Plans** → EC2 ONLY (family + region locked)
- **Provisioned Throughput** → Bedrock FM inference (NOT a Savings Plan)
- **Spot** → Interruptible training ONLY (NOT production inference)
- **Budgets** → Alerts, NOT discounts
