# Skill 2.2.2: Configure SageMaker AI Script Mode with Supported Frameworks for Simplicity and Performance

## Task 2.2: Train, Fine-tune, and Customize Models for ML and AI Solutions

---

## Core Concept & Business Objective

**Script Mode** = Bring your own training code (`entry_point`) while AWS provides & maintains the framework container (Deep Learning Containers/DLCs).

| Ownership Aspect | Script Mode | Built-in Algorithm | BYOC (Custom Container) |
|---|---|---|---|
| Training logic | Yours | AWS's | Yours |
| Container maintenance | AWS | AWS | Yours |
| Flexibility | High | Low | Maximum |
| Setup effort | Minimal | Minimal | Heavy |
| Dependency control | Partial (via `requirements.txt`) | None | Full |
| Exam "simplicity" pick | ✅ Primary | ✅ When standard | ❌ Last resort |

> **Exam Gotcha:** Script Mode ≠ Built-in Algorithm. Built-in algorithms supply the training script too; Script Mode supplies *your* script inside an *AWS-managed* framework container.

## Key SDK/Boto3 Configuration Patterns

### PyTorch/TensorFlow Estimator (Boto3 `sagemaker.estimator.Estimator`)

```python
from sagemaker.pytorch import PyTorch

estimator = PyTorch(
    entry_point="train.py",            # Your training script
    source_dir="src/",                 # Local dir with dependencies
    framework_version="2.2.0",         # Pin the DLC version
    py_version="py310",
    role=role_arn,
    instance_count=2,
    instance_type="ml.g5.2xlarge",
    hyperparameters={
        "batch-size": 64,              # Passed as CLI args (argparse)
        "epochs": 20,
        "learning-rate": 1e-3,
    },
    metric_definitions=[                # Custom CloudWatch metrics
        {"Name": "validation:loss", "Regex": "val_loss=([0-9\\.]+);"}
    ],
    environment={...},                  # Env vars for script
)
```

### Script-Side Requirements (train.py)

- **Read hyperparameters via `argparse`** — SageMaker injects them as CLI arguments.
- **Write outputs to `/opt/ml/model`** — artifacts saved here become `model.tar.gz`.
- **Read data from `/opt/ml/input/data/<channel>`** — includes `train/`, `validation/`, `test/`.
- **Emit metrics to stdout** — for CloudWatch regex parsing.
- **Use SM_CHANNEL_<NAME> env vars** for distributed data discovery.

> **Hard Rule:** In Script Mode, SageMaker does NOT create IFP (Image Format Protocol) or file interfaces for you. Your script must manage its own data loading and model serialization — this is the #1 distinguishing feature vs. built-in algorithms.

## Framework Support Matrix

| Framework | Supported? | DLC Notes |
|---|---|---|
| PyTorch | ✅ | Distributed via `torch.distributed` / SDP |
| TensorFlow | ✅ | Distributed via Horovod / Parameter Server |
| Hugging Face | ✅ | Wraps PyTorch/TF DLCs |
| Scikit-learn | ✅ | Lightweight, single-node only |
| XGBoost | ✅ (via script mode) | Or pre-built algorithm image |
| MXNet | ✅ (legacy focus) | Deprecated signals on exam |

> **Exam Gotcha:** Scikit-learn Script Mode does **NOT** support distributed training. If the question needs multi-node scaling, pick PyTorch/TensorFlow.

## Security & Compliance

- **IAM Role** passed to estimator must include:
  - `sagemaker.amazonaws.com` trust policy
  - S3 read/write to training data & output buckets
  - (Optional) ECR pull for custom requirements, CloudWatch `PutMetricData`
- **KMS Encryption:
  - At rest: `output_kms_key` on estimator; S3 bucket-level KMS
  - In transit: S3 HTTPS endpoints (default)
- **VPC Mode:** `subnets` + `security_group_ids` in estimator → isolates training from public internet; requires NAT gateway for DLC pull unless ECR VPC endpoints exist.

| Security Requirement | Config Location |
|---|---|
| Encrypt output artifacts | `output_kms_key="alias/aws/sagemaker"` |
| Encrypt training data | S3 bucket KMS default |
| Private training | `subnets`, `security_group_ids` |
| Custom container pull (priv ECR) | VPC endpoint + IAM condition |

## Optimizing Script Mode Performance

### When to Use Each Parallelism Strategy

| Strategy | Use When | Library |
|---|---|---|
| **Data Parallelism** | Model fits on single GPU/device; dataset large | SM Distributed Data Parallel (SDP), Horovod, `torch.distributed` |
| **Model Parallelism** | Model too large for single device | SM Model Parallel (SMP), DeepSpeed, FSDP |
| **Pipe Mode / Streaming** | Data too large to copy to EBS | `input_mode="Pipe"` in estimator |

### Configuration Choices & Trade-offs

| Choice | Simplicity | Performance | Notes |
|---|---|---|---|
| `instance_count=1` + small instance | Highest | Lowest | Dev/test only |
| `instance_count=N` + data parallel | Medium | High | Requires code changes (`DistributedDataParallel`) |
| Model parallel | Low | Highest for LoRA/LLMs | Requires sharding config |
| Warm pools | Medium | Faster restarts | `keep_alive_period_in_seconds` |
| Checkpointing / Spot | Medium | Cost-efficient | `use_spot_instances=True` |

> **Exam Gotcha:** Instances in Script Mode MUST have their code written to handle distributed execution. SageMaker does not auto-parallelize a single-node script across instances. Look for the option that notes "modify the training script to use DistributedDataParallel" rather than "increase instance count."

## Common Anti-Patterns & Distractors

- ❌ Using BYOC when a prebuilt DLC already supports the framework → wastes effort
- ❌ Hardcoding hyperparameters in the script instead of `argparse` → tuning jobs break
- ❌ Using Script Mode when a built-in algorithm matches the task (e.g., standard tabular regression → use XGBoost algorithm container)
- ❌ Forgetting to set `framework_version` → non-reproducible builds
- ❌ Expecting Script Mode to auto-generate metrics → must define `metric_definitions` regex
- ❌ Choosing Scikit-learn for multi-node training → no distributed support

## Decision Matrix: Which Training Route?

| Scenario | Recommended Route |
|---|---|
| Custom architecture (transformer, GAN, novel loss) | **Script Mode (PyTorch/TF)** |
| Tabular regression/classification, standard metrics | **Built-in (XGBoost/Linear Learner)** |
| Custom dependency (NDB, legacy TF, private library) | **BYOC** |
| Pre-trained FM fine-tuning, few lines of code | **JumpStart** |
| Need Hugging Face `Trainer` API without Docker | **Script Mode (HF estimator)** |
