# Skill 2.1.3: Compare and Select ML Models, GenAI Models, Algorithms & Solution Templates

## Task 2.1: ML Model and Foundation Model (FM) Development — Choose Appropriate Modeling Approaches

---

## The 4-Tier Selection Hierarchy

**Start at the top. Only move down when the lower tier cannot satisfy the requirement.**

| Tier | Problem Profile | Recommended Approach | AWS Implementation |
|:---:|---|---|---|
| **0** | **Fixed business logic** — deterministic rules | Plain code / API call | Lambda Function, Step Functions |
| **1** | **Pre-solved ML task** — OCR, transcription, sentiment, moderation | Managed AWS AI Service | Textract, Transcribe, Comprehend, Rekognition |
| **2** | **Proprietary patterns in tabular/historical data** | Custom supervised/unsupervised training | SageMaker AI built-in algorithms (XGBoost, Linear Learner, DeepAR) |
| **3** | **General language/reasoning/creative generation** | Foundation Model via API — prompt first | Amazon Bedrock (+ fine-tune only if necessary) |

> **Exam Gotcha:** Tier 0 is a valid "modeling approach." If a problem can be solved with a conditional statement, building any ML model is an **anti-pattern** and will be marked incorrect.

---

## Decision Matrices

### Traditional ML vs. Foundation Model (FM)

| Criteria | Train Custom ML Model (SageMaker AI) | Use Foundation Model (Amazon Bedrock) |
|---|---|---|
| **Knowledge source** | Own labeled historical data | General world knowledge (pre-trained) |
| **Data volume required** | Medium–large labeled dataset | Zero–few-shot examples |
| **Interpretability** | ✅ High (SHAP, coefficients, tree structure) | ⚠️ Low (opaque reasoning) |
| **Latency** | ✅ Millisecond–low seconds (real-time endpoints) | ⚠️ Seconds (LLM token generation) |
| **Cost at scale** | ✅ Lower per-inference after training | ⚠️ Higher per-token, scales linearly |
| **Format adaptability** | Tabular → numeric, time series | Natural language, code, dialogue |
| **Explainability via citations** | ❌ Not applicable | ✅ Via RAG source attribution |
| **Update speed for new knowledge** | 🔁 Retrain required | ✅ Instant via prompt or RAG sync |

### Managed AI Service vs. Custom Model vs. FM

| Capability Required | Managed AI Service (AWS) | Custom Model (SageMaker AI) | Foundation Model (Bedrock) |
|---|---|---|---|
| Extract text from scanned invoices/forms | **Textract `AnalyzeExpense`** ✅ | ❌ Overkill — training + labeling | ⚠️ Possible but unverified |
| Sentiment/entities/key-phrases in text | **Comprehend** ✅ | ❌ Requires labeled corpus | ⚠️ Possible via prompt |
| Speech → text transcription | **Transcribe** ✅ | ❌ Specialized audio pipeline | ⚠️ Limited quality control |
| Face/objects/scenes/moderation in images/video | **Rekognition** ✅ | ❌ Huge labeling cost | ⚠️ Multimodal FMs emerging but managed service is simpler |
| Time-series demand forecasting with feature interpretation | ❌ No service | **SageMaker XGBoost/DeepAR** ✅ | ❌ Not designed for tabular precision |
| Ticket summarization with company terminology | ❌ No dedicated service | ❌ Cannot generate prose | **Bedrock FM + prompting** ✅ |

## Fine-Tuning vs. Prompt Engineering vs. RAG

### The Decision Ladder (Memorize This Order)

```
STEP 1: Prompt Engineering (instructions + few-shot examples)
          │
          ├── SUCCESS → Deploy (zero training overhead)
          │
          └── FAILURE (gap persists in evaluations)
                    │
        ┌───────────┴────────────────┐
        ▼                            ▼
   Need domain KNOWLEDGE        Need domain BEHAVIOR
   (external facts, updated)    (style, terminology, format)
        │                            │
    STEP 2a: RAG                 STEP 2b: Fine-Tuning
   (Bedrock Knowledge Bases)     (SFT on labeled JSONL pairs)
        │                            │
        ▼                            ▼
   Content changes reflected     Weight update = retraining
   within minutes via sync       for every content change
```

> **Exam Gotcha:** The prompt-first order is **non-negotiable** in exam logic. Choosing fine-tuning before attempting prompt engineering is the single most common distractor.

### RAG vs. Fine-Tuning: Key Trade-Offs

| Property | RAG (Retrieval-Augmented Generation) | Fine-Tuning |
|---|---|---|
| **Knowledge storage** | External vector store (index) | Inside model weights |
| **Update latency** | Seconds–minutes (re-sync index) | Hours–days (new training job) |
| **Source citation** | ✅ Built-in (chunk metadata) | ❌ Impossible |
| **Catastrophic forgetting risk** | ✅ None — base model intact | ⚠️ Real risk — mitigated by mixing general data |
| **Whole-document synthesis** | ⚠️ Weaker (chunked retrieval) | ✅ Better on domain-specific task fidelity |
| **Cost model** | Pay per embedding + token + vector storage | Pay per training job + hosting fine-tuned model |
| **Ability to combine** | ✅ Can coexist (fine-tuned model + RAG) | |

## Algorithm / Model Selection by Use Case

| Use Case | Recommended Algorithm / Model | Why |
|---|---|---|
| Tabular regression (demand, revenue, churn risk) | XGBoost, Linear Learner | Interpretable, fast, handles non-linear data |
| Structured classification (fraud, churn, anomaly) | XGBoost, KNN, Random Cut Forest | High performance on tabular features |
| Time-series forecasting | **DeepAR** (probabilistic), **Prophet** | Multi-series, seasonality, cold-start support |
| Text multi-class classification | BlazingText (fastText) or fine-tuned BERT | Word-embedding or contextual embeddings |
| Image classification / object detection | SageMaker JumpStart vision transformers / CNNs | Pre-trained transfer learning |
| Anomaly detection (unlabeled) | IP Insights, Random Cut Forest | Unsupervised, streaming capable |
| Entity extraction / key-value pairs from documents | **Amazon Textract** | Fully managed, `AnalyzeExpense`, `AnalyzeID` |
| Sentiment / language detection | **Amazon Comprehend** | Managed, multi-language |
| Audio → text | **Amazon Transcribe** | Managed ASR, custom vocabulary support |
| Image moderation / face search / celebrity detection | **Amazon Rekognition** | Managed, low per-image cost |
| Summarization / Q&A over docs / chat | **Amazon Bedrock** FM + RAG via Knowledge Bases | General language capability |

## Foundation Model Selection on Amazon Bedrock

**Compare FMs on measurable evidence — not reputation.**

| Evaluation Dimension | Metrics / Method |
|---|---|
| **Output quality** | Model evaluation jobs in Bedrock (built-in or custom datasets) |
| **Latency** | InvokeModel p50/p99 latency, streaming vs. batch |
| **Cost per request** | Price per input/output token; throughput pricing |
| **Domain fit** | Medical/code/legal specialized FMs (e.g., Anthropic Claude, Cohere, Meta, Titan) |
| **Guardrail compatibility** | Bedrock Guardrails (content filters, PII redaction, denied topics) |

> **Exam Gotcha:** Selecting a larger FM purely to improve quality without addressing the root gap (prompting, RAG, fine-tuning) is a **distractor**. Larger models increase cost and latency without guaranteed quality gains.

## SageMaker JumpStart (Comparing Pre-Trained Options)

| Feature | Value |
|---|---|
| **What it is** | Pre-trained model hub + solution templates (CV, NLP, LLMs, Tabular) |
| **When to use** | Start from a working baseline — not an empty notebook |
| **Advantages** | Fastest path to transfer learning for vision/text; one-click deploy |
| **Trade-off** | Less control vs. building from scratch; may need fine-tuning on domain data |

## Interpretability Patterns

| Need | AWS Tool / Pattern |
|---|---|
| Global feature importance for trees | SageMaker Clarify + SHAP, built-in XGBoost importance |
| Local feature attribution | SageMaker Clarify `SHAP` reports, bias reports |
| Explainable linear models | Linear Learner (coefficients) |
| Auditable predictions for finance/stakeholders | Transparent models (regression, decision tree) not deep NN |
| Pre-build trust in production | SageMaker Model Cards + Clarify |

> **Exam Gotcha:** When a question asks for **interpretability + tabular data**, deep learning and large FMs are almost always **wrong answers**. Favor explainable tree or linear models.

## Cost / Performance / Latency Trade-Offs

### Custom ML (SageMaker AI)

| Trade-Off | Action |
|---|---|
| Increase accuracy | Add features, larger model, ensemble — **costs training time + infra** |
| Reduce inference latency | Deploy on GPU, asynchronous inference, multi-model endpoints |
| Reduce training cost | Spot instances for training, distributed training only when necessary |
| Reduce hosting cost | SageMaker multi-model endpoints, autoscaling, serverless inference |

### Foundation Models (Bedrock)

| Trade-Off | Action |
|---|---|
| Improve quality | RAG, more in-context examples, larger model — **costs latency + tokens** |
| Reduce latency | Smaller model, stream responses, reduce output tokens (`max_tokens`) |
| Reduce cost | Batch inference, lower-token prompts, smaller model, cache embeddings |
| Need deterministic output | Set `temperature=0`, use JSON mode for structured outputs |

## Security & Compliance (Cross-Cutting Concerns)

| Concern | Implementation |
|---|---|
| **Encryption at rest** | SageMaker: default AWS-managed KMS; optional customer-managed KMS (CMK). Bedrock: FMs store encrypted data; custom models in KMS. |
| **Encryption in transit** | TLS 1.2+ for all Bedrock API calls and SageMaker endpoints |
| **VPC isolation** | SageMaker training/jobs in VPC; Bedrock via **VPC Interface Endpoints** (`bedrock-runtime`, `bedrock`) |
| **IAM least privilege** | `bedrock:InvokeModel`, `bedrock:GetFoundationModel`, `sagemaker:CreateTrainingJob` scoped |
| **Guardrails** | Bedrock Guardrails for PII redaction, topic denial, content policies |
| **Model access** | Explicitly enable specific Bedrock FMs via console/IAM (not all enabled by default) |
| **Prompt injection defense** | Guardrails + explicit system instructions |

## Quick Recall — The Unified Decision Tree

```
1. Fixed deterministic logic?
   └─ YES → Write code. Stop. (No ML.)

2. Problem already solved by AWS AI service?
   └─ YES → Textract / Transcribe / Comprehend / Rekognition. Stop.

3. Patterns only exist in your OWN labeled tabular/historical data?
   └─ YES → Train supervised model (SageMaker AI).
         ├─ Interpretability required → XGBoost / Linear Learner
         ├─ Time-series → DeepAR
         └─ Unlabeled anomaly detection → Random Cut Forest

4. General language generation / understanding needed?
   └─ YES → Amazon Bedrock Foundation Model.
         ├─ Step 1: Prompt Engineering → Evaluate
         ├─ Step 2: External knowledge needed → RAG (Knowledge Bases)
         └─ Step 3: Behavior gap persists → Supervised Fine-Tuning
```
