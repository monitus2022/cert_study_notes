# Skill 2.3.2: Create Model Performance Baselines and Implement Drift Detection

## Task 2.3: Analyze and Evaluate the Performance of ML and AI Systems

---

## Baseline Architecture & Strategy

| Baseline Type | Purpose | Key Metrics | AWS Implementation |
|---|---|---|---|
| **Model Quality Baseline** | Capture reference accuracy/precision on validation data | F1, RMSE, MAE, AUC-ROC | SageMaker Model Registry + CloudWatch |
| **Data Drift Baseline** | Statistical fingerprint of training input distributions | PSI, KL divergence, KS statistic | SageMaker Model Monitor (DataQuality) |
| **Model Drift Baseline** | Distribution of predictions at launch | Prediction drift, label drift (delayed) | SageMaker Model Monitor (ModelQuality) |
| **Bias Drift Baseline** | Reference bias metrics from launch period | Class Imbalance (CI), DPL, CDDPL | SageMaker Clarify (in Model Monitor) |
| **Feature Attribution Drift** | SHAP value distribution baseline | SHAP drift score, top-feature shifts | SageMaker Clarify (Explainability) |
| **Operational Baseline** | Endpoint latency/error/cache-hit norms | p50/p99 latency, 5xx rate, invocation count | CloudWatch Alarms + Anomaly Detection |

**Key Boto3 APIs:**
- `sagemaker.ModelMonitor.create_monitoring_job(baseline_constraints, baseline_statistics)` — creates data/model quality baselines
- `sagemaker.clarify.SageMakerClarifyProcessor.run_bias()` — generates bias baseline job
- `sagemaker.ProcessingJob` — generates baseline outputs (constraints.json, statistics.json)

**Baseline JSON Artifacts (S3):**
- `statistics.json` — column-level means, std, missing counts, numeric ranges, categorical cardinality
- `constraints.json` — derived thresholds (min/max, completeness %, data_type checks)
- `bias_baseline.json` — pre-training & post-training bias metrics
- `explainability_baseline.json` — SHAP feature importance distributions

## Drift Detection Patterns

| Drift Type | Detection Signal | Metric/Threshold | Suggested Alert |
|---|---|---|---|
| **Data Distribution** | Input feature distributions depart from baseline | Population Stability Index (PSI) > 0.1–0.25 | CloudWatch Alarm → SNS |
| **Prediction Drift** | Model output distribution shifts | KL divergence, JS distance, Chi-square over prediction bins | SNS → retrain pipeline trigger |
| **Label Drift** | Ground truth outcomes change vs baseline (delayed by merge job) | Compare AUC/F1 of deployed model against baseline on new labels | SageMaker Model Monitor ≥ 1 baseline job |
| **Bias Drift** | CDDPL or DPL exceeds SOC thresholds | CDDPL ≥ 0.8 → immediate P1 alert; DPL thresholds by use-case | Clarify monitoring job → EventBridge |
| **SHAP Drift** | Feature attributions shift meaning | Normalized discounted cumulative gain over feature ranks | Detailed investigation via Notebook |

> **Exam Gotcha:** PSI thresholds are not universal—0.1 flag, 0.25 alert is a common heuristic. If the exam offers an AWS-native preference, choose SageMaker Model Monitor with *statistical bias* as the automated solution before selecting custom Lambda-based checks.

## SageMaker Model Monitor Configuration Deep-Dive

### Monitoring Job Types
| Type | Captured Data | Geo-spatial Requirement | Baseline Pre-requisite |
|---|---|---|---|
| `DataQuality` | Input features at inference time | Uses `capture_json` from endpoint data capture | Requires `statistics.json` + `constraints.json` |
| `ModelQuality` | Predicted labels + ground truth (merged with `join_source`) | Ground truth can arrive later — once baseline is built with enough labeled samples | Requires first baseline job to learn quality thresholds |
| `ModelBias` | Face/facial gender representation, prediction distributions | Requires SageMaker Clarify processor configuration | Requires `bias_baseline.json` |
| `ModelExplainability` | Feature importance/SHAP values per inference | Requires Clarify config with SHAP baseline | Requires `explainability_baseline.json` |

### Critical Code Parameters (Boto3)
```python
monitor.create_monitoring_schedule(
    monitoring_schedule_name="drift-schedule",
    monitoring_type="DataQuality",  # or "ModelQuality", "ModelBias", "ModelExplainability"
    monitoring_schedule_config={
        "ScheduleConfig": {"ScheduleExpression": "cron(0 1 * * ? *)"},
        "MonitoringJobDefinition": {
            "MonitoringInputs": [{
                "EndpointInput": {
                    "EndpointName": "prod-endpoint",
                    "LocalPath": "/opt/ml/processing/input",
                    "S3InputMode": "File"
                }
            }],
            "MonitoringOutputs": {
                "S3Output": {
                    "S3Uri": "s3://monitoring-reports/",
                    "LocalPath": "/opt/ml/processing/output"
                }
            },
            "MonitoringResources": {"ClusterConfig": {"InstanceCount": 1, "InstanceType": "ml.m5.xlarge"}}
        }
    }
)
```

**Key `DataCaptureConfig` settings:**
| Parameter | Recommended Value | Rationale |
|---|---|---|
| `EnableCapture` | `True` | Required for all monitoring |
| `InitialSamplingPercentage` | 100 (start) → adjust down | Capture full sample initially for baseline |
| `CaptureOptions` | `Input` + `Output` for ModelQuality; `Input` only for DataQuality | Ground truth may not be in output |
| `CaptureContentTypeHeader` | `"application/json"` | Match content type of request |
| `DestinationS3Uri` | Dedicated bucket/prefix | Separation from model artifacts |

## Amazon CloudWatch Drift Monitoring

| CloudWatch Feature | Baseline Capability | Use Case |
|---|---|---|
| **Metric Math Alarms** | `ABS(METRICS()-early_baseline) > threshold` | Express drift as departure from launch value |
| **Anomaly Detection Bands** | Learns expected band from historical data (Algorithm: RCF) | Detect unusual p99 latency, error rate patterns |
| **Composite Alarms** | Combines multiple underlying CloudWatch alarms | Alert only when simultaneous drift on ≥2 metrics |
| **Logs Insights (ML prefix)** | Ad-hoc query of inference logs, prompt/response quality | Investigate drift events post-hoc |
| **Contribution Analysis** | Identifies which dimension (instance type, AZ) contributes to anomaly | Pinpoint infrastructure vs model drift |

> **Exam Gotcha:** CloudWatch Anomaly Detection only works well with **stable, periodic baseline data**. It is not a replacement for statistical drift detection on input features (use SageMaker DataQuality for that).

## GenAI Baseline & Drift Detection

| Component | Baseline Metric | Drift Detection Method |
|---|---|---|
| **Prompt/Response Length** | Token count percentile bands | Monitor if mean token count shifts per session |
| **Semantic Similarity of Outputs** | BERTScore/Cosine similarity against golden answer set | Segment drift if similarity distribution degrades |
| **RAG Retrieval Accuracy** | Context Precision, Context Recall per knowledge base | Split monitoring: (1) retrieval hit rate vs baseline KB; (2) generation faithfulness |
| **LLM-as-a-Judge Scores** | Reference distributions of LLM judge rating (1–5) | Track score histogram shift over batches |
| **Cost/Token Usage** | Baseline tokens per request | Alarms for abnormal prompt injection or verbose drift |
| **Safety/Bias Flags** | Base rate of guardrail interventions | Monitor intervention rate departure from baseline |

**Bedrock Evaluations (Console or API) Outputs:**
- `EvaluationModelConfig` — choose programmatic, judge model, or human-workteam
- **Programmatic metrics**: BLEU, ROUGE, BERTScore, METEOR, semantic similarity
- **Judge model metrics**: Accuracy, Helpfulness, Category-specific scoring (relevance, coherence)
- Results stored in S3; can compare multiple prompt/model variants in one job

## Drift Response Automation Patterns

| Pattern | Trigger | AWS Implementation |
|---|---|---|
| **Retraining on DQ violation** | PSI breach → Lambda → Step Functions | EventBridge rule on monitoring job completion |
| **A/B switch to challenger** | ModelQuality alert fires | SageMaker endpoint update traffic shift |
| **Auto-scaling by latency drift** | p99 deviation from operational baseline | Application Auto Scaling target tracking on SageMakerVariantInvocationsPerInstance |
| **Rollback when bias drift** | CDDPL threshold breach | Rollback endpoint to previous stable model version using Model Registry |
| **Human-in-the-loop review** | Unexplained drift requiring SME investigation | Amazon A2I review loop for sampled drifted predictions |

## Anti-Patterns & Distractor Traps

- **Relying solely on training time validation metrics as baseline** — unacceptable because data drift cannot be detected without production input distributions.
- **Setting drift thresholds too tight** → alarm fatigue; or too loose → missed degradation.
- **Capturing only input, not output, when ground truth joins are needed** — ModelQuality jobs require both prediction and ground truth (merged via `join_source: {"Input": ..., "Output": ...}`); DataQuality is input-only.
- **Overlooking periodic re-baselining** — after retraining or feature changes, baseline must be regenerated. Using stale `constraints.json` creates false positives.
- **Confusing A/B testing with shadow testing for baseline comparison** — A/B changes caller-facing responses; shadow tests log without altering responses, both useful but only shadow preserves caller experience.
- **Ignoring label drift** — model degradation not visible from input features alone; requires delayed ground truth labeling and scheduled `ModelQuality` jobs.

> **Exam Gotcha:** If a question says "callers must not be impacted" and includes "live traffic" as the evaluation source, choose **SageMaker Shadow Testing** or **Model Monitor**; if it requires "split live response" → that is A/B, reject it.
