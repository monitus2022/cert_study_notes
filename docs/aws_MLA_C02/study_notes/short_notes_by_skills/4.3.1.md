# Skill 4.3.1: Secure CI/CD Pipelines by Checking for Code and Image Vulnerabilities

## Task 4.3: Operating, Monitoring, and Securing ML and AI Solutions — Secure ML and AI workloads and model endpoints

| Dimension | Amazon CodeGuru Security | Amazon Inspector |
|---|---|---|
| **Primary target** | Application source code (custom logic in pipeline repos) | Built workload artifacts (EC2, ECR images, Lambda packages) |
| **What it finds** | Hardcoded credentials, injection flaws, insecure patterns, policy violations, secrets in code | CVEs in OS packages/app dependencies, unintended network exposure, package vulnerabilities in assembled images |
| **Pipeline stage** | Pre-build / commit phase (static analysis on source) | Post-build / artifact phase (image scan after assembly) |
| **Exam trigger terms** | "source code vulnerability," "hardcoded API key," "secret in repo," "static analysis" | "container image CVE," "vulnerable package," "base image scan," "ECR image scan" |
| **Output action** | Findings gate merge/build via CodePipeline manual approval or failure | Findings gate deployment via Inspector + EventBridge → build failure or alert |

---

## Complementary Controls in the Pipeline (Do Not Confuse)

- **CodeGuru Security** = source-level → **does NOT inspect compiled images or third-party package CVEs.**
- **Inspector** = artifact-level → **does NOT find secrets or logic flaws in application code.**
- **Both needed together** — a pipeline with only one has a diagnostic blind spot.
- **AWS Secrets Manager** = runtime secret retrieval/rotation → replaces hardcoded credentials found by CodeGuru, but is not a scanner.

> **Exam Gotcha:** A question about "vulnerable Python package in a built image" → **Amazon Inspector**, not CodeGuru. A question about "credentials committed to a Git repo" → **CodeGuru Security**, not Inspector.

---

## Pipeline Integration & Gating Patterns

- **CodePipeline / CodeBuild integration:** Findings from CodeGuru Security appear as test reports; configure **manual approval stage** or **fail build on high-severity findings** using EventBridge rules that react to Inspector/CodGuru events.
- **Amazon ECR Enhanced Scanning (Inspector):** Enable at registry level; scans on push — supports continuous monitoring (re-scans when new CVEs published).
- **Lambda vulnerability scanning:** Inspector scans Lambda functions and associated layers for package-level CVEs — no agent required.
- **EC2 scanning:** Inspector requires SSM Agent on instances for host-based assessments.

**Decision matrix: What to scan and when**

| Artifact/Stage | Scanner | Notes |
|---|---|---|
| Raw source code (Python, Java, etc.) pre-commit | CodeGuru Security | Flags secrets, insecure APIs, OWASP Top 10 patterns |
| Dockerfile / build scripts | CodeGuru Security / manual review | Misconfigured image build steps |
| Built container image in ECR | Inspector (ECR Enhanced) | CVE scan, base image risks |
| Deployed EC2 instance | Inspector | OS/package vulnerabilities + network exposure |
| Lambda function | Inspector | Package vulnerabilities in deployment package/layers |

## Security Configurations & IAM for Pipeline Scanning

- **CodeGuru Security role needs:** `codeguru-security:CreateScan`, `codeguru-security:GetFindings`, access to source repo (CodeCommit/GitHub token) via IAM role or Secrets Manager.
- **Inspector role needs:** `inspector2:Enable`, `inspector2:ListFindings`, and for ECR: `ecr:DescribeRepositories`, `ecr:DescribeImages`; for EC2: SSM permissions to collect inventory.
- **Encryption:** ECR repo encrypted with **KMS customer-managed key (CMK)** to meet compliance; Inspector findings stored encrypted in S3 if exported.
- **VPC endpoint for ECR/Inspector:** Use interface endpoints (`com.amazonaws.region.ecr.api`, `com.amazonaws.region.inspector2`) to keep scan traffic private and avoid internet egress from build environments.

> **Exam Gotcha:** Inspector requires ECR repositories to be in **same account** for continuous scan unless delegated admin is configured in AWS Organizations. Cross-account image scanning requires **ECR repository policy + Inspector delegated admin**.

---

## Anti-Patterns & Common Traps

- **Widening IAM permissions to silence scan errors** — Scanner failures are not IAM denials; read the error type before changing policy.
- **Running scans but not gating deployment** — Findings that don't stop a pipeline are "reports nobody reads." Exam expects **gating** language.
- **Using Inspector to find secrets** — Inspector does not detect credentials; that is CodeGuru Security's job.
- **Using CodeGuru to find CVEs** — CodeGuru is static source analysis, not a CVE database scanner.
- **Scanning only on push, never re-scanning** — Inspector continuous monitoring alerts on **newly published CVEs** against existing images; trigger re-deployment or quarantine on critical findings.

---

## Compliance & Audit Tie-Ins

- **AWS CloudTrail:** Logs API calls for scanning activities (`codeguru-security:CreateScan`, `inspector2:Enable`). Configure **data events** if tracking object-level access to ECR images.
- **AWS Config:** Tracks whether ECR Enhanced Scanning is enabled; whether Inspector is enabled across accounts — use managed rules like `ecr-repository-tag-immutable-enabled`, `inspector-ecr-scan-enabled`.
- **Amazon EventBridge:** Route CodeGuru/Inspector findings to SNS/Security Hub/automated remediation (e.g., quarantine image by changing ECR lifecycle policy).

> **Exam Gotcha:** "Audit needs to prove images were scanned before deployment" → combination of **CodePipeline stage transitions in CloudTrail + Inspector findings export to S3/CloudWatch Logs**. Neither service alone gives a complete audit trail.

## Pipeline Security Deep-Dive (Beyond Scanning)

| Control | Implementation |
|---|---|
| **Least privilege for pipeline roles** | Separate roles: `CodeBuildRole` (pull source, push image), `DeployRole` (SageMaker create endpoint), `ScanRole` (Inspector/CodeGuru). Never reuse human IAM user. |
| **Secrets in pipeline** | Use **Secrets Manager** for GitHub tokens, ECR credentials, model registry auth; never bake into buildspec.yaml or Dockerfile. |
| **Image provenance** | Enable **ECR tag immutability**, sign images with **AWS Signer** (for Lambda/SageMaker containers), block unsigned images in deployment policy. |
| **Supply chain protection** | Pin base image digests (`FROM public.ecr.aws/...@sha256:...`), maintain private ECR mirror of approved base images, scan dependencies before promotion. |
| **Model artifact pipeline** | Validate model artifacts from Model Registry; block unregistered external models — use IAM conditions on `sagemaker:ModelApprovalStatus`. |

## Rapid Decision: Finding Type → Service

| Finding described in question | Correct AWS service |
|---|---|
| Hardcoded AWS access key in Python file in repo | Amazon CodeGuru Security |
| SQL injection pattern in application code | Amazon CodeGuru Security |
| CVE-2024-XXXX in `numpy==1.24.0` inside Docker image | Amazon Inspector (ECR Enhanced) |
| Open SSH port on training EC2 instance | Amazon Inspector (Network Reachability) |
| Container running as root in image | Amazon Inspector (CIS benchmarks) or CodeGuru for Dockerfile misconfig |
| Prompts attempting jailbreak at inference time | Amazon Bedrock Guardrails (runtime control, not pipeline scan) |
| Model endpoint accessible from public internet | VPC/Security Group review; Inspector network exposure findings |

> **Exam Gotcha:** "Inference path reachable from internet" is a **security group / network configuration issue**, not solved by CodeGuru or Inspector. Inspector may *flag* network exposure on EC2, but the fix is SG/VPC configuration.

---

## Memorize — Hard Rules

- **CodeGuru Security is SAST** (static); **Inspector is DAST/packages** (dynamic/package-level).
- **Inspector + ECR Enhanced Scanning:** continuous, default enabled on push, re-scans within 24h of new CVE publication.
- **CodeGuru findings:** severity levels Critical/High/Medium/Low/Info; gate on **Critical + High** for production ML pipelines.
- **Neither service scans model weights or training data** for data poisoning — that requires separate validation (e.g., data quality checks, model evaluation in SageMaker Clarify).
- **Secrets Manager rotation** does not auto-update code that bakes secrets; it is for runtime retrieval.
