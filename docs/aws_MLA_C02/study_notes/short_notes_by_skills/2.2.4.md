# Skill 2.2.4: Implement Training Time Reduction Techniques (Early Stopping, Distributed Training)
## Task 2.2: ML Model and Foundation Model (FM) Development – Train, fine-tune, and customize models for ML and AI solutions

**Core objective:** Reduce wall-clock training time, cost, and resource waste without harming convergence or model quality. Two layers matter: **(1) shorten a single training run** (early stopping, distributed training, I/O, precision) and **(2) shorten hyperparameter search** (AMT early stopping, warm start, parallel trials).

| Technique | Best For | AWS Mechanism | Trade-off / Gotcha |
|---|---|---|---|
| **Early stopping** | Validation metric plateaus; prevent overfitting | Training script callback; AMT early stopping | Needs validation set; patience too small stops early; metric direction must match |
| **Data parallel** | Model fits on one device; dataset large | SageMaker Distributed Data Parallel (SMDDP) | Communication overhead; scale batch size & learning rate |
| **Model parallel** | Model too large for one device | SageMaker Distributed Model Parallel (SMP) | Pipeline bubbles; complexity; slower if comms dominate |
| **Sharded data parallel** | Very large model + large data | SMP sharded data parallel | Memory savings; more complex than data parallel |
| **Mixed precision** | GPU compute bound | Training Compiler; framework AMP | Numerical instability; not all ops supported |
| **Efficient I/O** | Data loading bottleneck | Pipe mode, FSx for Lustre, augmented manifest | Format constraints; setup overhead |
| **Managed spot training** | Cost reduction | SageMaker managed spot | Interruptions; requires checkpointing |
| **Warm start** | Similar tuning job already run | AMT warm start | May bias search if data/distribution changed |
| **AMT early stopping** | Many tuning jobs | AMT early stopping; Hyperband | Stops late bloomers; needs intermediate metric |
| **Parallel tuning jobs** | Time-sensitive HPO | AMT parallel jobs | Higher cost; less efficient search |

### Early Stopping
- **Training-level:** Monitor validation loss/accuracy; stop when no improvement for a patience window; restore best checkpoint. Saves compute and prevents overfitting.
- **AMT-level:** Stops underperforming tuning trials early using the objective metric and intermediate results. Types include Auto and Hyperband.
- **Gotcha:** AMT early stopping ≠ training-script early stopping. AMT stops tuning jobs; script-level stops epochs within one job.
- **Gotcha:** Objective metric direction: minimize MSE vs. maximize AUC. Wrong direction optimizes toward a worse model.
- **Gotcha:** Without a validation set, early stopping cannot work correctly.

### Distributed Training
- **Data parallel:** Replicate model on each device; split batch; all-reduce gradients. Use when model fits on one device. Scale batch size and learning rate proportionally.
- **Model parallel:** Partition model layers/tensors across devices. Use when model does not fit on one device. Pipeline parallelism reduces idle time.
- **Sharded data parallel:** Shard model parameters, gradients, and optimizer states across data-parallel ranks. Use for models too large for standard data parallel but not requiring full model parallel.
- **SageMaker libraries:** SMDDP for optimized data parallel; SMP for model and sharded data parallel. Use EFA-enabled instances for tight coupling.
- **Gotcha:** Distributed training only helps if compute bound. If I/O or CPU bound, fix data pipeline first.
- **Gotcha:** Model parallel can be slower than single device if the model actually fits due to communication overhead.

### Hyperparameter Tuning Time Reduction
- **Search strategies:** Bayesian (efficient, low-dimensional), Random (parallel, high-dimensional), Hyperband (early stopping, large search spaces).
- **Warm start:** Reuse previous tuning trials. Types: Identical data, Transfer learning. Reduces search time but may bias if data changed.
- **Parallel jobs:** More parallel trials reduce wall-clock time but increase cost and reduce search efficiency.
- **Early stopping:** Stop poor trials early. Requires objective metric emitted to CloudWatch.
- **Gotcha:** AMT needs a defined objective metric and correct direction. Max jobs and max runtime control budget.

### Infrastructure & I/O Acceleration
- **Pipe mode:** Stream data from S3 without full download. Good for large datasets.
- **FSx for Lustre:** High-performance file system for training workloads.
- **Augmented manifest:** Efficient label access for large datasets.
- **Training Compiler:** Optimizes computation graph for supported frameworks and GPU instances.
- **Checkpointing:** Save model state to S3; essential for managed spot and long-running jobs.
- **SageMaker Debugger:** Profile bottlenecks (CPU, GPU, I/O, network) to identify true training-time causes.

### FM Customization Time Reduction
- **Prompt engineering first:** No training; fastest path to improvement.
- **RAG optimization:** Fix retrieval (embedding model, chunking, ranking) before fine-tuning the generator.
- **PEFT/LoRA:** Train small adapter weights; faster and cheaper than full fine-tuning.
- **Distillation:** Train smaller student from larger teacher; reduces inference cost, but training time may be significant.
- **Bedrock:** Managed supervised fine-tuning, reinforcement fine-tuning, and distillation.
- **Gotcha:** Catastrophic forgetting when fine-tuning on narrow data; mix general data or use PEFT.
- **Gotcha:** If retrieved passages are wrong, fine-tuning the generator will not fix the answer.

### Anti-Patterns & Exam Traps
- **Adding epochs** to reduce training time.
- **Switching objective metric** to speed up training.
- **Reducing validation split** for speed (negligible; harms early stopping).
- **Using model parallel** when model fits on one device.
- **Ignoring communication overhead** in distributed training.
- **No checkpointing** with managed spot training.
- **Fine-tuning FM** when prompt engineering or RAG would suffice.

| Exam Trigger | Correct Answer |
|---|---|
| Model fits on one instance, dataset large, training too slow | **Data parallel** |
| Model too large for one GPU | **Model parallel** |
| Huge model + large data | **Sharded data parallel** |
| Stop training when validation metric plateaus | **Early stopping** |
| Reduce HPO time | **AMT early stopping, warm start, parallel jobs, Hyperband** |
| Cost reduction for training | **Managed spot + checkpointing** |
| I/O bottleneck | **Pipe mode, FSx for Lustre** |
| FM fine-tuning faster | **PEFT/LoRA, distillation, prompt engineering** |
| Catastrophic forgetting | **Mix general data, PEFT, regularization** |
