# Skill 4.2.5: Optimize costs and set cost quotas by using appropriate cost management tools.

## Task 4.2: Optimize and manage ML and AI infrastructure costs and performance.

---

## Cost Management Tools: Decision Matrix

| Tool | Primary Function | Alerting | Use Case |
|---|---|---|---|
| **AWS Budgets** | Track spend/usage vs. threshold | ✅ Yes (forecast + actual) | **Set cost quotas**; alert before overrun |
| **AWS Cost Explorer** | Analyze & visualize historical/forecast spend | ❌ No | **Identify cost drivers** via tags/services |
| **AWS Trusted Advisor** | Best-practice checks (idle/underused resources) | ❌ No (report only) | **Find waste**: idle endpoints, underutilized instances |
| **AWS Compute Optimizer** | Recommend right-sized compute configs | ❌ No | **Instance family/type recommendations** from utilization |
| **AWS Cost Allocation Tags** | Attribute spend to teams/models/envs | ❌ No (enabler) | **Attribution**: prerequisite for all cost reporting |
| **AWS Cost Anomaly Detection** | Detect unusual spend patterns | ✅ Yes | **Automated anomaly alerts** for cost spikes |

## AWS Budgets: Critical Configuration Details

- **Budget types**: Cost, Usage (e.g., token count, instance-hours), Savings Plans utilization/coverage, Reservation utilization/coverage.
- **Alert triggers**: Actual spend exceeding threshold **or** forecasted spend *on track* to exceed threshold (sent during current period).
- **Delivery channels**: Email recipients (max 10), SNS topic, Slack/Chime via AWS Chatbot.
- **Scope**: Per-account, per-linked-account, per-tag, per-service, per-AZ, per-Region.
- **Notification latency**: Typically within ~15 min for actual; forecasted alerts can take 1–24 h.

> **Exam Gotcha**: AWS Budgets is the **only** tool that provides proactive, threshold-driven alerts. Cost Explorer has no alerting mechanism. Do not confuse "reporting" (Cost Explorer) with "quota enforcement / alerting" (Budgets).

## Cost Allocation Tags: Prerequisite for Attribution

- **User-defined tags** (e.g., `Team`, `ModelID`, `Environment`) must be activated in **AWS Billing Console → Cost Allocation Tags** before they appear in Cost Explorer or Budgets.
- **AWS-generated tags** (`createdBy`, `aws:cloudformation:stack-name`) are applied automatically, require activation.
- Tags propagate to SageMaker endpoints, Bedrock invocations, and vector databases. Without tags, cost reports show only service-level totals.

> **Exam Gotcha**: A budget scoped by tag **cannot** be created until the tag is activated in Billing Console. Tag activation has a ~24–48 h propagation delay.

## Purchasing Options vs. Budgets: Non-Overlapping Concepts

| Mechanism | Purpose | Discount Rate (Approx.) |
|---|---|---|
| **SageMaker AI Savings Plans** | Lower hourly rate on SageMaker instances | Up to 64% |
| **Compute Savings Plans** | Lower rate on EC2, Fargate, Lambda | Up to 66% |
| **EC2 Instance Savings Plans** | Lower rate on EC2 (locked to family + Region) | Up to 72% |
| **Provisioned Throughput (Bedrock)** | Reserve FM capacity at fixed hourly rate | Model-dependent |
| **AWS Budgets** | Alert when spend threshold approaching | **No discount — monitoring only** |

> **Exam Gotcha**: AWS Budgets **does not reduce rates**. A budget with alert ≠ a savings plan. SageMaker Savings Plans cover **only** SageMaker usage (training, endpoints, batch, notebooks). Compute/EC2 Savings Plans **do not** cover SageMaker.

## Quotas & Service Quotas

- **Service Quotas dashboard** (AWS Management Console) or `get_service_quota` API sets hard ceilings on resource counts (e.g., number of SageMaker endpoints per account, Bedrock invocations per minute).
- **SageMaker endpoint quotas**: Default 20 endpoints/account, 100 instances/account — raise via support ticket/Service Quotas.
- **Bedrock quotas**: Token-per-minute (TPM), requests-per-minute (RPM) per model; default often low (e.g., 60 RPM). Raise proactively for production.
- Use **AWS Budgets** for soft financial ceilings; use **Service Quotas** for hard resource ceilings — they serve different purposes.

> **Exam Gotcha**: "Set cost quotas" in the exam context refers to **AWS Budgets** (financial alerts), not Service Quotas (resource limits). However, Service Quotas prevents cost escalation by limiting resource creation.

## Token-Based Cost Monitoring: Bedrock Metrics

| CloudWatch Metric | What It Measures | Optimization Signal |
|---|---|---|
| `InvocationModelInvocations` | # of FM calls | Increased traffic |
| `InputTokenCount` | Input tokens per invocation | Prompt length growing |
| `OutputTokenCount` | Output tokens per invocation | Response verbosity |
| `InvocationClientErrors` | Client-side errors (throttles) | Quota exhaustion |
| `ModelLatency` | End-to-end latency | Performance degradation |

- Track **embedding computation costs**: `InputTokenCount` for embedding model invocations.
- Track **vector DB storage**: custom metric (e.g., `IndexStorageBytes`) via CloudWatch custom metric.

## Anti-Patterns & Traps

- **Anti-Pattern**: Applying endpoint-level cost levers (right-sizing, autoscaling) to Bedrock token-based workloads. No effect.
- **Anti-Pattern**: Setting a budget after spend has already breached. Budgets are for **proactive** awareness; use Cost Explorer for retrospective analysis.
- **Anti-Pattern**: Enabling prompt caching with dynamic prefix. Cache invalidates on every request; no savings realized. Static prefix must come first, dynamic content last.
- **Anti-Pattern**: Creating a budget scoped by a tag before activating the tag. No data populated.
- **Anti-Pattern**: Confusing "alerts" with "enforcement" — Budgets send alerts but do **not** stop resource creation or block API calls.

## High-Yield Exam Facts

- **AWS Budgets** supports up to **200 budgets per account**, each with up to **5 alert thresholds**.
- **Forecasted budget alerts** use statistical projections (typically 80% prediction interval).
- **Cost Explorer** shows up to **14 months** of historical data; forecast up to 12 months ahead.
- **Trusted Advisor** checks: Idle SageMaker notebook instances, underutilized EBS volumes, unassociated Elastic IPs.
- **Cost Anomaly Detection** uses ML to detect spend anomalies; useful for catching runaway Bedrock token bills or autoscaling loops.
