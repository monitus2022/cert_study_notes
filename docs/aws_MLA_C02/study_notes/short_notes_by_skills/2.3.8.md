# Skill 2.3.8: Apply NLP Evaluation Metrics (BLEU, ROUGE, BERTScore, Semantic Similarity)

## Task 2.3: Analyze and evaluate the performance of ML and AI systems

---

## Metric Selection Decision Matrix

| Metric | Type | Best Use Case | Key Limitation | Compute Cost |
|--------|------|---------------|----------------|--------------|
| **BLEU** | N-gram overlap (precision-focused) | Machine translation quality | Penalizes valid paraphrases; ignores recall; poor for short text | Low |
| **ROUGE-N** | N-gram overlap (recall-focused) | Summarization completeness | Misses semantic equivalence; inflated by length | Low |
| **ROUGE-L** | Longest common subsequence | Summarization fluency + structure | Still lexical; ignores synonyms | Low |
| **BERTScore** | Contextual embedding similarity | Semantic equivalence across wordings | Requires transformer model; higher latency | Medium-High |
| **Semantic Similarity** | Embedding cosine similarity | Paraphrase detection, answer relevance | Sensitive to embedding model choice; no factual grounding | Medium |

---

## Core Concepts & Definitions

- **BLEU (Bilingual Evaluation Understudy):** Measures n-gram *precision* with brevity penalty. Scores range 0–1 (or 0–100 scaled). Intended for machine translation where concise outputs are preferred.
- **ROUGE (Recall-Oriented Understudy for Gisting Evaluation):** Measures n-gram *recall* against reference summaries. ROUGE-N (n-gram overlap), ROUGE-L (longest common subsequence), ROUGE-S (skip-bigram).
- **BERTScore:** Uses contextual embeddings (BERT, RoBERTa) to compute token-level cosine similarity between candidate and reference. Produces Precision (P), Recall (R), and F1. Aligns tokens via greedy matching.
- **Semantic Similarity:** Compares sentence/paragraph embeddings (e.g., sentence-transformers, Amazon Titan Embeddings). Measured as cosine similarity; threshold-based decisions (e.g., > 0.8 = "similar").

---

## BLEU Deep Dive

- **Formula:** `BLEU = BP × exp(Σ wₙ log pₙ)` where `pₙ` = modified n-gram precision (clipped), `BP` = brevity penalty.
- **Brevity penalty applies when candidate length < reference length.** Long outputs are not penalized beyond the precision clipping.
- **Default weighting:** Uniform across n-grams (typically up to 4-gram).
- **Smoothing required** when no n-gram matches (avoid `log(0)`), especially for short candidates.

> **Exam Gotcha:** BLEU is *precision-oriented*. A short, safe answer can score high BLEU even if it omits critical content. BLEU alone cannot detect omissions, hallucinations, or factual errors.

---

## ROUGE Deep Dive

| Variant | Measures | Formula Intuition |
|---------|----------|-------------------|
| **ROUGE-N** | N-gram recall | `matched n-grams / total reference n-grams` |
| **ROUGE-L** | Longest common subsequence | Captures sentence-level structure; F-measure used |
| **ROUGE-S** | Skip-bigram (any pair of words in order) | More flexible than contiguous n-grams |

- **ROUGE is recall-oriented:** Favors thorough coverage of reference content.
- **Common pitfall:** A generated summary that repeats all reference content plus irrelevant text scores high ROUGE but low precision.

> **Exam Gotcha:** A system can game ROUGE by producing overly long outputs. Always report ROUGE alongside a precision metric or a length penalty.

---

## BERTScore Deep Dive

- **Requires a pre-trained transformer** (e.g., `bert-base-uncased`, `roberta-large`).
- **Algorithm:** Tokenize both candidate and reference → compute contextual embeddings → greedy alignment (each candidate token matched to most similar reference token) → compute P, R, F1 with optional importance weighting (IDF).
- **Rescaled to 0–1** for interpretability (baseline-rescaled BERTScore).
- **Advantage over BLEU/ROUGE:** Captures semantic similarity across different wordings (e.g., "quick brown fox" vs "fast auburn fox" still scores moderately high).

> **Exam Gotcha:** BERTScore requires downloading model weights. For offline evaluation or when compute is constrained, prefer BLEU/ROUGE. For semantic nuance, BERTScore outperforms lexical metrics.

---

## Semantic Similarity in Practice

- **Embedding models:** `sentence-transformers/all-MiniLM-L6-v2` (lightweight), Amazon Titan Embeddings (Bedrock), Cohere Embed v3.
- **Cosine similarity range:** -1 to 1; for text, typically 0 to 1.
- **Threshold selection is task-dependent:**
  - Answer relevance: > 0.7
  - Paraphrase detection: > 0.8
  - Near-duplicate detection: > 0.9

- **Use cases in exam scenarios:**
  - **RAG answer relevance:** Compare generated answer embedding vs. question embedding.
  - **Grounding/faithfulness:** Compare generated answer vs. retrieved context (semantic similarity can detect fabricated content when similarity is low).
  - **Duplicate question detection** in support systems.

## Trade-offs & Anti-Patterns

| Anti-Pattern | Why It Fails | Correct Alternative |
|--------------|--------------|---------------------|
| Using BLEU for summarization | Ignores recall; summaries need completeness | ROUGE or BERTScore |
| Using ROUGE for translation | Ignores precision; translations need conciseness | BLEU or BERTScore |
| Reporting a single metric to prove quality | No metric captures factuality, coherence, fluency | Combine overlap + embedding + LLM-as-judge |
| Relying on BLEU/ROUGE for creative writing | Lexical matching fails on paraphrases | BERTScore or semantic similarity |
| Using semantic similarity for factual grounding | Embedding similarity ≠ factual verification | RAG triad: context relevance + faithfulness + answer relevance |
| Assuming higher ROUGE = better model always | Overly long outputs inflate recall | Report ROUGE-L F1 with length statistics |

## AWS Service Integration

| AWS Service | NLP Metric Capability |
|-------------|----------------------|
| **Amazon Bedrock Evaluations (programmatic)** | Native support for BLEU, ROUGE, BERTScore for model output assessment |
| **Amazon Bedrock Evaluations (LLM-as-judge)** | Semantic similarity scoring via judge model + explanation |
| **SageMaker AI with MLflow** | Log custom NLP metrics (e.g., `mlflow.log_metric("bleu", 0.42)`) per run |
| **Amazon Bedrock Prompt Management** | Compare prompt variants using automated metrics + human review |

- **Bedrock programmatic evaluation** supports custom metrics via AWS Lambda when built-in metrics insufficient.
- **Custom metric implementation:** Use `nltk.translate.bleu_score.corpus_bleu`, `rouge_score.rouge_scorer.RougeScorer`, or `bert_score.score` in SageMaker processing jobs.

## Key Configuration Parameters

- **BLEU:** `max_n` (default 4), `smoothing_method` (e.g., `method1`, `add-k`).
- **ROUGE:** `rouge_types=['rouge1','rouge2','rougeL']`, `use_stemmer=True` (normalizes morphology).
- **BERTScore:** `model_type='roberta-large'`, `idf=True` (weight rare words), `rescale_with_baseline=True`.
- **Semantic similarity:** `embedding_model`, `threshold`, `pooling` (mean vs CLS token).

---

## Security & Compliance Notes

- **Embedding / evaluation data may contain PII.** Use KMS-encrypted S3 buckets for reference datasets and candidate outputs.
- **Bedrock evaluations** support VPC endpoints (Interface endpoint `bedrock`). Ensure IAM roles have `bedrock:CreateEvaluationJob`, `bedrock:GetEvaluationJob`, and S3 read/write permissions.
- **Logging NLP metric outputs** to CloudWatch: Use structured JSON logs; enable log group encryption with KMS.

> **Exam Gotcha:** Human-based Amazon Bedrock evaluation jobs created in the console require a browser-facing UI for raters. Programmatic evaluation jobs do not.

---

## Exam Quick Reference

- **BLEU** → precision, translation, brevity penalty.
- **ROUGE** → recall, summarization, vulnerable to verbose outputs.
- **BERTScore** → semantic robustness, higher cost, contextual embeddings.
- **Semantic similarity** → paraphrase/answer relevance, embedding model dependent, threshold tuning required.
- **Never trust a single NLP metric.** Production-grade evaluation combines overlap + embedding + judge/human review.
