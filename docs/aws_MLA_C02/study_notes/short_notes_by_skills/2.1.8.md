# Skill 2.1.8: Apply AWS AI Services to Solve Specific Business Problems
## Task 2.1: ML Model and Foundation Model (FM) Development - Choose Appropriate Modeling Approaches

## Service Decision Matrix

| Business Problem | AWS Service | Core Capability | Input | Output |
|---|---|---|---|---|
| **Document text/structure extraction** | Amazon Textract | OCR + Forms + Tables + Queries | Scanned docs, PDFs, images | Text, key-value pairs, table cells, relationships |
| **Image/Video analysis** | Amazon Rekognition | Objects, faces, PPE, text, moderation, celebrities | Images, video streams/files | Labels, confidence scores, bounding boxes, facial metadata |
| **Text NLP structure** | Amazon Comprehend | Entities, key phrases, sentiment, PII, topics, syntax | UTF-8 text documents | Entity types, sentiment scores, topic labels, PII detection flags |
| **Speech-to-text** | Amazon Transcribe | Audio transcription, speaker diarization, custom vocab | Audio files (S3), streaming audio | Transcript JSON, timestamps, speaker labels, confidence |

## Feature-Specific API Deep Cuts

### Amazon Textract – Critical Distinctions

| API | Use Case | Key Parameters |
|---|---|---|
| `DetectDocumentText` | Simple OCR only, plain text/page blobs | DocumentLocation, FeatureTypes |
| `AnalyzeDocument` | Forms + Tables extraction | FeatureTypes: `FORMS`, `TABLES`, `QUERIES` |
| `AnalyzeExpense` | Invoices/receipts only (Vendor, Tax, Line Items) | Document (single invoice png/jpg/pdf) |
| `AnalyzeID` | Identity doc (license, passport) | DocumentPages → FieldSummary |
| **Async APIs** (`StartDocumentAnalysis`) | Multi-page docs >1 page PDF, or all S3-batch | JobId polling / SNS notification |
| **Sync APIs** (direct) | Single-page, small files, byte arrays | Response inline |

> **Exam Gotcha:** Sync APIs accept image bytes directly and handle <20MB on S3 or local buffer. Async is REQUIRED for multi-page processing (>1 page PDFs) and larger jobs—choosing sync for large payloads or vice versa is a classic distractor.

> **Exam Rule:** `AnalyzeExpense` is optimized for invoices and returns `LINE_ITEM_GROUPS`, `EXPENSE_DOCUMENTS`, `SUMMARY_FIELDS`. It includes **invoice-specific tax and total extraction** that `AnalyzeDocument` does not. 

### Amazon Rekognition – Model Scoping

| Operation | Specific Use | Note |
|---|---|---|
| `DetectLabels` | Generic objects, scenes, brands | Returns parent + child label hierarchy with confidence |
| `DetectFaces` | Facial attributes + landmarks | Does NOT do facial recognition/matching |
| `IndexFaces` + `SearchFacesByImage` | Face matching (requires collection) | Service-side biometric identity storage—requires careful IAM + consent governance |
| `DetectModerationLabels` | Content moderation (explicit/nudity/violence) | Specialized model, top-level + parent categories |
| `DetectText` | Detect text in images/video | Similar to Textract but for **scene text**, not documents |
| `StartContentModeration` / `StartLabelDetection` | Async media (video; S3) | JobId + SNS completion |

> **Exam Gotcha:** `DetectText` (Rekognition) extracts text from arbitrary image/video scenes (signs, billboards) but NOT structured tables/key-value forms. For documents with fields, **Textract is the correct service**. Rekognition `DetectText` ≠ Textract OCR.

> **Exam Rule:** Rekognition Face Matching requires TWO separate steps: (1) `IndexFaces` to create/append to a `CollectionId` vector store of face embeddings; (2) `SearchFacesByImage` to match. "Collected faces" are stored and searchable as `FaceRecords`.

### Amazon Comprehend – Choosing the Right Analysis Type

| API | What It Detects | Representative Use | Output Details |
|---|---|---|---|
| `DetectSentiment` | Sentiment (POSITIVE/NEGATIVE/NEUTRAL/MIXED) | Reviews, feedback | Per-document score, not per-entity |
| `DetectEntities` | Entities (PERSON, ORG, DATE, QUANTITY, etc.) | Knowledge extraction, search | Mentions with offsets, confidence, types |
| `DetectKeyPhrases` | Key noun phrases | Search connectors, topics | Comma-separated phrases w/ Score |
| `DetectPiiEntities` | PII by box (not NER) | Compliance scanning | Type (SSN, EMAIL, ADDRESS, DRIVER_ID), Score, Begin/EndOffsets |
| `DetectTargetedSentiment` | Sentiment toward a SPECIFIC entity | Brand/product feature analysis | Entity → Sentiment mapping |
| `DetectSyntax` (Full text) | Token + part-of-speech (NNP, VBZ) | Text normalization | Tokenization + POS tags |
| `DetectDominantLanguage` | Language ID (100+ langs) | Multi-lingual routing | ISO-639-1 code + Score |

> **Exam Gotcha:** `DetectSentiment` returns a document-level sentiment only. Use **`DetectTargetedSentiment`** when you need per-entity (brand/actor-specific) sentiment. 

> **Exam Gotcha:** `DetectPiiEntities` covers a finite built-in list (e.g., SSN, credit card, driver's license, SSN, name, phone). For enterprise-compliance requiring **custom PII types**, use Comprehend **custom entity recognition** (train a custom classifier/entity recognizer). 

### Amazon Transcribe – Key Features & Limits

| Function | How to Access | When |
|---|---|---|
| **Standard Batch** | `StartTranscriptionJob` | Pre-recorded audio on S3 (MP3, WAV, FLAC, etc.) |
| **Streaming** | `StartStreamTranscription` WebSocket/HTTP2 | Real-time call centers, voice input |
| **Custom Vocabulary** | `VocabularyFileUri` or `VocabularyName` | Domain terms (product names, acronyms) – 4 variants |
| **Custom Language Model** | `ModelName` trained w/ Comprehend-style data | Ongoing regional dialect or noisy audio |
| **Speaker Diarization** | `ShowSpeakerLabels=True` | Multi-speaker audio; `MaxSpeakerLabels` (1-10) |
| **Channel Identification** | `ChannelIdentification=True` | Stereo audio where speaker left/right channels differ |
| **Subtitling** | `Subtitles` → Formats: `srt`, `vtt` | Video caption workflows |
| **Content Filtering** | `VocabularyFilterMethod` = `mask`, `remove`, `tag` | Profanity masking |

> **Exam Gotcha:** Transcribe supports **custom vocabularies** (lists of 1–10k weighted terms) with `Phrases`, `SoundsLike`, `IPA`, or `DisplayAs` columns. For higher accuracy on domain-specific audio, a **custom language model** (requires 1–100k training transcripts) is the stronger signal—but takes more data.

## Security & Compliance Across AI Services

### Shared Model

| Dimension | Requirement | Notes |
|---|---|---|
| **IAM Authentication** | SigV4 via service-specific actions | E.g., `textract:AnalyzeDocument`, `rekognition:DetectFaces`, `comprehend:DetectSentiment`, `transcribe:StartTranscriptionJob` |
| **KMS Encryption at Rest** | `Request` param `KmsKeyId` or auto-SSE-S3 for jobs | MANY async Jobs (Textract async, Transcribe batch) write **output to S3**; those S3 outputs can be SSE-KMS |
| **VPC Endpoints** | Interface VPC endpoints available for ALL 4 services | PrivateLink (`com.amazonaws.<region>.textract`, `.rekognition`, `.comprehend`, `.transcribe`) |
| **Audit/Compliance** | CloudTrail logs all API calls | Use for compliance review and detection |

> **Exam Gotcha:** Textract async, Transcribe, and Rekognition video operations return JobIds and require polling (`Get*` APIs) or SNS notifications (`NotificationChannel`). The async operation writes results directly to **S3**, not into the response body. You must grant service-side write permission to S3 (either using a service role or specifying destination S3 URI policy).

## AWS AI Service: When vs. Custom Build

| Trigger for AWS AI Service | Trigger for Custom Model / Bedrock |
|---|---|
| Task is already solved (document extraction, transcription, object detection) | Requires proprietary domain knowledge (e.g., forecasting sales) |
| No in-house labeled data exists | Plenty of labeled training data available |
| You need output quickly, low maintenance | You need full control over model performance / edge deployment |
| Accuracy of pre-trained service is adequate | Pre-trained service misses niche/domain-specific categories |
| Cost per API call acceptable at scale | High call volume demands optimized per-unit inference (SageMaker endpoint) |

## Distractor/Exam Traps

| Scenario | WRONG (Frequent Distractor) | RIGHT |
|---|---|---|
| Extract total, vendor, line items from invoice PDF | `AnalyzeDocument` (Textract) | `AnalyzeExpense` |
| Face similarity check | `DetectFaces` | `IndexFaces` + `SearchFacesByImage` |
| Sentiment about one brand in a review | `DetectSentiment` | `DetectTargetedSentiment` |
| Multi-page PDF processing | Sync `DetectDocumentText` | Async `StartDocumentAnalysis` |
| Transcribe speaker labels | Add custom vocabulary | `ShowSpeakerLabels=True` |
| Detect inappropriate image | Rekognition `DetectLabels` | `DetectModerationLabels` |
| General OCR for document on S3 | Rekognition `DetectText` | Textract `DetectDocumentText` |

## Rapidity of Decision: Managed vs. Custom vs. Foundation Model

| Requirement | Constraint | Decision |
|---|---|---|
| Extract key-value pairs from scanned tax forms | Task-specific, pre-trained is good enough | Amazon Textract `AnalyzeDocument` (FORMS) |
| Classify sentiment of customer feedback for call center | General NLP, common sentiment categories | Amazon Comprehend `DetectSentiment` or `DetectTargetedSentiment` |
| Detect if factory workers are wearing helmets in CCTV feed | Real-time video, custom domain | Custom model via SageMaker AI; or Rekognition `DetectLabels` if helmets are included as a label category |
| Transcribe audio meetings with speaker separation | Audio standard, speaker labels needed | Amazon Transcribe + `ShowSpeakerLabels=True` |
| Answer questions from internal employee manual | Fast update, cite sources | Amazon Bedrock + Knowledge Bases (RAG) |
| Forecast next quarter store demand | Proprietary historical data, interpretability | SageMaker AI regression on company data (e.g., XGBoost) |
| Summarize long support tickets | General language ability, no training data | Amazon Bedrock foundation model + prompt engineering |

## Core Retention Summary

**The "Rule of Thumb" by problem class:**

- **Structured docs → Textract (Optimized per-doc type: AnalyzExpense, AnalyzeID)**
- **Computer vision (images/video) → Rekognition (Moderation, Labels, Faces)**
- **NLP tasks → Comprehend (Sentiment, Entities, PII)**
- **Voice/Audio → Transcribe (Diarization, Custom vocab)**
- **General model capability → Bedrock (prompt first)**
- **Own historical data → SageMaker AI (train supervised)**

> **Hard rule:** For every AWS AI service scenario, ask: (1) Is the task already pre-solved? (2) Does the service's built-in label/response schema match the business need exactly? (3) Are we processing the input in a supported format and calling the correct API (sync/async)? If yes—use the service. If the task needs in-domain accuracy not covered by the service—go custom or fine-tune.

## When NOT to use AWS AI Services

- **Latency-critical, high-QPS endpoints** → Custom `SageMaker Endpoint` with low-latency model (e.g., DistilBERT) is more cost-effective than per-API charges.
- **Few-shot custom object detection on edge devices** → AWS Panorama or custom SageMaker model (Rekognition cloud does not run offline on edge).
- **Highly specialized NLP domain models (legal, medical)** → Amazon Comprehend Medical handles clinical entities. For legal contracts beyond Comprehend's generic entity list, fine-tuning Bedrock or training custom detection may be required.
- **Multilingual tasks beyond Comprehend's built-in language coverage** → Custom model or Amazon Translate+Bert based approach.
- **Streaming video analysis at camera-edge for privacy-sensitive workloads** → AWS IoT Greengrass + custom inference; avoid sending all video to Rekognition when local processing is required.
