# Skill 4.2.4: Optimize capacity for cost, performance, and reliability.

## Task 4.2: Operating, Monitoring, and Securing ML and AI Solutions - Optimize and manage ML and AI infrastructure costs and performance.

---

## Core Principle: "What Are You Actually Paying For?"

| Workload Type | Billing Unit | Optimization Levers |
|---|---|---|
| **Hosted Inference (SageMaker AI)** | Compute hours / instance capacity | Right-sizing, Auto Scaling, MMEs, Savings Plans |
| **FM Inference (Amazon Bedrock)** | Input/Output tokens | Model selection, Prompt discipline, Caching, Provisioned Throughput |
| **Batch/Async Jobs** | Job duration × instance type | Spot instances, smaller instances, checkpointing |
| **Vector Databases/Embeddings** | Storage GB + compute | Dimension reduction, index compression, storage tiering |
| **Agents** | Multiplied tokens (plan + tools + synthesize) | Per-invocation tracing, tool call minimization |

> **EXAM GOTCHA:** Applying endpoint-level levers (instance sizing, auto scaling) to a token-based Bedrock bill optimizes **nothing**. Always identify the billing unit first.

## Traditional ML: Inference Capacity Optimization (SageMaker AI)

### Instance Family Selection Matrix

| Workload Pattern | Instance Family | Rationale |
|---|---|---|
| **CPU-bound inference** (tabular, XGBoost, small models) | General purpose (ml.m5, ml.c5) | Cost-effective; no GPU needed |
| **GPU-dependent** (LLMs, vision, large transformers) | Accelerated (ml.g5, ml.p4/p5) | Required for low-latency inference |
| **Memory-heavy models** (>10GB) | Memory-optimized (ml.r6) or multi-GPU | Prevent OOM; enable batch sizing |
| **Intermittent sporadic traffic** | Serverless inference | Pay per invocation; no idle cost |
| **Large payloads (>1GB) or 15min+ processing** | Asynchronous inference | Queued; auto-scales to zero |
| **Many small models sharing framework** | Multi-Model Endpoint (MME) | Shared compute; load-on-demand |

### Capacity Optimization Decision Path

1. **Measure first:** CloudWatch `InvocationsPerInstance`, `CPUUtilization`, `GPUUtilization`, `ModelLatency`, `OverheadLatency`
2. **Busy all day = sizing problem** → Right-size instance family
3. **Busy peak, idle overnight = scaling problem** → Configure Application Auto Scaling
4. **Intermittent usage = over-provisioned** → Serverless or MME
5. **Steady year-round = predictable spend** → SageMaker AI Savings Plans

> **EXAM GOTCHA:** Busy one hour, idle 23 = **scaling problem** (fix with auto scaling), NOT sizing problem (do not downsize instance).

### Auto Scaling Configuration

| Parameter | Recommendation |
|---|---|
| **Target metric** | `InvocationsPerInstance` (preferred over CPU for inference) |
| **Target value** | Set from measured peak; avoid >70% utilization |
| **Scale-out cooldown** | 60–180 seconds (rapid response) |
| **Scale-in cooldown** | 300+ seconds (prevent flapping) |
| **Min instances** | 0 for async; ≥1 for real-time (zero-capacity not supported on real-time) |

## Generative AI: Token Cost Optimization (Amazon Bedrock)

### Cost Levers Ranked by Impact

| Lever | Mechanism | Typical Savings |
|---|---|---|
| **Model downgrade** | Smaller FM meets quality bar | 50–90% per request |
| **Prompt caching** | Reuse KV cache for stable prefix | Up to 90% on cached tokens |
| **Input truncation** | Reduce context window / trim instructions | Proportional to token reduction |
| **Output cap** | Limit `max_tokens` | Limits worst-case cost |
| **Batch inference** | 50% discount for tolerant workloads | 50% vs on-demand |
| **Provisioned Throughput** | Commit to model units | Up to 50% vs on-demand |

> **EXAM GOTCHA:** Prompt caching is **not free**. Cached tokens are billed at reduced rate, cache writes can cost MORE than uncached input, minimum prefix length applies, and **any dynamic content in prefix invalidates the cache entirely**.

### Provisioned Throughput vs On-Demand

| Factor | On-Demand | Provisioned Throughput |
|---|---|---|
| **Billing** | Per token (input/output) | Fixed hourly per Model Unit |
| **Commitment** | None | 1-month or 6-month term |
| **Latency** | Variable | Predictable, lower |
| **Traffic pattern** | Variable, experimental | Steady, high-volume, predictable |
| **Scaling** | Automatic | Manual (purchase additional MUs) |

### Bedrock Billing Rules

- **Input tokens:** Priced per 1K tokens; includes system prompt, context, user message
- **Output tokens:** Priced per 1K tokens; generated response only
- **Batch inference:** ~50% discount on both input/output; asynchronous
- **Cache writes:** May be 25–100% premium over normal input tokens
- **Cache reads:** Up to 90% discount on cached input tokens

## Agent Cost Amplification

### Cost Anatomy of a Single Agent Invocation

**1 user request → 1 planning call + N tool calls + 1 synthesis call = (N+2) × token cost**

| Component | Cost Driver |
|---|---|
| **Planning** | System prompt + tool schemas + user message |
| **Tool invocation** | Tool name + arguments + tool result (can be large) |
| **Synthesis** | Full conversation history + tool outputs + final response |

> **EXAM GOTCHA:** A retry loop that a human never notices (e.g., agent retries a failed tool call 5 times) **multiplies cost without any change in traffic**. Track cost per invocation, not per conversation.

### Agent Observability for Cost

| Tool | Purpose |
|---|---|
| **Bedrock AgentCore Observability** | Per-invocation trace: model calls, tool calls, memory ops |
| **CloudWatch metrics** | Token usage per agent, invocations, tool call counts |
| **X-Ray traces** | Latency attribution: model vs tool vs retrieval vs orchestration |

## Purchasing Options Coverage Matrix

| Commitment Type | Covers | Does NOT Cover |
|---|---|---|
| **SageMaker AI Savings Plans** | SageMaker: training, inference, batch, notebooks | EC2, Lambda, Fargate, Bedrock |
| **Compute Savings Plans** | EC2, Lambda, Fargate (any region/family) | SageMaker AI instances |
| **EC2 Instance Savings Plans** | EC2 only (specific family/region) | SageMaker, Lambda, Fargate |
| **Bedrock Provisioned Throughput** | Specific FM capacity | Does not extend to other models |
| **Spot Instances** | Interruptible training jobs | Serving endpoints (no reliability) |
| **Reserved Instances** | EC2 instances (1-3 year) | SageMaker instances |

> **CRITICAL RULE:** **SageMaker AI Savings Plans** are the ONLY commitment that covers SageMaker ML instances. **Compute Savings Plans** do NOT apply to SageMaker. This is a frequent exam trap.

### Spot Usage Decision

| Workload | Spot Appropriate? |
|---|---|
| Training with checkpointing | **YES** — restart from checkpoint |
| Batch transform (flexible timing) | **YES** — retry with spot reclamation |
| Real-time inference endpoint | **NO** — capacity can be reclaimed; not a guarantee |
| Agent with mission-critical calls | **NO** — interruption breaks orchestration |

## Cost Monitoring & Alerting

### Service Selection Decision

| Requirement | Service |
|---|---|
| Historical + forecast spend analysis by tag/service | **AWS Cost Explorer** |
| Alert when projected spend crosses threshold | **AWS Budgets** (forecast-based alerts) |
| Alert when actual spend crosses threshold | **AWS Budgets** (actual-based alerts) |
| Idle/underutilized resource detection | **AWS Trusted Advisor** |
| Right-sizing recommendations | **AWS Compute Optimizer** |
| Per-service anomaly detection in spend | **Cost Anomaly Detection** |
| Tag enforcement | **AWS Organizations SCPs + Tag Policies** |

> **EXAM GOTCHA:** AWS Cost Explorer **visualizes** spend; AWS Budgets **alerts** on spend. Trusted Advisor surfaces **underutilized resources** but does not alert on custom thresholds.

### Attribution Prerequisites

- **Cost Allocation Tags:** Tag resources with environment/model/team before analysis
- **Tagging pattern:** `CostCenter`, `ModelName`, `Environment`, `Team`, `ProjectID`
- **Cost Categories:** Group tags into business-friendly buckets in Cost Explorer
- **Budgets by tag aggregate:** Set separate budgets per team/model

## AI-Specific Cost Patterns to Monitor

| Pattern | Metric | Alert Threshold |
|---|---|---|
| **Token usage trend** | `TokenUsage` (CloudWatch) | Forecast exceeds budget at current growth |
| **Embedding compute** | Batch job duration × instance cost | Unexpected re-embedding of corpus |
| **Vector DB storage** | GB stored + IOPS provisioned | Unbounded index growth from new data |
| **Prompt inflation** | Avg tokens per request | Rising input size without traffic change |
| **Agent amplification** | Cost per completed invocation | Tool retry loops, verbose tool outputs |
| **Cache hit rate** | Cached tokens / total input tokens | Low hit rate = wasted cache writes |

## Dashboard Design for Optimization Decisions

| Dashboard Group | Metrics | Answers |
|---|---|---|
| **Capacity** | CPU/GPU utilization, memory, invocations per instance | Right-size vs scale? |
| **Performance** | Latency (p50/p95/p99), overhead latency, model latency | Is slowness due to capacity? |
| **Errors** | 4xx/5xx rates, throttling, ModelErrorRatio | Availability vs configuration? |
| **Token economics** | Input tokens/req, output tokens/req, cache hit %, cost per invocation | Traffic vs prompt weight? |
| **Cost attribution** | Spend by tag, model, environment | Which team/model drives spend? |

## Anti-Patterns Summary

- ❌ **Right-sizing an endpoint that needs auto scaling** — creates recurring capacity exhaustion
- ❌ **Applying Compute Savings Plans to SageMaker** — no discount applies
- ❌ **Enabling prompt caching with dynamic prefix** — invalidates every request; no savings
- ❌ **Using Spot for real-time endpoints** — interruption kills serving SLA
- ❌ **Setting budgets without tags** — spend threshold fires, but no attribution
- ❌ **Monitoring only invocation count for agents** — hidden model/tool call multiplication
- ❌ **Holding provisioned throughput for experimental traffic** — over-commitment to unproven demand
- ❌ **Using larger model than task requires** — quality excess is a pure cost waste
