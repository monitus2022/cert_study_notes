## Decision Matrix: Three Ways to Run a SageMaker Training Job

| Route | Training Logic | Container | Maintenance | Best When |
|-------|---------------|-----------|-------------|-----------|
| **Built-in Algorithm** | AWS-provided | AWS-managed | None | Standard tabular/NLP/CV tasks; fastest path |
| **Script Mode** | Your script (`entry_point`) | AWS-managed DLC | Script only | Custom architecture on standard frameworks |
| **BYO Container** | Your script | Your Docker image in ECR | Full container lifecycle | Exotic dependencies; unmanaged frameworks |

> **AWS-supplied training scripts run in script mode internally.** The terms "built-in" and "script mode" overlap—built-in often means AWS wrote the script and you just pass data + hyperparameters.

## Built-in Algorithm → Problem Type Map

| Algorithm | Problem | Key Hyperparameters | Notes |
|-----------|---------|---------------------|-------|
| **XGBoost** | Tabular classification/regression | `num_round`, `max_depth`, `eta`, `subsample`, `colsample_bytree` | Most common tabular choice; AWS version supports multi-instance |
| **Linear Learner** | Linear regression, binary/multi-class | `optimizer`, `learning_rate`, `batch_size`, `wd` (L2) | Fast baseline; handles sparse data well |
| **K-Means** | Clustering | `k`, `init_method`, `mini_batch_size` | Trains on unlabeled data |
| **PCA** | Dimensionality reduction | `num_components`, `algorithm_mode` | Modes: `regular`, `randomized` |
| **Factorization Machines** | Sparse tabular; recommendation | `factors_wd`, `factors_lr`, `epochs` | Handles categorical features natively |
| **Object Detection** | CV bounding boxes | `num_classes`, `base_network`, `mini_batch_size` | Requires RecordIO format annotations |
| **Image Classification** | CV classification | `num_classes`, `epochs`, `augmentation_type` | Transfer learning support via `use_pretrained_model` |
| **Semantic Segmentation** | CV pixel-wise | `backbone`, `validation_min_ratio` | Built on MXNet Gluon |
| **Seq2Seq** | Sequence-to-sequence text | `num_layers`, `embed_size`, `lr` | Used for translation, summarization |
| **LDA** | Topic modeling | `num_topics`, `alpha0` | Can be used in inference pipelines |
| **KNN** | Classification/regression | `k`, `sample_size` | Proxy-based inference |

> **XGBoost is the default choice for tabular data.** Linear Learner is for sparse, high-dim, low-sample scenarios. Factorization Machines are for high-cardinality categorical data.

## Script Mode: Estimator Configuration

```python
from sagemaker.pytorch import PyTorch

estimator = PyTorch(
    entry_point="train.py",
    source_dir="src/",                     # local dir with the script
    framework_version="2.1.0",
    py_version="py310",
    instance_type="ml.p3.2xlarge",
    instance_count=1,
    hyperparameters={
        "epochs": 12,
        "batch-size": 32,
        "learning-rate": 0.001,
    },
    role=role,
    output_path=f"s3://{bucket}/output",
)
```

| Framework | Estimator Class | Supported Libraries |
|-----------|----------------|--------------------|
| **PyTorch** | `sagemaker.pytorch.PyTorch` | Torch, torchvision, torchnlp |
| **TensorFlow** | `sagemaker.tensorflow.TensorFlow` | TF 2.x, Keras |
| **Hugging Face** | `sagemaker.huggingface.HuggingFace` | transformers, datasets |
| **scikit-learn** | `sagemaker.sklearn.SKLearn` | scikit-learn, pandas |
| **MXNet** | `sagemaker.mxnet.MXNet` | Gluon, NDArray |

> **Hyperparameters are injected as CLI arguments.** Use `argparse` in your script to parse them. SageMaker does not modify your training loop—only executes it within a managed container.

> **`source_dir` matters.** It packages every file in the directory and uploads it to S3. Excluding `source_dir` means only `entry_point` is shipped.

## Data Input Modes

| Mode | Use Case | Channel Setup |
|------|----------|---------------|
| **File** | Small to medium datasets; single file download | `TrainingInput(s3_data, input_mode="File")` |
| **Pipe** | Streams data directly from S3; avoids disk bottleneck | Requires Pipe-mode support in container; use with RecordIO |
| **FastFile** | Download to attached NVMe SSD | Default for most DLCs; parallel download |

> **Pipe mode eliminates cross-checking with `installed_packages` and is not universal.** Most built-in algorithms support Pipe, but not all custom scripts do. Default to File/FastFile.

## Security & IAM

| Requirement | Setting |
|-------------|---------|
| **Training role minimum permissions** | `s3:GetObject` on train/validation data; `s3:PutObject` on output bucket; `sagemaker:DescribeTrainingJob` |
| **KMS encryption at rest** | `output_kms_key` for model artifacts; S3 default SSE-S3 or SSE-KMS |
| **VPC isolation** | Set `subnets` + `security_group_ids` on estimator to run inside VPC |
| **Container registry access** | `ecr:GetDownloadUrlForLayer`, `ecr:BatchGetImage` for DLCs |

## Anti-Patterns & Exam Gotchas

| Anti-Pattern | Why It Fails |
|--------------|-------------|
| **Using built-in Linear Learner on text** | Built-ins expect numeric or RecordIO formats; no tokenizer |
| **Installing packages during training** (pip) | Use DLC with preinstalled libs or BYO container; reduce security surface |
| **Hardcoding S3 paths in script** | Use SageMaker environment variables: `SM_MODEL_DIR`, `SM_CHANNEL_TRAINING` |
| **Forgetting `wait=False` on estimator.fit** | Training job runs asynchronously; attached notifier prevents accidental early return |
| **Choosing built-in Image Classification for custom architecture** | It is a prebuilt ResNet-based network; custom nets require script mode or BYO |
| **Using `instance_count>1` with built-in KMeans** | KMeans does not distribute cleanly across instances |

> **The three SageMaker training routes are about ownership, not capability.** Built-in = AWS owns the ML logic. Script mode = you own the ML logic, AWS owns the runtime. BYO container = you own everything. The exam will often test whether a candidate correctly identifies which path matches a given team constraint (no Dockerfile maintenance, no custom framework, etc.).

## Frameworks & Version Pinning

| Component | Boto3 / SDK Detail |
|-----------|-------------------|
| **`framework_version`** | Required for framework estimators; must match a supported DLC version |
| **`py_version`** | Must match `framework_version` compatibility matrix |
| **`distribution`** | Dict with `"parameter_server"` or `"smdistributed"` keys |
| **`metric_definitions`** | List of `{"Name": "...", "Regex": "..."}` to parse custom metrics into CloudWatch |

## Training Job Environment Variables

**Available to any training script (script mode or BYO):**

| Variable | Purpose |
|----------|---------|
| `SM_MODEL_DIR` | Where to write final model artifacts (auto-uploaded to `output_path`) |
| `SM_CHANNEL_TRAINING` | Path to training data |
| `SM_CHANNEL_VALIDATION` | Path to validation data |
| `SM_CHANNELS` | JSON list of all channel names |
| `SM_HPS` | JSON dict of all hyperparameters |
| `SM_NUM_GPUS` | Number of GPUs on the instance |
| `SM_CURRENT_HOST` | Current instance in cluster |
| `SM_HOSTS` | JSON list of all instance hostnames (for distributed) |

> **Save model artifacts to `SM_MODEL_DIR`, not arbitrary paths.** Files written elsewhere are not uploaded to S3 and are lost when the container terminates.
