| **### Question 1 - Mitigating Sequential Batch Ordering Bias**<br><br>A retail company collected sales data sequentially by region, which is now stored in Amazon S3 and ingested into SageMaker for training a propensity model. The AI team notices that the mini-batches during training contain entire regions at once, causing the model to overfit to the first few regions and poorly generalize to others. They need the most operationally efficient way to distribute the underrepresented regions across all training batches without changing the dataset size or requiring additional data collection.<br><br>Which technique addresses this issue specifically? (Select ONE)<br><br>- **A)** Apply data augmentation to the underrepresented regions to add variation.<br>- **B)** Perform a stratified split to ensure equal distribution in train and test sets.<br>- **C)** Shuffle the records before training to break the alignment between collection order and batching.<br>- **D)** Oversample the underrepresented regions using SMOTE. | **Correct Answer:** **C**<br><br>**Correct Option Analysis:**<br>- **C is Correct:** When data is collected sequentially by category, training without shuffling causes mini-batch gradient descent to process entire regions sequentially. Shuffling breaks this alignment, ensuring samples from sparse regions are distributed evenly across all mini-batches throughout training.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** While augmentation adds synthetic sample diversity, it does not fix the underlying mini-batch ordering artifact caused by regional batch grouping. It also adds operational overhead.<br>- **B is Incorrect:** Stratified splitting ensures proportional representation across train/test splits, but it does not solve the intra-batch sequential ordering bias during gradient descent.<br>- **D is Incorrect:** Oversampling increases the count of underrepresented records but doesn't inherently fix the batch sequence order unless combined with shuffling.<br><br>> **Key Takeaway:** Shuffling reorders existing data to prevent temporal or collection-order biases during mini-batch gradient descent, but it does not change underlying class proportions or fix underrepresentation. |

It supports multiple data types and requires minimal custom code.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** Amazon Comprehend is used for extracting insights and PII from text, not for visualizing and balancing multimodal (numeric/image) data distributions.<br>- **C is Incorrect:** AWS Glue Data Quality evaluates datasets against declared rules (DQDL) but does not provide interactive visual transformations for balancing image/numeric distributions.<br>- **D is Incorrect:** Amazon Bedrock Guardrails are used for content filtering and safety screening of prompts/responses, not for dataset bias visualization.<br><br>> **Key Takeaway:** SageMaker Data Wrangler is the go-to tool for interactive, low-code data preparation, transformation, and bias mitigation across multimodal datasets. |
| **### Question 3 - Resolving Class Imbalance in Image Datasets**<br><br>A medical imaging company is training a SageMaker model to detect a rare disease from X-ray images stored in Amazon S3. The dataset contains 10,000 healthy images and 50 diseased images. The model reports 99% overall accuracy but fails to detect the rare disease in practice. The team needs to resolve this class imbalance with the least operational overhead while preserving the existing image data.<br><br>Which TWO techniques should the team apply? (Select TWO)<br><br>- **A)** Collect more healthy images to balance the dataset.<br>- **B)** Use class weighting to penalize errors on the rare class more heavily during training.<br>- **C)** Apply data augmentation to generate additional variation for the rare class.<br>- **D)** Drop 9,950 healthy images to force a 50/50 balance.<br>- **E)** Rely solely on overall accuracy as the primary evaluation metric. | **Correct Answers:** **B** and **C**<br><br>**Correct Option Analysis:**<br>- **B is Correct:** Class weighting increases the penalty for misclassifying the minority class, forcing the model to pay attention to the rare disease without requiring additional data collection.<br>- **C is Correct:** Data augmentation (e.g., rotating, flipping, cropping images) creates synthetic variation for the rare class, increasing its representation in the training data.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** Collecting more healthy images would worsen the imbalance, as the dataset already has a surplus of healthy images.<br>- **D is Incorrect:** Dropping 9,950 healthy images results in massive data loss and discards valuable information about healthy variations.<br>- **E is Incorrect:** Relying on overall accuracy is misleading in highly imbalanced datasets (the accuracy paradox). Metrics like Precision, Recall, or PR-AUC are required.<br><br>> **Key Takeaway:** Standard levers for resolving class imbalance include adding examples, reducing examples, generating variation (augmentation), or weighting the rare class more heavily. |

| **### Question 5 - Impact of Mean Imputation on Data Distribution**<br><br>A financial institution is preparing a dataset for a credit scoring model using AWS Glue DataBrew. A critical numeric column, "credit_utilization_ratio," has 15% missing values. To keep the rows usable for training, the data scientist decides to fill the missing values with the column's average (mean imputation).<br><br>What is the direct impact of this cleaning decision on the dataset's distribution? (Select ONE)<br><br>- **A)** It preserves the original distribution exactly.<br>- **B)** It removes the affected rows from the dataset.<br>- **C)** It pulls the distribution toward the middle and decreases variance.<br>- **D)** It converts the column to a categorical feature. | **Correct Answer:** **C**<br><br>**Correct Option Analysis:**<br>- **C is Correct:** Mean imputation replaces missing values with the average of the observed data. This retains the rows but artificially increases the frequency of central values, decreasing overall variance and pulling the feature's distribution toward the middle.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** Mean imputation alters the variance, standard deviation, and covariance of the feature, thus changing the distribution.<br>- **B is Incorrect:** Dropping affected rows refers to listwise deletion, which mean imputation explicitly avoids.<br>- **D is Incorrect:** Imputing a column with its numeric mean retains its continuous numeric data type, not categorical.<br><br>> **Key Takeaway:** Imputation choices carry assumptions. Mean imputation keeps rows usable but artificially narrows the variance and pulls the distribution toward the mean. |
| **### Question 6 - Resolving Inter-Annotator Disagreement**<br><br>A company is using Amazon SageMaker Ground Truth to label a dataset of customer reviews as positive, neutral, or negative. During the labeling process, two human annotators consistently disagree on the boundary between "neutral" and "negative" reviews. The ML engineer needs to resolve this issue to ensure high label quality and prevent the model from learning a blurred boundary.<br><br>What is the most appropriate action to take? (Select ONE)<br><br>- **A)** Remove the annotator who labels fewer items as negative.<br>- **B)** Add more unlabeled customer reviews to the dataset.<br>- **C)** Refine the labeling instructions to provide clear edge-case examples for the neutral/negative boundary.<br>- **D)** Switch to a larger language model architecture to handle the ambiguity. | **Correct Answer:** **C**<br><br>**Correct Option Analysis:**<br>- **C is Correct:** Persistent disagreement between annotators (low inter-annotator agreement) signals that the labeling instructions lack clear, mutually exclusive guidelines at the class boundary. Refining the instructions with specific edge-case examples directly resolves the ambiguity.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** Removing a worker treats a symptom rather than the root cause. Consistent disagreement across trained labelers points to systemic ambiguity in the instructions.<br>- **B is Incorrect:** Collecting more unlabeled data does not clarify ambiguous definitions; it will result in more inconsistently labeled noise.<br>- **D is Incorrect:** Model selection is downstream. A model cannot fix systemic data quality or labeling ambiguity issues.<br><br>> **Key Takeaway:** Label quality sets a ceiling on model quality. If annotators disagree on a class boundary, refine the labeling instructions rather than blaming the annotators or changing the model. |
| **### Question 7 - Enforcing Declarative Data Quality Rules**<br><br>A logistics company ingests daily shipment data into an Amazon S3 bucket and catalogs it in the AWS Glue Data Catalog. The data engineering team needs to enforce explicit, repeatable rules, such as requiring "tracking_id" to be 100% complete and "shipment_weight" to be between 0.1 and 100.0 kg, on every run before the data is used for ML training. The solution must minimize operational overhead and custom code.<br><br>Which AWS service should they use? (Select ONE)<br><br>- **A)** Author a ruleset in the Data Quality Definition Language (DQDL) and let AWS Glue Data Quality evaluate it.<br>- **B)** Write custom AWS Lambda functions to check the data on every S3 PutObject event.<br>- **C)** Use Amazon SageMaker Data Wrangler to manually profile the data each morning.<br>- **D)** Apply Amazon Bedrock Guardrails content filters to the dataset. | **Correct Answer:** **A**<br><br>**Correct Option Analysis:**<br>- **A is Correct:** AWS Glue Data Quality uses DQDL to define explicit, declarative rules (e.g., `Completeness "tracking_id" > 1.0` or `ColumnValues "shipment_weight" between 0.1 and 100.0`). These rulesets can be evaluated automatically against data in the Glue Data Catalog on every run.<br><br>**Distractor Analysis:**<br>- **B is Incorrect:** Writing custom Lambda functions introduces unnecessary operational overhead and custom code compared to declarative rule evaluation.<br>- **C is Incorrect:** Data Wrangler is an interactive tool for manual profiling and transformation, not an automated, declarative rule-evaluation engine for pipeline runs.<br>- **D is Incorrect:** Bedrock Guardrails screen prompts and model responses for safety, not tabular dataset column completeness or value ranges.<br><br>> **Key Takeaway:** AWS Glue Data Quality allows you to define explicit, declarative rules using DQDL that can be automatically evaluated against datasets in the Glue Data Catalog. |
| **### Question 8 - The Accuracy Paradox in Imbalanced Datasets**<br><br>An e-commerce platform is training a fraud detection model using SageMaker. The dataset consists of 99% legitimate transactions and 1% fraudulent transactions. After training, the model reports an overall accuracy of 99%. However, the business stakeholders complain that the model fails to catch any actual fraud.<br><br>Why is the overall accuracy metric misleading in this scenario? (Select ONE)<br><br>- **A)** Accuracy cannot be mathematically calculated on imbalanced datasets.<br>- **B)** The model can achieve 99% accuracy by simply predicting "legitimate" for every transaction.<br>- **C)** The fraudulent label carries less mathematical information than the legitimate label.<br>- **D)** Imbalance inherently slows down the model's convergence time, leading to flawed metric calculation. | **Correct Answer:** **B**<br><br>**Correct Option Analysis:**<br>- **B is Correct:** In highly imbalanced datasets, a naive model that predicts the majority class 100% of the time will achieve high overall accuracy (the accuracy paradox) while completely failing to identify minority instances.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** Accuracy can easily be calculated; it is simply uninformative and misleading for imbalanced distributions.<br>- **C is Incorrect:** While minority examples are of higher business value, the misleading nature of accuracy stems from majority-class masking, not information theory.<br>- **D is Incorrect:** Class imbalance affects model prediction bias, but it does not inherently increase computation time or break metric math.<br><br>> **Key Takeaway:** Overall accuracy is misleading in class-imbalanced datasets. Use Precision, Recall, F1-score, or PR-AUC to properly evaluate minority-class detection. |
| **### Question 9 - Risks of Near-Duplicate Deduplication**<br><br>A media streaming service is preparing a dataset of user interaction logs for a recommendation engine. The data is processed using AWS Glue DataBrew. The data scientist notices several near-duplicate records that differ only by a single field, such as a timestamp offset by 1 second.<br><br>What is the risk of treating these near-duplicates as distinct records during the deduplication phase? (Select ONE)<br><br>- **A)** It artificially inflates the pattern they share, biasing the recommendation engine.<br>- **B)** It removes the need to measure bias metrics on the dataset.<br>- **C)** It converts the continuous timestamp into a categorical feature.<br>- **D)** It preserves the original distribution exactly while increasing dataset size. | **Correct Answer:** **A**<br><br>**Correct Option Analysis:**<br>- **A is Correct:** Near-duplicate records that differ in only one field are an ambiguous case. Treating them as distinct records inflates whatever pattern they share, heavily biasing the model toward that specific interaction pattern.<br><br>**Distractor Analysis:**<br>- **B is Incorrect:** Deduplication choices do not remove the necessity of measuring bias metrics; they are independent data preparation steps.<br>- **C is Incorrect:** Deduplication does not change the data type of the fields involved.<br>- **D is Incorrect:** While it does increase dataset size, it definitely does not preserve the original distribution; it skews it toward the duplicated pattern.<br><br>> **Key Takeaway:** Deduplication has an edge case: near-duplicates. Treating near-duplicates as distinct records inflates the underlying pattern they share, skewing model training. |
