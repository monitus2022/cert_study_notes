| **### Question 1 - SageMaker AI MLflow for Reproducible Training Runs**<br><br>A machine learning engineering team is training a custom XGBoost model on Amazon SageMaker AI. They need to ensure that every training run is fully reproducible, tracking all hyperparameters, metrics, and model artifacts with the **least operational overhead**. Compliance rules mandate that experiment data must be stored securely within their AWS account without managing underlying tracking servers.<br><br>Which solution meets these requirements? (Select ONE)<br><br>- **A)** Manually log parameters and metrics to Amazon CloudWatch Logs and save artifacts to an S3 bucket.<br>- **B)** Configure Amazon SageMaker AI Managed MLflow to automatically capture run metadata, parameters, metrics, and artifacts.<br>- **C)** Deploy an open-source MLflow tracking server on an Amazon EC2 instance and point SageMaker training jobs to it.<br>- **D)** Use the SageMaker Model Registry to track only the model artifacts after the training job completes. | **Correct Answer:** **B**<br><br>**Correct Answer Analysis:**<br>- **B is Correct:** Amazon SageMaker AI provides a fully managed MLflow tracking server. (Select ONE)<br><br>- **A)** Programmatic evaluation using ROUGE and BLEU metrics.<br>- **B)** Human evaluation using a team of internal financial domain experts.<br>- **C)** LLM-as-a-judge evaluation using a more powerful model (e.g., Claude 3 Opus) to score and explain the responses.<br>- **D)** Shadow deployment comparing the two models on live traffic. | **Correct Answer:** **C**<br><br>**Correct Answer Analysis:**<br>- **C is Correct:** The LLM-as-a-judge evaluation method in Amazon Bedrock Evaluations uses a capable model to automatically score responses and provide a reasoning chain for the score. | **### Question 9 - Debugging ML Model Convergence using MLflow**<br><br>A team is using Amazon SageMaker AI to train a deep learning model. They notice that the validation loss has been worsening over the last 20 epochs while the training loss continues to improve. They are using SageMaker AI Managed MLflow to track experiments. Based on the tracked metrics, what is the most likely issue they are experiencing?<br><br>- **A)** The learning rate is set too high, causing the loss to oscillate.<br>- **B)** The model is overfitting to the training data.<br>- **C)** The training data storage format is incorrect.<br>- **D)** The model lacks the capacity to learn the signal. | **Correct Answer:** **B**<br><br>**Correct Answer Analysis:**<br>- **B is Correct:** When training loss decreases but validation loss increases (worsens), it is the classic signature of overfitting. The model is memorizing the training data rather than generalizing to unseen data.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** A learning rate that is too high typically causes the loss to oscillate wildly and never settle, rather than showing a steady decrease in training loss.<br>- **C is Incorrect:** Data storage format affects I/O speed, not the divergence of training and validation loss curves.<br>- **D is Incorrect:** If the model lacked capacity, the training loss would barely move or fail to decrease in the first place.<br><br>> **Exam Tip:** Read the curves: training loss down + validation loss up = overfitting. Loss not moving = model capacity or learning rate too low. Oscillating loss = learning rate too high. |
| **### Question 10 - Selecting GenAI Evaluation Metrics**<br><br>A team is using Amazon Bedrock Evaluations to assess a text summarization model. They need an automated, programmatic metric that evaluates the lexical overlap of n-grams between the generated summary and a reference summary. They want to avoid using an LLM-as-a-judge to save on compute costs.<br><br>Which metric is most appropriate for this programmatic evaluation? (Select ONE)<br><br>- **A)** BERTScore<br>- **B)** ROUGE<br>- **C)** Semantic Similarity<br>- **D)** Perplexity | **Correct Answer:** **B**<br><br>**Correct Answer Analysis:**<br>- **B is Correct:** ROUGE (Recall-Oriented Understudy for Gisting Evaluation) is a programmatic, n-gram overlap-based metric specifically designed for evaluating text summarization by comparing the generated text to a reference.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** BERTScore uses embeddings to measure semantic similarity, not lexical n-gram overlap, and is computationally heavier.<br>- **C is Incorrect:** Semantic Similarity is an embedding-based measure that compares meaning, not exact word overlap.<br>- **D is Incorrect:** Perplexity measures how well a probability model predicts a sample, typically used for evaluating language modeling itself, not summarization overlap.<br><br>> **Exam Tip:** Choose ROUGE or BLEU for cheap, fast, lexical (n-gram) overlap evaluation. Choose BERTScore or LLM-as-a-judge for semantic meaning evaluation. |
