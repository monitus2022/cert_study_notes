| **### Question 1 - AgentCore Memory: Long-term vs Short-term**<br><br>A retail company uses an AI agent to handle customer support. The agent successfully maintains context during a single multi-turn conversation, but returning customers have to repeat their order history and preferences on every new visit. The engineering team needs to implement a solution that persists context across sessions without mixing data between different users, adhering to strict privacy requirements.<br><br>Which solution meets these requirements with the **least operational overhead**? (Select ONE)<br><br>- **A)** Increase the session timeout for the Bedrock Agent to 24 hours.<br>- **B)** Configure Amazon Bedrock AgentCore Memory to use long-term memory scoped to an actor namespace.<br>- **C)** Store the full transcript of every session in an Amazon S3 bucket and prepend it to the prompt for future sessions.<br>- **D)** Deploy a separate Bedrock Agent instance for every user to maintain state. | **Correct Answer:** **B**<br><br>**Correct Answer Analysis:**<br>- **B is Correct:** Amazon Bedrock AgentCore Memory supports long-term memory (LTM), which automatically extracts and consolidates persistent insights (like user preferences) scoped to a user/actor namespace. This allows context to persist securely across distinct sessions without manual intervention or custom data pipelines.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** Increasing the session timeout only extends the duration of short-term memory for a single active session; it does not persist context after the session expires.<br>- **C is Incorrect:** Storing transcripts in S3 and manually prepending them introduces massive operational overhead, increases token costs, and risks data leakage between users.<br>- **D is Incorrect:** Deploying a separate agent instance per user is highly inefficient, unscalable, and violates the least operational overhead constraint.<br><br>> **Key Takeaway:** Use short-term memory for single-session context and AgentCore Long-term Memory (scoped by actorId) for cross-session context. |

(Select ONE)<br><br>- **A)** Use target tracking on a high-resolution concurrency metric.<br>- **B)** Increase the target value on the existing 1-minute invocation metric.<br>- **C)** Implement a scheduled scaling action for the duration of the marketing event.<br>- **D)** Manually pre-provision maximum capacity and leave it running. | **Correct Answer:** **A**<br><br>**Correct Answer Analysis:**<br>- **A is Correct:** High-resolution concurrency metrics (e.g., `ConcurrentRequestsPerModel`) emit at sub-minute intervals (e.g., 10 seconds).
