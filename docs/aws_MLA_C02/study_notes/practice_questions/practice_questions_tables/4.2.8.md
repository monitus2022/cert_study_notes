| **### Question 1 - Tracing Agent Invocations with Bedrock AgentCore**<br><br>An enterprise is deploying a multi-step customer service agent using **Amazon Bedrock**. | **### Question 6 - Diagnosing Ineffective Prompt Caching in Agents**<br><br>A team is troubleshooting an Amazon Bedrock agent that summarizes daily reports but includes a large, volatile context window that changes with every request. The team wants to implement prompt caching to reduce resource consumption but finds that the savings are not materializing. Which monitoring approach will best explain why the cache is missing, and what is the likely root cause?<br><br>Which approach identifies the issue and the root cause? (Select ONE)<br><br>- **A)** Check CloudWatch Metrics for high CacheHitRate; the root cause is that the response length is too long.<br>- **B)** Inspect the agent traces in AgentCore Observability to view token counts; the root cause is that the volatile context is placed before the static prefix, invalidating the cache.<br>- **C)** Review CloudTrail logs for API throttling; the root cause is that the model is too small.<br>- **D)** Monitor CPU utilization using CloudWatch; the root cause is that the vector database is returning too many results. | **Correct Answer:** **B**<br><br>**Correct Answer Analysis:**<br>- **B is Correct:** AgentCore Observability allows the team to view the exact input token counts per invocation. If cache is missing, the input token count will remain high. Response length does not invalidate input prompt cache.<br>- **C is Incorrect:** API throttling in CloudTrail would manifest as errors, not as a failure to cache tokens. Model size does not affect cache invalidation.<br>- **D is Incorrect:** CPU utilization is an infrastructure metric and does not diagnose prompt caching behavior, which is an application-level token optimization feature.<br><br>> **Key Takeaway:** Prompt caching requires a stable, static prefix; dynamic content at the start of a prompt invalidates the cache. Use AgentCore to observe the resulting high input token counts. |
