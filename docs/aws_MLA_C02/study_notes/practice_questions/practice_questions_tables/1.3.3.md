| **### Question 1 - Mitigating Collection Order Bias with Shuffling**<br><br>A retail company is building an ML model to predict customer churn. The dataset was collected sequentially over six months, and early data contains mostly high-value customers, while later data contains mostly low-value customers. The data science team must prepare the dataset for training while ensuring that mini-batch gradient descent does not learn temporal ordering artifacts. The solution must require the least operational overhead and use native AWS tooling.<br><br>Which **ONE** action should the team take to fulfill these requirements?<br><br>- **A)** Write a custom Python script in a SageMaker Processing job to sort the dataset by customer value.<br>- **B)** Use Amazon SageMaker Data Wrangler to shuffle the dataset randomly before splitting it into training and validation sets.<br>- **C)** Deploy an AWS Lambda function to randomly sample records and write them back to S3.<br>- **D)** Use Amazon SageMaker Ground Truth to label the low-value customers with higher confidence weights. | **Correct Answer:** **B**<br><br>**Correct Option Analysis:**<br>- **B is Correct:** Shuffling the dataset randomly breaks the alignment between collection order and the mini-batches fed into the training algorithm. Using SageMaker Data Wrangler provides a native, low-operational-overhead way to perform this transformation visually without writing custom code.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** Sorting by customer value would artificially group records by value rather than removing the temporal ordering artifact, potentially introducing a new ordering bias.<br>- **C is Incorrect:** Writing a custom Lambda function to randomize records in S3 introduces unnecessary operational overhead and is not a best practice for large ML datasets.<br>- **D is Incorrect:** SageMaker Ground Truth is used for data labeling, not for re-weighting classes or mitigating ordering bias during data preparation.<br><br>> **Key Takeaway:** Shuffling is the primary technique to remove bias introduced by the order in which data was collected or ingested, ensuring mini-batches are representative of the overall dataset. |
| **### Question 2 - Addressing Image Representation Bias via Augmentation**<br><br>An autonomous vehicle startup is training an object detection model. The image dataset is heavily biased towards daytime images, with only 5% nighttime images. The team must improve model performance on nighttime conditions without deploying a new fleet to collect more data, and must do so natively within Amazon SageMaker. The solution must not reduce the overall size of the dataset.<br><br>Which **ONE** technique should the team use to mitigate this bias?<br><br>- **A)** Use SageMaker Data Wrangler to drop daytime images until the dataset is balanced.<br>- **B)** Use Amazon Rekognition to label the nighttime images and increase their confidence scores.<br>- **C)** Apply image augmentation techniques (e.g., brightness/contrast adjustment, synthetic noise) to the nighttime images to synthetically increase their representation and diversity.<br>- **D)** Use SageMaker Ground Truth to generate synthetic daytime images from the nighttime images. | **Correct Answer:** **C**<br><br>**Correct Option Analysis:**<br>- **C is Correct:** Data augmentation modifies existing images to create new, synthetic variations. By applying augmentations to the underrepresented nighttime images, the team increases their representation and diversity without discarding valuable daytime data or deploying new collection mechanisms.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** Dropping daytime images (undersampling) reduces the overall size of the dataset, which violates the stated constraint and wastes valuable data.<br>- **B is Incorrect:** Amazon Rekognition provides labels and confidence scores but does not inherently solve representation bias; re-labeling does not increase the model's exposure to nighttime visual features.<br>- **D is Incorrect:** SageMaker Ground Truth is for human annotation workflows, not for synthetic image generation.<br><br>> **Key Takeaway:** Augmentation is the preferred method to address representation bias in image datasets when collecting new data is not feasible, as it increases minority class representation without reducing dataset size. |
| **### Question 3 - Bias Detection and Stratified Splitting with SageMaker Clarify**<br><br>A financial institution is preparing a dataset for a loan approval model. The dataset contains a sensitive attribute `gender` which is highly imbalanced, leading to potential representation bias. The team needs to evaluate the dataset for bias before training and split the data ensuring the exact same proportion of genders in the training and test sets. They want to use a managed AWS service designed specifically for this task.<br><br>Which **ONE** approach should the team take?<br><br>- **A)** Use Amazon SageMaker Clarify to generate bias metrics and apply stratified splitting based on the sensitive attribute.<br>- **B)** Use AWS Glue DataBrew to profile the dataset and manually create train/test splits using a custom PySpark script.<br>- **C)** Use Amazon Comprehend to detect PII in the gender column and redact it before splitting.<br>- **D)** Use Amazon SageMaker Feature Store to store the features, which will automatically balance the gender distribution during retrieval. | **Correct Answer:** **A**<br><br>**Correct Option Analysis:**<br>- **A is Correct:** Amazon SageMaker Clarify is specifically designed to detect bias in datasets and models using metrics like class imbalance (CI) and difference in positive proportions. It also provides built-in functionality for stratified splitting to ensure that sensitive attributes are proportionally represented across training, validation, and test sets.<br><br>**Distractor Analysis:**<br>- **B is Incorrect:** AWS Glue DataBrew is excellent for profiling and cleaning but lacks native, purpose-built bias detection metrics and stratified splitting based on sensitive attributes without custom scripting.<br>- **C is Incorrect:** Redacting the gender column with Amazon Comprehend removes the feature but does not evaluate or mitigate the underlying distribution bias in the dataset prior to training.<br>- **D is Incorrect:** SageMaker Feature Store is a repository for ML features; it does not automatically balance distributions or perform bias-aware stratified splits.<br><br>> **Key Takeaway:** SageMaker Clarify is the go-to AWS service for both identifying bias via pre-training metrics and executing stratified splits to maintain demographic proportions across data partitions. |
| **### Question 4 - Mitigating Multimodal Representation Bias (Select TWO)**<br><br>A healthcare company is building a model to predict disease progression. The dataset includes both numeric patient vitals (tabular) and X-ray images (image). The dataset exhibits representation bias across different age groups in both modalities. The team must mitigate this bias with minimal custom code using AWS services.<br><br>Which **TWO** techniques should the team employ to address the bias across both modalities?<br><br>- **A)** Use Amazon SageMaker Data Wrangler to oversample the underrepresented age groups in the tabular data.<br>- **B)** Apply image augmentation techniques (e.g., random rotations, cropping) to the X-ray images of the underrepresented age groups.<br>- **C)** Use AWS Glue Data Quality to drop the age group feature entirely to prevent the model from learning bias.<br>- **D)** Replace all missing numeric vitals with the global average using DataBrew.<br>- **E)** Deploy an AWS Lambda function to resize all images to a standard resolution. | **Correct Answers:** **A** and **B**<br><br>**Correct Options Analysis:**<br>- **A is Correct:** Oversampling the underrepresented group in the tabular data increases their weight during training without losing data from other groups. SageMaker Data Wrangler provides built-in transformations for balancing datasets.<br>- **B is Correct:** For image modalities, augmentation is the standard technique to increase the representation and diversity of an underrepresented group without collecting new raw images.<br><br>**Distractor Analysis:**<br>- **C is Incorrect:** Dropping the age group feature may hide the bias but does not fix the underlying data representation issue; the model will still underperform for that demographic if their features are not well-represented.<br>- **D is Incorrect:** Mean imputation addresses missing data, not representation bias or class imbalance across demographic groups.<br>- **E is Incorrect:** Resizing images is a standard preprocessing step but does nothing to address demographic representation bias.<br><br>> **Key Takeaway:** When dealing with multimodal datasets, bias mitigation techniques must be applied per modality: oversampling/SMOTE for tabular data and augmentation for image data. |
| **### Question 5 - Fixing Mini-Batch Ordering Artifacts**<br><br>An e-commerce platform is training a recommendation model. The training data was ingested chronologically and grouped strictly by user ID. When training without shuffling, the model learns the preferences of users at the beginning of the dataset and overwrites those weights with users at the end of the dataset. The team must fix this ordering artifact with the least computational overhead.<br><br>Which **ONE** action should the team take?<br><br>- **A)** Implement stratified sampling based on user ID.<br>- **B)** Apply shuffling to the entire dataset before feeding it into the training algorithm.<br>- **C)** Apply Synthetic Minority Over-sampling Technique (SMOTE) to the user features.<br>- **D)** Normalize the numerical features using Amazon SageMaker Data Wrangler. | **Correct Answer:** **B**<br><br>**Correct Option Analysis:**<br>- **B is Correct:** Shuffling the dataset randomly distributes the records so that mini-batches contain a diverse mix of user IDs, preventing the model's weights from being sequentially overwritten by the grouped ordering of users.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** Stratified sampling ensures proportional representation of classes, but it does not inherently break the within-group ordering artifacts that cause mini-batch gradient descent to learn sequentially.<br>- **C is Incorrect:** SMOTE is used to generate synthetic examples for an underrepresented class, not to fix the ordering of records within mini-batches.<br>- **D is Incorrect:** Normalization scales feature values but does not change the order in which the records are fed to the model.<br><br>> **Key Takeaway:** If data is ingested in batches grouped by a specific category (e.g., user ID, region, date), shuffling is mandatory to break the alignment between collection order and mini-batch composition. |
| **### Question 6 - Mitigating Class Imbalance in Text Data**<br><br>A media company is preparing a dataset for a sentiment analysis model. The text data contains a disproportionately high volume of positive reviews compared to negative reviews. The team needs to mitigate this class imbalance to ensure the model accurately detects negative sentiment. They want to use an AWS tool that provides built-in transformations for this specific purpose with the least operational overhead.<br><br>Which **ONE** approach should the team take?<br><br>- **A)** Use Amazon SageMaker Data Wrangler to apply SMOTE (Synthetic Minority Over-sampling Technique) directly to the raw text features.<br>- **B)** Use Amazon SageMaker Data Wrangler to randomly undersample the majority class (positive reviews).<br>- **C)** Use AWS Glue Data Quality to enforce a rule that limits the number of positive reviews.<br>- **D)** Use Amazon Comprehend to translate negative reviews to multiple languages to artificially increase their count. | **Correct Answer:** **B**<br><br>**Correct Option Analysis:**<br>- **B is Correct:** SageMaker Data Wrangler includes built-in transformations to balance data, such as randomly undersampling the majority class. This requires no custom code and directly addresses the class imbalance in the training dataset.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** SMOTE operates on continuous numeric feature vectors. It cannot be directly applied to raw text strings without first vectorizing the text, which adds operational overhead.<br>- **C is Incorrect:** AWS Glue Data Quality enforces data quality rules (like dropping rows that fail a condition), but it is not designed as an ML data balancing tool for class imbalance.<br>- **D is Incorrect:** Translating negative reviews into multiple languages changes the feature distribution and introduces multilingual noise; it is not a valid technique for resolving class imbalance in a monolingual model.<br><br>> **Key Takeaway:** For text classification datasets with class imbalance, random undersampling of the majority class or oversampling of the minority class are standard, low-overhead techniques available in SageMaker Data Wrangler. |
| **### Question 7 - Preventing Data Leakage and Distribution Bias in Splits**<br><br>An enterprise is preparing a training dataset for a binary classification model. The data scientists want to ensure that their train, validation, and test sets do not suffer from data leakage and that each set maintains the exact same distribution of a sensitive demographic feature (e.g., `age_group`). They want to accomplish this using an AWS native service without writing custom splitting scripts.<br><br>Which **ONE** approach fulfills these requirements?<br><br>- **A)** Use a random split via AWS Glue DataBrew.<br>- **B)** Use Amazon SageMaker Clarify to perform a stratified split based on the demographic feature.<br>- **C)** Use Amazon SageMaker Ground Truth to manually separate the records into different S3 buckets.<br>- **D)** Use AWS Glue Data Quality to validate the distributions after a manual split. | **Correct Answer:** **B**<br><br>**Correct Option Analysis:**<br>- **B is Correct:** Amazon SageMaker Clarify supports stratified splitting, which divides the dataset while preserving the percentage of samples for each target class or sensitive attribute. This ensures the distribution is consistent across all splits and prevents the model from being trained on a biased subset.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** A standard random split via Glue DataBrew may result in uneven distributions of the sensitive feature across the train, validation, and test sets, especially if the feature is a minority class.<br>- **C is Incorrect:** Manual separation via Ground Truth is highly inefficient and prone to human error, violating the requirement for an automated, scriptless AWS native approach.<br>- **D is Incorrect:** Validating distributions *after* a manual split does not proactively prevent the bias during the split; it only reports on it after the fact.<br><br>> **Key Takeaway:** Stratified splitting is essential when dealing with sensitive attributes or imbalanced classes, ensuring that every split accurately reflects the overall population distribution. |
| **### Question 8 - Resolving Class Imbalance vs. Geographic Representation Bias (Select TWO)**<br><br>A machine learning team is using Amazon SageMaker to train a model. The dataset is highly imbalanced regarding a specific outcome label (1% positive, 99% negative). Additionally, the dataset exhibits representation bias where one geographic region is severely underrepresented. The team must resolve both the class imbalance and the geographic representation bias before training.<br><br>Which **TWO** techniques should the team employ?<br><br>- **A)** Apply shuffling to the entire dataset to randomize the order of records.<br>- **B)** Use oversampling or class re-weighting to increase the impact of the rare outcome label.<br>- **C)** Apply data augmentation or collect more data to increase the representation of the underrepresented geographic region.<br>- **D)** Drop the geographic region feature from the dataset to eliminate bias.<br>- **E)** Convert the dataset to Parquet format to optimize the distribution of data. | **Correct Answers:** **B** and **C**<br><br>**Correct Options Analysis:**<br>- **B is Correct:** Class imbalance (where one outcome label dominates) is resolved by adding examples of the rare class (oversampling), reducing the majority class, or applying class weights during training so the model pays more attention to the rare class.<br>- **C is Correct:** Geographic representation bias (where a specific demographic or group is missing) is resolved by increasing the representation of that group, either through data augmentation or collecting additional real-world data.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** Shuffling reorders existing records but does nothing to change the underlying mathematical ratios of class imbalance or representation bias.<br>- **D is Incorrect:** Dropping the geographic feature prevents the model from explicitly using it, but does not fix the fact that the model lacks training data for that region's unique characteristics.<br>- **E is Incorrect:** Converting to Parquet optimizes storage and query performance but has zero effect on the statistical distribution or bias of the records.<br><br>> **Key Takeaway:** Class imbalance (outcome label proportions) and representation bias (group inclusion) are distinct problems requiring different remedies; rebalancing labels does not automatically fix demographic underrepresentation. |
| **### Question 9 - Handling Chronological Batch Bias**<br><br>A gaming company is building a churn prediction model. The raw data consists of player event logs collected sequentially by timestamp. The team noticed a recent game patch caused a spike in churn events. The team decides to treat this as a standard classification problem rather than a time-series forecasting problem, and must split the data such that both the training and test sets reflect the overall distribution of churn events, minimizing bias.<br><br>Which **ONE** splitting technique should they use?<br><br>- **A)** Perform a chronological split to preserve the time-series nature of the data, accepting the bias in the training set.<br>- **B)** Perform a standard random split without considering the churn label to ensure a 80/20 ratio of total records.<br>- **C)** Use stratified splitting on the `churn` label to ensure the ratio of churn events is consistent across training and test sets.<br>- **D)** Filter out the churn events from the recent game patch to make the dataset uniform. | **Correct Answer:** **C**<br><br>**Correct Option Analysis:**<br>- **C is Correct:** Because the churn events are clustered chronologically due to the game patch, a chronological split would place all churn events in the test set, starving the training set of positive examples. Stratified splitting on the `churn` label ensures both sets receive a proportional amount of churn and non-churn events, mitigating the temporal cluster bias.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** A chronological split would result in a training set with very few churn events, causing the model to predict poorly on the test set which contains the spike.<br>- **B is Incorrect:** A standard random split might still result in an uneven distribution of the rare churn events, whereas stratified splitting guarantees the distribution is maintained.<br>- **D is Incorrect:** Filtering out the recent churn events removes valuable data and prevents the model from learning the patterns associated with the game patch.<br><br>> **Key Takeaway:** When a rare event is clustered temporally or sequentially, standard random splits may not be sufficient; stratified splitting on the target label ensures both training and test sets contain representative examples. |
