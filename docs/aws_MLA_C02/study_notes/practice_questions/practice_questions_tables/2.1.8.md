| **### Question 1 - Document Extraction with Least Operational Overhead**<br><br>A financial technology company receives thousands of scanned loan applications in PDF format daily. They need to automatically extract key-value pairs like applicant name, loan amount, and interest rate, as well as table data from these documents. The engineering team has strict constraints to build this pipeline with the **least operational overhead** and **fastest time-to-market**.<br><br>Which AWS service should they use to accomplish this?<br><br>- **A)** Train a custom computer vision model using Amazon SageMaker to detect and extract text and table structures.<br>- **B)** Use Amazon Textract's `AnalyzeDocument` API to extract text, tables, and key-value pairs.<br>- **C)** Use Amazon Rekognition's `DetectText` API to extract text from the scanned PDFs.<br>- **D)** Fine-tune a foundation model in Amazon Bedrock by providing sample PDFs and expected JSON outputs. | **Correct Answer:** **B**<br><br>**Correct Answer Analysis:**<br>- **B is Correct:** Amazon Textract is a fully managed service specifically designed to automatically extract text, handwriting, layout elements, and structured data (like tables and key-value pairs) from scanned documents. It requires no model training, providing the least operational overhead and fastest time-to-market.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** Training a custom CV model in SageMaker requires data labeling (bounding boxes), model architecture selection, training, and hosting infrastructure, which introduces massive operational overhead compared to a managed API.<br>- **C is Incorrect:** While Amazon Rekognition `DetectText` can extract raw text from images, it is designed for short text in natural scenes (like street signs or social media images), not for extracting structured tables and key-value pairs from complex forms.<br>- **D is Incorrect:** Foundation models in Bedrock are primarily for text generation/reasoning. While some support multimodal inputs, fine-tuning them for precise structured document extraction is unnecessarily complex, costly, and inefficient compared to Textract.<br><br>> **Key Takeaway:** For extracting structured data (tables, forms, key-value pairs) from scanned documents, Amazon Textract is the native, low-overhead AWS AI service. |

It abstracts away the model training and hosting infrastructure, requiring minimal ML expertise.<br><br>**Distractor Analysis:**<br>- **B is Incorrect:** Amazon Comprehend is a natural language processing (NLP) service. It cannot analyze visual data like video footage or images for logo detection.<br>- **C is Incorrect:** Amazon Textract is designed for extracting text and structured data from documents, not for identifying specific visual objects or brand logos in video streams.<br>- **D is Incorrect:** Building a custom training script in SageMaker requires deep ML engineering expertise to architect, train, and deploy a computer vision model, violating the "minimal ML expertise" and "no infrastructure management" constraints.<br><br>> **Key Takeaway:** When you need to detect custom, proprietary objects in images/videos without managing infrastructure, use Amazon Rekognition Custom Labels. |

It supports real-time transcription and has a native Content Redaction feature that automatically identifies and redacts PHI/PII directly in the generated text, satisfying all constraints as a fully managed service.<br><br>**Distractor Analysis:**<br>- **B is Incorrect:** Transcribe Standard does not natively understand medical terminology as accurately as Transcribe Medical, and routing through a custom SageMaker NLP pipeline introduces unnecessary operational overhead and latency, violating the fully managed constraint.<br>- **C is Incorrect:** Amazon Comprehend Medical is an NLP service that analyzes *text*, not audio. It cannot directly transcribe audio files.<br>- **D is Incorrect:** Bedrock foundation models process text and images (via multimodal models), not direct audio streams. You would still need a transcription service first.<br><br>> **Key Takeaway:** For audio transcription involving medical terminology and requiring native PII/PHI redaction, Amazon Transcribe Medical is the correct managed service. |

It requires no custom model training, making it highly cost-effective and low-overhead.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** Amazon Rekognition is for image and video analysis, not text processing.<br>- **C is Incorrect:** Amazon Textract is for extracting text from scanned documents, not for analyzing the sentiment or meaning of text data.<br>- **D is Incorrect:** While SageMaker JumpStart offers pre-trained models, deploying and managing the endpoint still requires significantly more operational overhead than calling a fully managed serverless API like Amazon Comprehend.<br><br>> **Key Takeaway:** For out-of-the-box text NLP tasks (sentiment, entities, key phrases), use Amazon Comprehend to avoid training and hosting overhead. |

| **### Question 7 - Extracting Custom Entities from Text**<br><br>A manufacturing company wants to automatically scan internal engineering reports (stored as text) to extract proprietary part numbers (e.g., "XJ-9920-A") and warranty codes.
