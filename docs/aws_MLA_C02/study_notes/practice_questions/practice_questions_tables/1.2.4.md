| **### Question 1 - Feature Engineering for Linear Models**<br><br>A machine learning team is preparing a dataset for a linear regression model in Amazon SageMaker. The dataset contains numerical features with vastly different scales (e.g., annual income in the tens of thousands and age in the tens). To ensure that gradient descent converges efficiently, the team needs to transform the features so they are centered with a mean of 0 and a standard deviation of 1.<br><br>Which feature engineering technique should the team apply using SageMaker Data Wrangler to meet this requirement?<br><br>- **A)** Apply Min-Max Normalization.<br>- **B)** Apply Standardization (Z-score scaling).<br>- **C)** Apply Robust Scaling.<br>- **D)** Apply Log Transformation. | <details><summary><b>Correct Answer & Explanation</b></summary><br>**Correct Answer:** **B**<br><br>**Correct Answer Analysis:**<br>Standardization (or Z-score scaling) transforms the data so that it has a mean of 0 and a standard deviation of 1. This is crucial for linear models that use gradient descent, as it ensures the optimization landscape is spherical, allowing the algorithm to converge faster and more reliably.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** Min-Max Normalization scales the data to a fixed range, typically [0, 1], but does not center the mean at 0 or guarantee a standard deviation of 1.<br>- **C is Incorrect:** Robust scaling uses the median and interquartile range (IQR) instead of the mean and standard deviation, making it better for datasets with extreme outliers, but it does not result in a mean of 0 and standard deviation of 1.<br>- **D is Incorrect:** Log transformation is used to reduce the skewness of a distribution, not to center the data at a mean of 0 with a standard deviation of 1.<br><br>> **Key Takeaway:** Standardization (Z-score scaling) is the preferred feature engineering technique for linear models requiring normally distributed data centered at zero with unit variance.</details> |

By applying a logarithmic function, the large extreme values are pulled closer to the rest of the data, resulting in a more symmetric, normal-like distribution which many machine learning algorithms process more effectively.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** Binning converts continuous variables into categorical bins, which results in a loss of granular information that a tree-based model could otherwise utilize.<br>- **C is Incorrect:** Standardization scales the data around the mean but does not fundamentally change the shape (skewness) of the distribution.<br>- **D is Incorrect:** Feature splitting is used to break down compound fields (e.g., extracting a domain from an email address), not for adjusting numerical distributions.<br><br>> **Key Takeaway:** Log transformation is the standard technique for normalizing right-skewed continuous data by compressing the range of large numbers.</details> |

| **### Question 6 - Preventing Training-Serving Skew in Scaling**<br><br>An ML engineer has successfully trained a model using a `StandardScaler` fitted on the training dataset. The engineer is now deploying the model to a SageMaker real-time endpoint for inference. Compliance rules require that the feature distribution seen by the model during inference matches the training distribution exactly.<br><br>How should the engineer apply the scaling transformation to the real-time inference data to meet this requirement?<br><br>- **A)** Refit the `StandardScaler` on a batch of incoming real-time inference data to adapt to current trends.<br>- **B)** Apply the `StandardScaler` parameters (mean and variance) learned during training to the inference data.<br>- **C)** Recalculate the scaling parameters using a daily AWS Glue job and push them to the endpoint.<br>- **D)** Apply Min-Max Normalization locally on the incoming request payload before sending it to the model. | <details><summary><b>Correct Answer & Explanation</b></summary><br>**Correct Answer:** **B**<br><br>**Correct Answer Analysis:**<br>To prevent training-serving skew, the exact same transformation parameters (e.g., mean and standard deviation for StandardScaler) that were learned (fitted) on the training data must be applied (transformed) to the inference data. If the scaler is refit on new data, the mapping of input values changes, leading to inaccurate predictions.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** Refitting the scaler on inference data recalculates the mean and variance based on the new data, meaning the same input value will map to a different scaled value than it did during training.<br>- **C is Incorrect:** Recalculating parameters daily also changes the mapping over time and introduces skew.<br>- **D is Incorrect:** Switching to Min-Max Normalization for inference when Standardization was used for training will completely break the model's expected input distribution.<br><br>> **Key Takeaway:** A scaling transform fitted on training data must be applied, not refitted, on data seen during inference to prevent training-serving skew.</details> |

Applying standardization to highly skewed data first can result in poorly scaled values due to the skewed mean.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** You cannot apply a log transformation *after* standardization because standardization creates negative values, and the logarithm of a negative number is undefined.<br>- **C is Incorrect:** Normalization and binning do not address the requirement for a mean of 0 and standard deviation of 1.<br>- **D is Incorrect:** Binning converts continuous data to categorical data, at which point a log transformation is meaningless.<br><br>> **Key Takeaway:** When a dataset is both skewed and needs to be standardized, apply the log transformation first to handle the skewness, then apply the standard scaling.</details> |
| **### Question 8 - Robust Scaling for Outlier-Heavy Data**<br><br>An industrial IoT team is processing sensor data in AWS Glue DataBrew. The dataset contains a `temperature_reading` feature that occasionally records extreme, erroneous spikes (outliers) due to sensor malfunctions. These outliers are severely distorting the mean and standard deviation of the dataset. The team needs a scaling method that is resilient to these outliers for a regression model.<br><br>Which feature engineering technique should the team use?<br><br>- **A)** Apply Standardization (Z-score scaling).<br>- **B)** Apply Min-Max Normalization.<br>- **C)** Apply Robust Scaling.<br>- **D)** Apply Feature Splitting. | <details><summary><b>Correct Answer & Explanation</b></summary><br>**Correct Answer:** **C**<br><br>**Correct Answer Analysis:**<br>Robust Scaling uses the median and the interquartile range (IQR) to scale the data. Because the median and IQR are not heavily influenced by extreme outliers (unlike the mean and standard deviation), this method is highly effective for datasets containing severe outliers.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** Standardization relies on the mean and standard deviation, both of which are highly sensitive to extreme outliers.<br>- **B is Incorrect:** Min-Max Normalization scales data based on the minimum and maximum values. Extreme outliers will stretch the scale, compressing all normal data into a tiny range.<br>- **D is Incorrect:** Feature splitting is for breaking down compound strings, not for handling numerical outliers.<br><br>> **Key Takeaway:** Robust Scaling (using median and IQR) is the best feature engineering technique for datasets where extreme outliers would distort standard mean-based scaling.</details> |

| **### Question 10 - Handling Non-Uniform Distributions with Binning**<br><br>A healthcare provider is preparing patient data for a predictive model. They want to group patients into 4 equal-sized tiers based on their `annual_visits` count. However, the distribution of visits is highly non-uniform (most patients have 0-2 visits, but a few have many). They need to ensure each bin contains an approximately equal number of patients. For a highly non-uniform distribution, this would result in the first bin containing 99% of the data and the remaining bins being nearly empty.<br>- **C is Incorrect:** Standardizing the data does not change the underlying frequency distribution; applying equal-width binning afterward would still result in uneven bin populations.<br>- **D is Incorrect:** Similar to C, normalizing the data does not fix the non-uniform distribution issue for equal-width binning.<br><br>> **Key Takeaway:** Use quantile (equal-frequency) binning when you need to group a non-uniformly distributed continuous variable into bins that each contain a roughly equal number of samples.</details> |
