| **### Question 1 - Oscillating Training Loss in XGBoost**<br><br>An ML engineering team is training a complex XGBoost model on a large tabular dataset using **Amazon SageMaker AI**. The training job is running successfully, but the team notices in Amazon CloudWatch that the training loss oscillates wildly across epochs and never settles. The team must debug this convergence issue with the **least operational overhead**.<br><br>Which action should the team take to identify and resolve the issue?<br><br>- **A)** Decrease the learning rate (`eta`) hyperparameter to prevent the optimizer from overshooting the local minima.<br>- **B)** Increase the number of training instances to distribute the workload and stabilize the gradient updates.<br>- **C)** Change the evaluation metric from RMSE to MAE to smooth out the loss reporting in CloudWatch.<br>- **D)** Enable Amazon SageMaker Model Monitor on the training endpoint to detect data drift and retrain the model. | **Correct Answer:** **A**<br><br>**Correct Option Analysis:**<br>- **A is Correct:** Oscillating or unstable loss curves during gradient descent typically indicate that the learning rate is set too high. The optimizer's weight updates repeatedly overshoot the local loss minimum, causing the objective function to bounce back and forth. Decreasing the learning rate (or applying learning rate decay) stabilizes the optimization and allows the loss to converge.<br><br>**Distractor Analysis:**<br>- **B is Incorrect:** Increasing the number of instances impacts distributed training throughput and communication overhead, but it does not fundamentally fix an overly aggressive learning rate.<br>- **C is Incorrect:** Changing the evaluation metric (e.g., from RMSE to MAE) only alters how the error is reported to CloudWatch; it does not change the underlying mathematical optimization process or fix the convergence issue.<br>- **D is Incorrect:** SageMaker Model Monitor is used to monitor deployed endpoints for data drift and model quality, not for debugging training job convergence issues.<br><br>> **Exam Tip / AWS Best Practice:** If a loss curve oscillates and fails to settle, the learning rate is the first hyperparameter to examine and reduce. |
