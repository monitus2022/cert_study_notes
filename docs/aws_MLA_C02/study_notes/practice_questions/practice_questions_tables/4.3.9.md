| **### Question 1 - Amazon Bedrock Guardrails Contextual Grounding**<br><br>An enterprise is deploying an internal HR assistant using **Amazon Bedrock**. The assistant retrieves employee handbook documents to answer user queries. The compliance team mandates that the assistant must not generate answers that are not directly supported by the retrieved documents, to prevent hallucinations and ensure accurate policy representation. The solution must minimize operational overhead and use native AWS services.<br><br>Which **ONE** Amazon Bedrock Guardrails feature should the ML engineer configure to meet this requirement?<br><br>- **A)** Denied Topics<br>- **B)** Contextual Grounding Check<br>- **C)** Content Filters<br>- **D)** Sensitive Information Filters | **Correct Answer:** **B**<br><br>**Correct Answer Analysis:**<br>- **B is Correct:** Contextual Grounding Check in Amazon Bedrock Guardrails evaluates whether the model's response is factually supported by the reference text (retrieved passages) provided in the prompt context. If the response is not grounded in the source material, the guardrail blocks or flags it, effectively mitigating hallucinations.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** Denied Topics are used to block conversations about specific predefined subjects (e.g., investment advice or medical diagnoses), not to verify factual alignment with retrieved documents.<br>- **C is Incorrect:** Content Filters are designed to block harmful, hateful, or toxic content based on severity categories, not to check for hallucination or grounding.<br>- **D is Incorrect:** Sensitive Information Filters detect, mask, or block PII (Personally Identifiable Information) in the input or output, which is unrelated to verifying if a response is supported by the source text.<br><br>> **Exam Tip:** Use Contextual Grounding checks for RAG applications to prevent hallucinations by ensuring responses are supported by retrieved source passages. |
| **### Question 2 - Masking PII in Model Responses**<br><br>A healthcare company is building an AI chatbot using **Amazon Bedrock** to answer general patient support queries. The security team mandates that any personally identifiable information (PII), such as Social Security numbers or patient IDs, generated in the model's response must be redacted before being displayed to the user. The solution must use Amazon Bedrock Guardrails and minimize configuration complexity.<br><br>Which **ONE** configuration meets this requirement with the least operational overhead?<br><br>- **A)** Configure a Sensitive Information Filter and set the action to Mask.<br>- **B)** Configure a Word Filter with a custom list of all possible patient IDs.<br>- **C)** Configure a Denied Topic for "Patient Information".<br>- **D)** Configure an Automated Reasoning check to validate PII rules. | **Correct Answer:** **A**<br><br>**Correct Answer Analysis:**<br>- **A is Correct:** Sensitive Information Filters in Amazon Bedrock Guardrails natively detect PII (like SSNs, phone numbers, or custom regex patterns) and can be configured to **Mask** the detected sensitive data in the model response before it reaches the user.<br><br>**Distractor Analysis:**<br>- **B is Incorrect:** Word Filters are designed to block specific words or profanity. Maintaining a list of all possible patient IDs is unscalable and operationally heavy compared to using native PII detection.<br>- **C is Incorrect:** Denied Topics would block the entire conversation about a subject, not specifically redact or mask PII within a valid response.<br>- **D is Incorrect:** Automated Reasoning checks validate logical consistency against formal rules, not detect and mask PII entities.<br><br>> **Exam Tip:** Use Sensitive Information Filters with the "Mask" action to redact PII in model outputs without blocking the entire response. |
| **### Question 3 - Blocking Specific Subject Matter**<br><br>A financial services firm is using a foundation model via **Amazon Bedrock** to summarize market news. Due to strict regulatory compliance, the foundation model must absolutely refuse to provide any form of investment advice or specific stock recommendations to users. The firm wants to implement this using the most appropriate Amazon Bedrock Guardrails feature.<br><br>Which **ONE** feature should the firm configure to enforce this rule?<br><br>- **A)** Contextual Grounding Check<br>- **B)** Sensitive Information Filter<br>- **C)** Denied Topics<br>- **D)** Content Filters | **Correct Answer:** **C**<br><br>**Correct Answer Analysis:**<br>- **C is Correct:** Denied Topics in Amazon Bedrock Guardrails allow administrators to define specific subjects that the model must refuse to discuss. Configuring "Investment Advice" as a denied topic ensures the guardrail blocks any prompt or response attempting to solicit or provide such advice.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** Contextual Grounding checks ensure responses are supported by source text; they do not explicitly block entire subject domains like investment advice.<br>- **B is Incorrect:** Sensitive Information Filters are for PII redaction, not for blocking thematic content or advice.<br>- **D is Incorrect:** Content Filters block harmful/hateful/sexual content based on severity, not specific financial advice topics.<br><br>> **Exam Tip:** Use Denied Topics to prevent the model from engaging in specific, predefined subject matters that violate business policy. |
| **### Question 4 - Implementing Automated Reasoning Checks**<br><br>An AI application processes user queries about company expense reimbursement policies. Which **ONE** Amazon Bedrock Guardrails feature should be used?<br><br>- **A)** Automated Reasoning checks<br>- **B)** Contextual Grounding checks<br>- **C)** Word filters<br>- **D)** Sensitive Information filters | **Correct Answer:** **A**<br><br>**Correct Answer Analysis:**<br>- **A is Correct:** Automated Reasoning checks in Amazon Bedrock Guardrails use formal mathematical logic to validate whether the model's response is consistent with explicitly stated rules and policies provided by the administrator.<br><br>**Distractor Analysis:**<br>- **B is Incorrect:** Contextual Grounding checks evaluate if a response is supported by retrieved text passages, not if it adheres to formal logical constraints like expense thresholds.<br>- **C is Incorrect:** Word filters simply block or mask specific terms; they cannot evaluate logical conditions or policy rules.<br>- **D is Incorrect:** Sensitive Information filters are strictly for identifying and masking PII, not for enforcing business logic.<br><br>> **Exam Tip:** Use Automated Reasoning checks to validate model outputs against strict logical or business rules (e.g., corporate policies). |
| **### Question 5 - Applying Guardrails to Third-Party Models**<br><br>An AI engineering team wants to evaluate user prompts and model responses for harmful content and PII, but they are using a self-hosted open-source model outside of the Amazon Bedrock platform. The team wants to utilize Amazon Bedrock Guardrails to perform this evaluation without building and managing custom content filtering models. Which **ONE** approach should the ML engineer take?<br><br>- **A)** Migrate the model to Amazon SageMaker JumpStart and use AWS Lambda to intercept calls.<br>- **B)** Use the `ApplyGuardrail` API to evaluate the prompts and responses independently.<br>- **C)** Configure a VPC Interface Endpoint to route traffic through Bedrock Guardrails.<br>- **D)** Enable AWS CloudTrail data events to inspect the payloads for PII.<br>- **E)** Use Amazon Comprehend to detect PII and Amazon Macie to detect harmful content. | **Correct Answer:** **B**<br><br>**Correct Answer Analysis:**<br>- **B is Correct:** The `ApplyGuardrail` API in Amazon Bedrock allows developers to evaluate prompts and model responses from any source (including models hosted outside of Bedrock, or custom models) using Bedrock Guardrails. This decouples the guardrail evaluation from the model invocation, providing a flexible, low-operational-overhead solution.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** Migrating the model to SageMaker and writing custom Lambda interceptors introduces unnecessary operational overhead and does not directly leverage the native Bedrock Guardrails API.<br>- **C is Incorrect:** VPC Interface Endpoints are for network routing and privacy, not for content inspection or applying safety guardrails.<br>- **D is Incorrect:** AWS CloudTrail is used for auditing API calls, not for real-time content evaluation or PII redaction.<br>- **E is Incorrect:** While Amazon Comprehend can detect PII, stitching together multiple services for guardrail duties (PII + harmful content) is far more complex and operationally heavy than using the native `ApplyGuardrail` API.<br><br>> **Exam Tip:** The `ApplyGuardrail` API allows you to use Bedrock Guardrails on models hosted outside of Amazon Bedrock, decoupling safeguards from model execution. |
| **### Question 6 - Protecting Sensitive Data in Logs**<br><br>An enterprise has implemented an **Amazon Bedrock Guardrail** with a Sensitive Information Filter configured to mask PII in model responses. However, the security team notices that unmasked PII is still appearing in the application's Amazon CloudWatch logs. The application uses the `InvokeModel` API with the guardrail configured. Which **ONE** action should the ML engineer take to ensure PII is masked throughout the logging path?<br><br>- **A)** Configure AWS Config rules to automatically redact PII from CloudWatch logs.<br>- **B)** Enable AWS CloudTrail data events for the Bedrock API calls.<br>- **C)** Ensure the application logs the final Guardrail-processed output rather than the raw model output.<br>- **D)** Apply a separate Denied Topic guardrail specifically for the logging component. | **Correct Answer:** **C**<br><br>**Correct Answer Analysis:**<br>- **C is Correct:** When a guardrail is applied, it processes the response and returns the masked version to the caller. If the application code is logging the raw output (or an intermediate step) before the guardrail is applied, or if it logs the raw user prompt instead of the processed prompt, unmasked PII will appear. The engineer must update the application logic to log only the final, guardrail-processed text.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** AWS Config evaluates resource configurations, not real-time data payloads within CloudWatch logs.<br>- **B is Incorrect:** CloudTrail logs API metadata, not the actual payload content, so it won't contain the PII response body anyway, and it doesn't fix the application's logging behavior.<br>- **D is Incorrect:** Denied Topics block specific subjects; they do not address how the application logs data.<br><br>> **Exam Tip:** Guardrails protect the data returned to the user, but application logging behavior must also be designed to log the *post-guardrail* payload, not the raw model output. |

This feature directly intercepts and blocks or masks the specified terms in both the user input and the model output.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** Content Filters block harmful content based on broad categories (e.g., hate, violence, sexual) and severity thresholds, not specific custom words like competitor names.<br>- **B is Incorrect:** Denied Topics are for blocking entire subject matters, not individual words or terms.<br>- **D is Incorrect:** Sensitive Information Filters are designed for PII like SSNs and credit card numbers, not custom competitive terms.<br><br>> **Exam Tip:** Use Word Filters to block or mask specific terms, including profanity and custom organizational terms (e.g., competitor names). |

| **### Question 9 - Contextual Grounding Thresholds**<br><br>An AI engineering team is building a Retrieval-Augmented Generation (RAG) application. They want to use **Amazon Bedrock Guardrails** to ensure the model's responses are grounded in the retrieved documents. They configure a Contextual Grounding check with a threshold of 0.65. During testing, they find that the model is still returning some hallucinated responses that are barely grounded in the source text. Which **ONE** action should they take to make the guardrail more strict and block these hallucinations?<br><br>- **A)** Decrease the threshold to 0.50.<br>- **B)** Increase the threshold to 0.85.<br>- **C)** Change the action from Block to Mask.<br>- **D)** Apply the guardrail only to the prompt, not the response. | **Correct Answer:** **B**<br><br>**Correct Answer Analysis:**<br>- **B is Correct:** The Contextual Grounding threshold determines the minimum confidence score required for a response to be considered "grounded." A higher threshold (e.g., 0.85) requires a higher degree of grounding in the source text, making the guardrail stricter and more likely to block barely-grounded hallucinated responses.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** Decreasing the threshold makes the guardrail *less* strict, allowing more borderline or ungrounded responses to pass through.<br>- **C is Incorrect:** Contextual Grounding checks evaluate factual support, and "Mask" is not an applicable action for grounding (masking is for PII). The action should be to block the response.<br>- **D is Incorrect:** Hallucinations occur in the model's response, not the prompt. Applying the check only to the prompt would fail to catch hallucinated outputs.<br><br>> **Exam Tip:** To prevent hallucinations more strictly with Contextual Grounding checks, *increase* the threshold score to require a higher degree of factual alignment. |
