| **### Question 1 - Bedrock Agents Native Session Management**<br><br>A retail company is deploying an Amazon Bedrock Agent to handle customer service inquiries. The agent must maintain dialogue context within a single ongoing conversation so that a user can ask follow-up questions without repeating themselves. The ML engineering team wants the solution with the least operational overhead.<br><br>Which approach should the team use to manage this short-term state? (Select ONE)<br><br>- **A)** Pass a unique `sessionId` parameter in the `InvokeAgent` API request for each turn of the same conversation.<br>- **B)** Store the entire conversation history in an Amazon S3 bucket and prepend it to the prompt on each invocation.<br>- **C)** Use a custom AWS Lambda function to save conversation history to a PostgreSQL database and query it before each invocation.<br>- **D)** Configure an Amazon DynamoDB table to store session state and manually inject the history into the agent's prompt template. | **Correct Answer:** **A**<br><br>**Correct Option Analysis:**<br>- **A is Correct:** Amazon Bedrock Agents natively supports short-term session memory.
