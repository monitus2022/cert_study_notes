(Select ONE)<br><br>- **A)** Create an AWS Lambda function triggered by CloudWatch Events that periodically samples endpoint traffic and computes the Kolmogorov-Smirnov statistic manually.<br>- **B)** Enable **Amazon SageMaker Model Monitor** with a baseline constraint file generated from a stable training dataset, and configure CloudWatch Alarms for violations.<br>- **C)** Use AWS Glue Data Quality rules to inspect the training dataset and manually compare it to production logs on a weekly basis.<br>- **D)** Rely on CloudWatch Anomaly Detection on the `Invocations` metric to detect changes in traffic volume. | **Correct Answer:** **B**<br><br>**Correct Answer Analysis:**<br>- **B is Correct:** Amazon SageMaker Model Monitor automatically captures baseline statistics and constraints from a training dataset, continuously monitors live endpoint traffic, and emits metrics to CloudWatch when data drift is detected. | **### Question 3 - Concept Drift vs. Data Drift**<br><br>An enterprise's customer support assistant receives prompts that are statistically close to the recorded training baseline. However, the business notices a steady decline in user satisfaction scores because user expectations of what constitutes a "helpful" response have evolved, and the previous correct answers are no longer preferred.<br><br>Constraint: The team must accurately classify this degradation to choose the correct remediation strategy.<br><br>Which condition is the application experiencing? (Select ONE)<br><br>- **A)** Data drift<br>- **B)** Concept drift<br>- **C)** Model throttling<br>- **D)** Tool invocation failure | **Correct Answer:** **B**<br><br>**Correct Answer Analysis:**<br>- **B is Correct:** Concept drift occurs when the relationship between the input and the expected output ($P(Y|X)$) changes, even if the input distribution ($P(X)$) remains the same. The prompts are unchanged, but what users consider an acceptable answer has shifted.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** Data drift (covariate shift) occurs when the input distribution ($P(X)$) changes. In this scenario, the prompts are statistically similar to the baseline.<br>- **C is Incorrect:** Model throttling results in HTTP 429 errors and dropped requests, not a decline in the quality or acceptance of completed responses.<br>- **D is Incorrect:** Tool invocation failures result in explicit runtime errors or fallback messages, not a gradual shift in user satisfaction regarding valid outputs.<br><br>> **Exam Tip / AWS Best Practice:** Data drift is a shift in inputs ($P(X)$), while concept drift is a shift in the expected output for the same inputs ($P(Y|X)$). |
| **### Question 4 - Amazon Bedrock Model Evaluation (Automatic vs. Human)**<br><br>A data science team needs to evaluate a newly fine-tuned foundation model before deploying it to production. They want to assess the model on correctness, toxicity, and factual accuracy. The team requires immediate results and explicitly states they have no budget or time to hire human reviewers for this iteration.<br><br>Constraint: The solution must use **Amazon Bedrock Model Evaluation** with the **fastest turnaround time** and **no human reviewers**.<br><br>Which evaluation method should they use? (Select ONE)<br><br>- **A)** Bedrock Model Evaluation - Human<br>- **B)** Bedrock Model Evaluation - Automatic<br>- **C)** Bedrock Guardrails content filtering<br>- **D)** CloudWatch generative AI observability metric analysis | **Correct Answer:** **B**<br><br>**Correct Answer Analysis:**<br>- **B is Correct:** Amazon Bedrock Model Evaluation Automatic jobs use an LLM-as-a-judge (judge model) to score model responses on metrics like correctness, toxicity, and factual accuracy. This provides fast, automated results without the need for human reviewers.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** Human evaluation jobs require sending prompts and responses to human reviewers, which takes significant time and budget, violating the constraints.<br>- **C is Incorrect:** Bedrock Guardrails are used at inference time to block harmful content; they do not evaluate model correctness or accuracy across an evaluation dataset.<br>- **D is Incorrect:** CloudWatch GenAI observability tracks operational telemetry (latency, token usage) but does not perform semantic evaluation of response quality or accuracy.<br><br>> **Exam Tip / AWS Best Practice:** Use Bedrock Automatic Model Evaluation (LLM-as-a-judge) for rapid, code-free assessment of model quality, and Human Evaluation for nuanced, subjective human-in-the-loop scoring. |
| **### Question 5 - A/B Testing with SageMaker Production Variants**<br><br>A machine learning team wants to introduce a new model version to live traffic. Both versions must be hosted on the same endpoint to simplify deployment and be evaluated on the same CloudWatch metrics.<br><br>Constraint: Use the **most cost-effective and native** SageMaker feature for traffic distribution.<br><br>Which configuration supports this requirement? (Select ONE)<br><br>- **A)** Create two separate SageMaker endpoints and use Amazon Route 53 weighted routing to distribute traffic.<br>- **B)** Deploy both models as production variants on a single SageMaker endpoint with a 1:9 weight ratio.<br>- **C)** Use a SageMaker Shadow variant with a 10% weight ratio.<br>- **D)** Implement an AWS Lambda function in front of the endpoint to randomly route 10% of traffic to the new model. | **Correct Answer:** **B**<br><br>**Correct Answer Analysis:**<br>- **B is Correct:** SageMaker Endpoints support multiple production variants. By assigning a weight of 1 to the new model and 9 to the existing model (a 1:9 ratio), SageMaker natively distributes 10% of the live traffic to the new variant, allowing direct comparison via CloudWatch metrics.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** Creating two separate endpoints and using Route 53 increases operational overhead and cost, and complicates metric aggregation compared to a single endpoint with variants.<br>- **C is Incorrect:** A Shadow variant receives a copy of the traffic, but its responses are not returned to the user. The requirement is to serve 10% of live requests to users, not to test in shadow mode.<br>- **D is Incorrect:** Using a Lambda function for routing introduces unnecessary custom code, latency, and operational overhead.<br><br>> **Exam Tip / AWS Best Practice:** Use SageMaker Production Variants with assigned weights for native A/B testing on a single endpoint, simplifying metric comparison and deployment. |

| **### Question 7 - Pipeline Anomaly Detection (Checking Output vs. Completion)**<br><br>A daily scheduled AWS Glue ETL job processes feature data and writes it to Amazon S3 for a SageMaker endpoint to use for batch inference. The job reports success, but model invocation errors spike immediately afterward. The ML engineer discovers that the Glue job outputted empty partitions due to an upstream API change.<br><br>Constraint: Identify the **monitoring gap** that allowed this to happen.<br><br>Which monitoring gap does this pattern reveal? (Select ONE)<br><br>- **A)** The endpoint has too few production variants for the traffic volume.<br>- **B)** The pipeline monitors job completion status without checking the output data quality.<br>- **C)** The account has no cost allocation tags applied to the SageMaker workload.<br>- **D)** The model was evaluated by an LLM-as-a-judge rather than human reviewers. | **Correct Answer:** **B**<br><br>**Correct Answer Analysis:**<br>- **B is Correct:** The Glue job completed with a success exit code but produced empty partitions. Monitoring only checked job completion status rather than validating the actual output data quality (e.g., verifying record counts, schema integrity, or null constraints), leading to downstream inference failures.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** The number of production variants affects traffic distribution, not data-driven invocation failures caused by empty partitions.<br>- **C is Incorrect:** Cost allocation tags are used for financial tracking and have no impact on runtime functionality or data quality.<br>- **D is Incorrect:** The evaluation method (LLM-as-a-judge vs. human) pertains to model quality assessment, not runtime failures caused by malformed or empty data inputs.<br><br>> **Exam Tip / AWS Best Practice:** Monitoring a pipeline must include data quality checks on the *output* of a job, not just the job's exit status, to prevent silent handoff failures. |

| **### Question 10 - Distance Metrics for High-Dimensional Drift**<br><br>An ML engineer is configuring **Amazon SageMaker Model Monitor** to detect data drift on a tabular dataset. The dataset contains a mix of categorical and numerical features. The engineer wants to use the default statistical tools provided by Model Monitor to establish the baseline and detect drift.<br><br>Constraint: Rely on **default SageMaker Model Monitor** capabilities to minimize operational overhead.<br><br>Which statistical tests does Model Monitor natively use by default to compare the baseline and current distributions? (Select TWO)<br><br>- **A)** Kolmogorov-Smirnov (K-S) test for numerical features.<br>- **B)** Chi-Squared test for categorical features.<br>- **C)** Wasserstein distance for high-dimensional embeddings.<br>- **D)** Population Stability Index (PSI) for all features. | **Correct Answers:** **A** and **B**<br><br>**Correct Answer Analysis:**<br>- **A is Correct:** By default, SageMaker Model Monitor uses the Kolmogorov-Smirnov (K-S) test to compare the distributions of numerical features between the baseline and current datasets.<br>- **B is Correct:** For categorical features, Model Monitor natively uses the Chi-Squared test to determine if the distribution of categories has shifted from the baseline.<br><br>**Distractor Analysis:**<br>- **C is Incorrect:** While Wasserstein distance is a valid metric for high-dimensional spaces like embeddings, it is not the default metric used out-of-the-box by SageMaker Model Monitor for standard tabular data.<br>- **D is Incorrect:** Population Stability Index (PSI) is a common drift metric in finance and industry, but SageMaker Model Monitor defaults to K-S and Chi-Squared, not PSI, for its built-in constraints.<br><br>> **Exam Tip / AWS Best Practice:** SageMaker Model Monitor handles tabular data drift out-of-the-box using the K-S test for numerical data and the Chi-Squared test for categorical data. | |
