| **### Question 1 - Semantic Chunking for Technical Manuals**<br><br>An AI team is building a RAG application to answer employee questions using a corpus of long, highly technical engineering manuals. The team is using **Amazon Bedrock Knowledge Bases** with an Amazon OpenSearch Serverless vector store. They need to ensure that chunking maintains the semantic boundaries of the text, such as keeping section headers with their corresponding paragraphs, rather than arbitrarily cutting text mid-sentence. It groups related sentences and paragraphs together, ensuring that a section header remains with its corresponding text block, which is ideal for maintaining context in technical manuals without writing custom parsing logic.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** Fixed-size chunking arbitrarily splits text based on a predefined token count, which will still cut mid-sentence or separate headers from their paragraphs regardless of the small chunk size or overlap.<br>- **C is Incorrect:** While hierarchical chunking provides parent-child relationships for broader context retrieval, it does not inherently prevent arbitrary mid-sentence splitting at the child level unless paired with semantic boundaries.<br>- **D is Incorrect:** "No chunking" treats the entire manual as a single chunk, which will likely exceed the embedding model's maximum input token limit and severely dilute the semantic accuracy of the vector representation.<br><br>> **Exam Tip / AWS Best Practice:** When document structure and semantic boundaries are more important than strict token limits, use **semantic chunking** in Amazon Bedrock Knowledge Bases to preserve contextual meaning. |
