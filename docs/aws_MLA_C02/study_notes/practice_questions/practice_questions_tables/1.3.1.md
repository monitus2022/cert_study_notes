| **### Question 1 - Declarative Data Quality Rules in AWS Glue**<br><br>An enterprise machine learning team is preparing a customer demographics dataset stored in Amazon S3 and cataloged in the AWS Glue Data Catalog. The compliance team requires that explicit, repeatable data quality rules—such as ensuring the `customer_id` column is 100% complete and the `age` column is strictly between 18 and 100—are evaluated automatically on every pipeline run.<br><br>The team must implement this validation with the **least operational overhead** and without writing custom evaluation scripts.<br><br>Which **ONE** approach satisfies these requirements? (Select ONE)<br><br>- **A)** Create an AWS Lambda function triggered by S3 events to parse the data and validate the completeness and age ranges using Python Pandas.<br>- **B)** Author a ruleset using the Data Quality Definition Language (DQDL) and use AWS Glue Data Quality to evaluate it against the Data Catalog table.<br>- **C)** Use Amazon SageMaker Data Wrangler to interactively profile the dataset and manually verify that ages fall within the required range.<br>- **D)** Create an AWS Glue DataBrew profile job to run on the dataset, which will automatically infer anomalies and missing values based on statistical distributions. | **Correct Answer:** **B**<br><br>**Correct Answer Analysis:**<br>- **B is Correct:** AWS Glue Data Quality uses the Data Quality Definition Language (DQDL) to define explicit, declarative rules (e.g., `Completeness "customer_id" = 1.0`, `ColumnValues "age" between 18 and 100`). These rulesets can be evaluated automatically against datasets in the AWS Glue Data Catalog on every pipeline run, enforcing strict validation with minimal operational overhead.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** Writing a custom Lambda function with Pandas introduces unnecessary operational overhead, requires infrastructure management, and does not natively integrate with Glue Data Catalog declarative rules.<br>- **C is Incorrect:** Amazon SageMaker Data Wrangler is an interactive tool for visual data preparation and transformation, not an automated, repeatable ruleset evaluation engine for pipeline gates.<br>- **D is Incorrect:** AWS Glue DataBrew profiling generates statistical summaries and infers anomalies, but it does not enforce strict, explicit declarative rules (like exactly 100% completeness and specific value bounds) in the way DQDL does.<br><br>> **Key Takeaway:** Use AWS Glue Data Quality with DQDL when you need to enforce explicit, declarative data validation rules automatically within your data pipelines. |
| **### Question 2 - Surface Data Defects Before Cleaning**<br><br>A retail company is ingesting daily transaction logs into Amazon S3 as CSV files. The data science team needs to understand the current state of the data—specifically identifying missing values, inconsistent date formats, and unexpected ranges in numeric columns—*before* deciding on a specific cleaning strategy.<br><br>The solution must minimize infrastructure management and provide built-in visualizations of the dataset's characteristics.<br><br>Which **ONE** AWS service should the team use to profile the dataset? (Select ONE)<br><br>- **A)** AWS Glue Data Quality<br>- **B)** AWS Glue DataBrew<br>- **C)** Amazon SageMaker Ground Truth<br>- **D)** AWS Lambda with Amazon Macie | **Correct Answer:** **B**<br><br>**Correct Answer Analysis:**<br>- **B is Correct:** AWS Glue DataBrew is a visual data preparation tool that allows users to run profile jobs on datasets. A DataBrew profile job measures the dataset and generates statistics, surfacing missing values, duplicate rows, outlier information, and inconsistent formats. This allows the team to see the defects before choosing a repair approach.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** AWS Glue Data Quality evaluates datasets against pre-defined declarative rules (DQDL). While it can generate a recommended ruleset, its primary purpose is rule enforcement, not open-ended statistical profiling to discover unknown data defects.<br>- **C is Incorrect:** Amazon SageMaker Ground Truth is used for data labeling and human review workflows, not for profiling data quality or identifying missing values.<br>- **D is Incorrect:** AWS Lambda is a serverless compute service, and Amazon Macie is a data security service for discovering sensitive data (PII). Neither provides statistical dataset profiling.<br><br>> **Key Takeaway:** Profiling comes before cleaning; use AWS Glue DataBrew to statistically profile datasets and discover unknown anomalies, missing values, and format inconsistencies. |

The raw dataset contains extreme outliers in the `transaction_amount` column and suffers from severe class imbalance, where fraudulent transactions represent less than 1% of the data. (Select ONE)<br><br>- **A)** AWS Glue DataBrew<br>- **B)** AWS Glue Data Quality<br>- **C)** Amazon SageMaker Data Wrangler<br>- **D)** Amazon SageMaker Ground Truth | **Correct Answer:** **C**<br><br>**Correct Answer Analysis:**<br>- **C is Correct:** Amazon SageMaker Data Wrangler is designed for interactive data preparation and feature engineering. It contains built-in transformations for detecting and handling outliers, as well as tools for resolving class imbalance (like SMOTE). The engineer can apply these transforms and immediately visualize the effect on the distribution.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** While AWS Glue DataBrew has visual data preparation capabilities, SageMaker Data Wrangler is purpose-built for ML workflows, offering native, interactive ML-specific transforms like SMOTE for class imbalance directly within the ML studio environment.<br>- **B is Incorrect:** AWS Glue Data Quality enforces declarative rules but does not provide an interactive UI for experimenting with ML-specific data augmentation or class imbalance resolution.<br>- **D is Incorrect:** SageMaker Ground Truth is for data labeling, not for transforming data or resolving class imbalance.<br><br>> **Key Takeaway:** For interactive ML-specific data transformations—like outlier handling and class imbalance resolution—SageMaker Data Wrangler provides the most purpose-built environment with immediate visual feedback. |
| **### Question 4 - Stopping Pipelines on Quality Failures**<br><br>A financial services company uses AWS Step Functions to orchestrate a complex ETL pipeline before model training. The data is cataloged in the AWS Glue Data Catalog. The team needs to ensure that if a dataset fails specific data quality rules (e.g., a required column has more than 5% missing values), the Step Functions pipeline immediately halts to prevent corrupt data from reaching the model training phase.<br><br>Which **ONE** approach achieves this with the **least operational overhead**? (Select ONE)<br><br>- **A)** Use AWS Glue DataBrew to profile the data and output a CloudWatch metric. Create a CloudWatch Alarm that triggers a Lambda function to stop the Step Function execution.<br>- **B)** Author an AWS Glue Data Quality ruleset in DQDL and attach it to the AWS Glue Data Catalog table. Configure the Step Functions pipeline to evaluate the ruleset and halt if the evaluation fails.<br>- **C)** Write a custom AWS Glue PySpark job that counts null values and throws an exception if the threshold is exceeded.<br>- **D)** Use Amazon Macie to scan the S3 bucket for data quality issues and block the training job if issues are detected. | **Correct Answer:** **B**<br><br>**Correct Answer Analysis:**<br>- **B is Correct:** AWS Glue Data Quality integrates natively with the AWS Glue Data Catalog. You can define a DQDL ruleset (e.g., `Completeness "column_name" > 0.95`) and evaluate it. The evaluation results can be used by orchestrators like Step Functions to branch or halt the pipeline, providing a low-overhead, declarative gating mechanism.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** Using DataBrew profiling to output metrics, setting up CloudWatch Alarms, and invoking Lambda introduces unnecessary architectural complexity and operational overhead compared to native Glue Data Quality integration.<br>- **C is Incorrect:** Writing a custom PySpark job requires development and maintenance effort, violating the least operational overhead constraint.<br>- **D is Incorrect:** Amazon Macie is a security service for discovering and protecting sensitive data (PII), not for enforcing general data quality rules like column completeness.<br><br>> **Key Takeaway:** AWS Glue Data Quality acts as a pipeline gate; its declarative rule evaluations can be used by orchestrators like Step Functions to halt pipelines automatically on failure. |

The engineer can then review, modify, and adopt these rules for ongoing validation.<br><br>**Distractor Analysis:**<br>- **B is Incorrect:** Amazon SageMaker Feature Store is used for storing, retrieving, and managing ML features, not for generating or recommending data quality rules.<br>- **C is Incorrect:** AWS Lambda is a compute service. While you could write custom code to analyze data, it does not natively recommend DQDL rules.<br>- **D is Incorrect:** Amazon Comprehend is an NLP service used for extracting insights from text, not for evaluating tabular data quality rules.<br><br>> **Key Takeaway:** AWS Glue Data Quality can automatically recommend a starting DQDL ruleset based on a dataset in the AWS Glue Data Catalog, accelerating data quality setup. |
| **### Question 6 - Automating Profiling on a Schedule**<br><br>A healthcare analytics team receives new patient treatment records in an Amazon S3 bucket every week. | **### Question 7 - Validating Unique Constraints**<br><br>An e-commerce platform ingests daily order data into an AWS Glue Data Catalog table. The ML team needs to ensure that the `order_id` column is completely unique, and that the `order_status` column only contains one of four predefined values ('PENDING', 'SHIPPED', 'DELIVERED', 'CANCELLED'). If these rules fail, the data must be quarantined.<br><br>Which **ONE** approach implements this validation declaratively? (Select ONE)<br><br>- **A)** Write an AWS Glue DataBrew recipe with custom transformations to filter out duplicate `order_id`s and invalid statuses.<br>- **B)** Use AWS Glue Data Quality to define a ruleset utilizing `Uniqueness` and `AllowedValues` rules in the DQDL.<br>- **C)** Create a custom PySpark script in an AWS Glue Spark job to perform `dropDuplicates()` and `filter()` operations.<br>- **D)** Train a SageMaker model to classify valid versus invalid orders based on historical data. | **Correct Answer:** **B**<br><br>**Correct Answer Analysis:**<br>- **B is Correct:** AWS Glue Data Quality's Data Quality Definition Language (DQDL) natively supports rules like `Uniqueness "order_id" = 1.0` and `AllowedValues "order_status" in ['PENDING', 'SHIPPED', 'DELIVERED', 'CANCELLED']`. This declarative approach cleanly enforces the constraints without custom code.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** DataBrew recipes are for transforming and cleaning data, not for declaratively validating rules to gate a pipeline. While it can filter data, it doesn't natively "validate" in the same declarative pipeline-gating way.<br>- **C is Incorrect:** Writing a custom PySpark script introduces unnecessary code maintenance and operational overhead compared to a declarative DQDL ruleset.<br>- **D is Incorrect:** Training an ML model is unnecessary overkill for simple rule-based validation of distinct and enumerated values.<br><br>> **Key Takeaway:** DQDL provides specific rule types like `Uniqueness` and `AllowedValues` to declaratively validate column constraints in AWS Glue Data Quality. |

(Select ONE)<br><br>- **A)** AWS Glue Data Quality<br>- **B)** AWS Glue DataBrew<br>- **C)** Amazon Macie<br>- **D)** AWS Glue Data Catalog | **Correct Answer:** **B**<br><br>**Correct Answer Analysis:**<br>- **B is Correct:** AWS Glue DataBrew provides built-in transforms for data cleaning, including deduplication. In the interactive DataBrew project UI, engineers can identify duplicate or near-duplicate rows and use the "Remove duplicate rows" transform, configuring it to keep the first or last occurrence based on specific columns (like the review text).<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** AWS Glue Data Quality can enforce a `Uniqueness` rule, but it evaluates and fails the dataset; it does not provide interactive visual transforms to *clean* or deduplicate the data.<br>- **C is Incorrect:** Amazon Macie is for security and PII discovery, not data deduplication.<br>- **D is Incorrect:** AWS Glue Data Catalog is a metadata repository, not a data transformation or cleaning tool.<br><br>> **Key Takeaway:** AWS Glue DataBrew excels at interactive data cleaning, offering built-in visual transforms like deduplication to repair dataset defects. |
| **### Question 9 - Monitoring Data Quality Job Metrics**<br><br>A company runs daily AWS Glue Data Quality evaluations on their feature datasets. The data engineering manager wants to set up an alert if a specific data quality rule—such as the completeness of the `email_address` column—drops below 90%, so they can take proactive action before the ML training pipeline runs.<br><br>Which **ONE** AWS service natively collects these Data Quality evaluation metrics for alerting? (Select ONE)<br><br>- **A)** Amazon CloudWatch<br>- **B)** AWS CloudTrail<br>- **C)** Amazon EventBridge<br>- **D)** AWS Security Hub | **Correct Answer:** **A**<br><br>**Correct Answer Analysis:**<br>- **A is Correct:** Amazon CloudWatch collects metrics and logs from the jobs that validate and clean data (including AWS Glue Data Quality and DataBrew jobs). The results of DQDL rule evaluations are published as CloudWatch metrics, allowing you to create CloudWatch Alarms to alert the team when rules fail or metrics drop below a threshold.<br><br>**Distractor Analysis:**<br>- **B is Incorrect:** AWS CloudTrail records API calls made in your account (who did what), but it does not collect metric data regarding the internal outcomes of data quality rules.<br>- **C is Incorrect:** Amazon EventBridge is used to route events (like a Glue job state change from RUNNING to FAILED), but the actual rule evaluation metrics (like completeness percentages) are collected by CloudWatch.<br>- **D is Incorrect:** AWS Security Hub is for security posture management, not data quality metric monitoring.<br><br>> **Key Takeaway:** Amazon CloudWatch natively collects metrics from AWS Glue Data Quality and DataBrew, enabling alerts when data quality thresholds are violated. |
