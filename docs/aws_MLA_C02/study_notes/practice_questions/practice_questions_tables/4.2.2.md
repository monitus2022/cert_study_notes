| **### Question 1 - Troubleshooting SageMaker Endpoint Latency**<br><br>A machine learning team has deployed a real-time inference endpoint on Amazon SageMaker AI. Users are reporting intermittent high latency, but the overall CPU utilization remains consistently low. The team needs to isolate whether the bottleneck is in the data pre-processing logic or the actual model inference execution with the least operational overhead.<br><br>Which tool should the team use to troubleshoot this issue? (Select ONE)<br><br>- **A)** Use Amazon CloudWatch Metrics to monitor the `CPUUtilization` of the endpoint.<br>- **B)** Enable AWS X-Ray tracing on the endpoint to capture execution segments for pre-processing and inference.<br>- **C)** Deploy an Amazon SageMaker Processing job to analyze the endpoint's network traffic.<br>- **D)** Use Amazon SageMaker Debugger to profile the latency of individual training loops.<br> | **Correct Answer:** **B**<br><br>**Correct Answer Analysis:**<br>- **B is Correct:** AWS X-Ray allows developers to instrument their application code to trace requests as they flow through different components. By defining custom sub-segments for data pre-processing and model inference, the team can precisely identify which step is causing the intermittent latency spikes, satisfying the requirement with minimal overhead.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** CloudWatch Metrics provides aggregate time-series data (like average CPU). Since CPU is already low, it won't isolate the specific code block causing the latency.<br>- **C is Incorrect:** SageMaker Processing is used for data preparation and ETL workloads, not for analyzing live network traffic of a real-time inference endpoint.<br>- **D is Incorrect:** SageMaker Debugger is designed to capture metrics and identify issues during the *training* phase (like gradient vanishing), not for real-time inference latency troubleshooting.<br><br>> **Exam Tip / AWS Best Practice:** Use AWS X-Ray to trace requests across components and identify the exact sub-segment causing latency bottlenecks, while CloudWatch Metrics is better for aggregate system-level health checks. |
