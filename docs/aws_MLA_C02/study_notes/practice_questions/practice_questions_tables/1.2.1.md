| **### Question 1 - Visual Data Cleaning without Code**<br><br>A retail company has terabytes of raw sales data stored in Amazon S3. The solution must minimize operational overhead and strictly avoid writing custom Apache Spark or Python scripts.<br><br>Which AWS tool should the team use to fulfill these requirements?<br><br>- **A)** Use SageMaker Data Wrangler to interactively build a data flow and export it to an AWS Lambda function.<br>- **B)** Use AWS Glue DataBrew to create a visual recipe of cleaning steps and run a DataBrew job.<br>- **C)** Use Amazon EMR to provision a Spark cluster and write PySpark scripts to clean the data.<br>- **D)** Use AWS Glue Studio to author a custom PySpark ETL job for data profiling and cleaning. | **Correct Answer:** **B**<br><br>**Correct Answer Analysis:**<br>- **B is Correct:** AWS Glue DataBrew is a visual data preparation tool that allows users to create "recipes" of cleaning and transformation steps without writing any code. It does not allow the level of custom OS-level dependency installation or deep cluster tuning required for specific complex Spark libraries/UDFs.<br>- **D is Incorrect:** SageMaker Data Wrangler is designed for interactive, low-code data preparation on smaller scales and does not support running custom Spark UDFs across a managed cluster in the same way EMR does.<br><br>> **Exam Tip:** Choose Amazon EMR over AWS Glue when you need custom libraries, complex Spark UDFs, specific hardware (GPUs), or deep cluster tuning control. |

| **### Question 9 - Stateless Per-Record Stream Processing**<br><br>A company is processing a streaming IoT data feed to detect anomalies. They need to transform the incoming data stream by parsing JSON payloads and filtering records based on a simple temperature threshold before sending the valid records to Amazon Kinesis Data Firehose. The transformation requires per-record processing with no need to maintain state across records or sliding windows. The solution must be highly serverless and event-driven.<br><br>Which AWS tool is the MOST appropriate for this transformation?<br><br>- **A)** AWS Glue Streaming ETL<br>- **B)** AWS Lambda<br>- **C)** Amazon EMR<br>- **D)** AWS Glue DataBrew | **Correct Answer:** **B**<br><br>**Correct Answer Analysis:**<br>- **B is Correct:** AWS Lambda is ideal for event-driven, per-record stream processing. Since the transformation (parsing JSON and filtering based on a threshold) is stateless and does not require aggregations across multiple records or sliding windows, Lambda is the most lightweight and serverless option.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** AWS Glue Streaming ETL runs Apache Spark Structured Streaming, which is overkill for simple, stateless per-record filtering and introduces unnecessary operational overhead and cost.<br>- **C is Incorrect:** Amazon EMR requires cluster management and is designed for heavy batch or complex stateful stream processing, not simple per-record filtering.<br>- **D is Incorrect:** AWS Glue DataBrew is designed for batch data preparation, not real-time stream processing.<br><br>> **Exam Tip:** For stateless, per-record stream transformations, AWS Lambda is the most efficient tool. Use Spark (via Glue Streaming or EMR) only when stateful windowed aggregations are required. |
