operational overhead. |

They need to build an automated pipeline to detect this drift.<br><br>Which pipeline architecture meets these requirements? (Select ONE)<br><br>- **A)** Monitor the average token length of prompts and trigger an alarm if it changes by 10%.<br>- **B)** Generate embeddings of current prompts, compare their distribution to a baseline using a statistical distance metric, and trigger an alarm if the distance crosses a threshold.<br>- **C)** Use Amazon Bedrock automatic evaluations to score the toxicity of incoming prompts.<br>- **D)** Set up an A/B test between the current FM and a new FM variant to compare invocation latencies. | **Correct Answer:** **B**<br><br>**Correct Option Analysis:**<br>- **B is Correct:** Data drift in generative AI is detected by capturing embeddings of input prompts, comparing the current distribution to a stable baseline using a statistic suited for high-dimensional data, and alerting when the distance exceeds a predefined threshold.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** Token length is a superficial metric and does not capture semantic shifts in the distribution of user prompts (data drift).<br>- **C is Incorrect:** Toxicity evaluation checks the safety of prompts, not statistical distribution shifts (data drift).<br>- **D is Incorrect:** A/B testing compares model variants on live traffic, it is not a pipeline for detecting input data distribution drift.<br><br>> **Key Takeaway:** Detecting data drift in FMs requires an embedding-based pipeline that statistically compares current prompt distributions to a baseline to identify semantic shifts. |

| **### Question 10 - Identifying Concept Drift in FM Outputs**<br><br>A customer service foundation model has been in production for 6 months. The input prompts from users have remained statistically similar to the training baseline (verified by an embedding pipeline), but the customer satisfaction scores for the model's responses have dropped significantly over the last month. The team needs to identify the type of drift occurring to address the root cause.<br><br>Which condition is the team experiencing? (Select ONE)<br><br>- **A)** Data drift<br>- **B)** Concept drift<br>- **C)** A throttling limit on the model invocation call<br>- **D)** A failure in one of the tools the assistant calls | **Correct Answer:** **B**<br><br>**Correct Option Analysis:**<br>- **B is Correct:** Concept drift occurs when the input data distribution ($P(X)$) remains constant, but the relationship between the input and the desired output ($P(Y|X)$) changes. In this case, the prompts are the same, but what users consider an acceptable answer has shifted, leading to lower satisfaction scores.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** Data drift is a shift in the input distribution ($P(X)$), which has been explicitly ruled out by the embedding pipeline showing prompts remain similar to the baseline.<br>- **C is Incorrect:** Throttling limits result in HTTP 429 errors and failed requests, not a gradual degradation in customer satisfaction for completed responses.<br>- **D is Incorrect:** Tool failures lead to explicit runtime errors or fallback messages, not a subtle shift in the acceptability of valid responses.<br><br>> **Key Takeaway:** Concept drift is characterized by a shift in what constitutes a correct output, even when the input data distribution remains stable, often detected through downstream business metrics. |
