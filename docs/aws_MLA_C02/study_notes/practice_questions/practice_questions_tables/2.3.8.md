| **### Question 1 - Evaluating Translation Models with N-Gram Precision**<br><br>A machine learning team is evaluating an Amazon Bedrock model fine-tuned for translating technical documentation from English to Spanish. The team needs to programmatically evaluate the quality of the translations against human-generated reference translations. The evaluation metric must heavily penalize missing important technical keywords and measure precise n-gram overlap, applying a brevity penalty for outputs that are too short. Which evaluation metric should the team use in an Amazon Bedrock Evaluation job?<br><br>Which **ONE** metric best fits this requirement? (Select ONE)<br><br>- **A)** ROUGE-N<br>- **B)** BLEU<br>- **C)** BERTScore<br>- **D)** Perplexity | **Correct Answer:** **B**<br><br>**Correct Answer Analysis:**<br>**B is Correct:** BLEU (Bilingual Evaluation Understudy) is a precision-oriented metric used primarily for machine translation. It measures the exact n-gram overlap between the generated text and the reference text, applying a brevity penalty to penalize translations that are too short, ensuring all critical keywords are present.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** ROUGE-N is a recall-oriented metric typically used for summarization, measuring how many n-grams from the reference appear in the candidate text.<br>- **C is Incorrect:** BERTScore evaluates semantic similarity using contextual embeddings rather than exact n-gram precision and overlap, which does not strictly enforce keyword matching.<br>- **D is Incorrect:** Perplexity measures how well a probability model predicts a sample, typically used to evaluate language models intrinsically rather than translation quality against a reference.<br><br>> **Exam Tip:** Use BLEU for translation (precision-focused with brevity penalty) and ROUGE for summarization (recall-focused). |
| **### Question 2 - Evaluating Summarization Models with Recall Metrics**<br><br>An AI startup is using a large language model (LLM) on Amazon Bedrock to generate automated executive summaries of quarterly financial reports. The engineering team must set up a Bedrock Evaluation job to assess the summarization quality. The chosen metric must evaluate how well the generated summary covers the key points present in the human-written reference summaries, prioritizing the recall of overlapping n-grams. The solution must be implemented with the least operational overhead.<br><br>Which **ONE** metric best fits this requirement? (Select ONE)<br><br>- **A)** BLEU<br>- **B)** BERTScore<br>- **C)** ROUGE<br>- **D)** Word Error Rate (WER) | **Correct Answer:** **C**<br><br>**Correct Answer Analysis:**<br>**C is Correct:** ROUGE (Recall-Oriented Understudy for Gisting Evaluation) is designed for evaluating summarization. It measures recall by calculating how many n-grams from the reference summary appear in the generated summary, ensuring that the model captures all the critical information.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** BLEU is a precision-based metric primarily used for translation, measuring how many n-grams in the generated text appear in the reference, not the other way around.<br>- **B is Incorrect:** BERTScore evaluates semantic similarity using embeddings rather than explicit n-gram recall.<br>- **D is Incorrect:** Word Error Rate (WER) measures the edit distance (insertions, deletions, substitutions) between a candidate and reference, commonly used in speech recognition rather than summarization recall.<br><br>> **Exam Tip:** If the scenario emphasizes capturing all key points from the reference, use ROUGE (Recall). If it emphasizes exact matches in the output, use BLEU (Precision). |
| **### Question 3 - Overcoming Synonym Penalties with Semantic Similarity**<br><br>A healthcare company is using Amazon Bedrock Knowledge Bases to retrieve and generate patient education materials. The generated text often uses different but synonymous medical terms compared to the reference documents (e.g., "high blood pressure" instead of "hypertension"). The team must evaluate the semantic similarity of the generated text to the reference text without penalizing the use of synonyms. Traditional n-gram overlap metrics are explicitly deemed insufficient by the compliance team.<br><br>Which **ONE** metric should the team implement in their Amazon Bedrock Evaluation? (Select ONE)<br><br>- **A)** BLEU-4<br>- **B)** BERTScore<br>- **C)** ROUGE-L<br>- **D)** Exact Match Accuracy | **Correct Answer:** **B**<br><br>**Correct Answer Analysis:**<br>**B is Correct:** BERTScore computes similarity using contextual embeddings (like BERT) rather than exact string matching. It maps tokens to embeddings and calculates cosine similarity, meaning synonyms like "hypertension" and "high blood pressure" will score highly without being penalized for lack of exact n-gram overlap.<br><br>**Distractor Analysis:**<br>- **A is Incorrect:** BLEU-4 strictly evaluates 4-gram precision, requiring exact word matches. It would heavily penalize synonymous replacements.<br>- **C is Incorrect:** ROUGE-L evaluates the longest common subsequence based on exact word matches, failing to account for semantic equivalence.<br>- **D is Incorrect:** Exact Match Accuracy requires the generated text to match the reference text word-for-word, making it the worst choice for evaluating synonyms.<br><br>> **Exam Tip:** When a scenario explicitly mentions synonyms, paraphrasing, or different wordings with the same meaning, select BERTScore or Semantic Similarity. |

It is useful for evaluating the structural alignment and sequence of words, as it doesn't require n-grams to be perfectly contiguous, only in the same order.<br><br>**Distractor Analysis:**<br>- **B is Incorrect:** BLEU-2 evaluates contiguous 2-gram (bigram) precision, which requires exact sequential matches and does not inherently measure the longest common subsequence.<br>- **C is Incorrect:** BERTScore calculates embedding cosine similarity, evaluating semantic meaning rather than structural sequence overlap.<br>- **D is Incorrect:** While Cosine Similarity is a vector space metric, it is not the specific NLP metric designed to measure the longest common subsequence.<br><br>> **Exam Tip:** ROUGE-L = Longest Common Subsequence. It evaluates structural order without requiring contiguous matches. |

This ensures the model is capturing all necessary information.<br><br>**Distractor Analysis:**<br>- **C is Incorrect:** BERTScore measures semantic similarity using embeddings, not explicit n-gram precision or recall based on exact word overlaps.<br>- **D is Incorrect:** Perplexity measures the model's predictive confidence and does not compare output against a reference text for precision or recall.<br>- **E is Incorrect:** Toxicity metrics evaluate the safety and harmfulness of the content, not n-gram precision and recall.<br><br>> **Exam Tip:** Use BLEU and ROUGE together when you need to balance Precision (BLEU) and Recall (ROUGE) in text generation tasks. |

| **### Question 8 - Measuring Unigram Recall for Data Extraction**<br><br>A financial services firm is running an LLM on Amazon Bedrock to extract structured key financial figures from unstructured earnings reports. The team must evaluate the model's output to ensure that all key financial figures from the reference text are present in the generated output. They specifically require a metric that measures the proportion of unigrams from the reference text that appear in the generated output.<br><br>Which **ONE** NLP metric specifically measures this recall? (Select ONE)<br><br>- **A)** ROUGE-1<br>- **B)** BLEU-1<br>- **C)** BERTScore<br>- **D)** Perplexity | **Correct Answer:** **A**<br><br>**Correct Answer Analysis:**<br>**A is Correct:** ROUGE-1 measures unigram recall. It calculates the number of matching unigrams (single words) between the reference and the candidate text, divided by the total number of unigrams in the reference text. This precisely matches the requirement of ensuring all reference figures (represented as words) are present in the output.<br><br>**Distractor Analysis:**<br>- **B is Incorrect:** BLEU-1 measures unigram precision, meaning it checks how many unigrams in the generated text appear in the reference text. This evaluates conciseness/relevance rather than completeness (recall).<br>- **C is Incorrect:** BERTScore measures semantic similarity through embeddings, not the explicit proportion of overlapping unigrams.<br>- **D is Incorrect:** Perplexity evaluates the probability distribution of the language model and does not compare extracted facts against a reference text.<br><br>> **Exam Tip:** "ROUGE-1" equals unigram recall. "ROUGE-2" equals bigram recall. Use ROUGE-N when the scenario demands verifying that all reference elements are captured in the output. |

They need to establish a baseline for model performance using standard NLP evaluation metrics. The baseline must specifically evaluate the precision of unigrams and bigrams in the generated output, but it must explicitly apply a brevity penalty to heavily penalize outputs that are too short and fail to provide a complete description. The team must automate this without managing servers.<br><br>Which **ONE** metric must be used? (Select ONE)<br><br>- **A)** BLEU<br>- **B)** ROUGE-L<br>- **C)** BERTScore<br>- **D)** F1-Score | **Correct Answer:** **A**<br><br>**Correct Answer Analysis:**<br>**A is Correct:** BLEU calculates modified n-gram precision (for unigrams, bigrams, etc.) and multiplies the result by a brevity penalty. The brevity penalty explicitly penalizes generated texts that are shorter than the reference text, preventing the model from achieving high precision by simply outputting a single correct word.<br><br>**Distractor Analysis:**<br>- **B is Incorrect:** ROUGE-L measures the longest common subsequence and is recall-oriented; it does not inherently apply a brevity penalty to penalize short outputs based on precision.<br>- **C is Incorrect:** BERTScore uses embeddings to calculate semantic similarity and does not apply a brevity penalty based on output length.<br>- **D is Incorrect:** F1-Score combines precision and recall but does not apply a specific brevity penalty for translation or text generation tasks like BLEU does.<br><br>> **Exam Tip:** The brevity penalty is a unique mathematical component of the BLEU score, designed to prevent the model from cheating by generating very short, precise outputs. |
