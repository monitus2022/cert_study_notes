### Question 1 - SageMaker Ground Truth Labeling Workflow Design

A healthcare AI startup is building a model to detect abnormal chest X-ray patterns using **Amazon SageMaker AI**. They have 50,000 unlabeled X-ray images in an S3 bucket and need high-quality annotations from certified radiologists.

The compliance team mandates that all annotation work remains within a private VPC with no public internet access, and the ML engineering team wants to minimize operational overhead for the labeling infrastructure.

Which approach should the engineering team use to label this dataset? (Select ONE)

* **A)** Deploy an open-source annotation tool (e.g., Label Studio) on EC2 instances within the VPC and configure security groups to restrict access to radiologists.
* **B)** Use SageMaker Ground Truth with a private workforce using the Amazon Cognito user pool and a VPC endpoint for secure access.
* **C)** Create a custom AWS Lambda function that serves images to radiologists via an API Gateway private endpoint, with annotations stored in DynamoDB.
* **D)** Use Amazon Bedrock to automatically generate annotations from the X-ray images without human review.
* **E)** Send the images to Amazon Mechanical Turk and filter workers by their self-reported medical qualifications.

??? note "Click to reveal Answer & Explanation"
    **Correct Answer:** **B**

    #### Correct Option Analysis
    * **B is Correct:** SageMaker Ground Truth natively supports private workforces via Amazon Cognito user pools, allowing organizations to restrict annotation tasks to authenticated internal users (certified radiologists). VPC endpoints for Ground Truth ensure all traffic stays within the private network, satisfying compliance requirements with minimal operational overhead since Ground Truth manages the labeling infrastructure, task distribution, and result collection.

    #### Distractor Analysis
    * **A is Incorrect:** Deploying and maintaining a custom annotation tool on EC2 requires patching, scaling, high availability configuration, and ongoing operational overhead. This violates the "minimize operational overhead" constraint when SageMaker Ground Truth provides this natively.
    * **C is Incorrect:** Building a custom annotation application using Lambda, API Gateway, and DynamoDB introduces significant development and maintenance overhead. Ground Truth already provides these capabilities as a managed service.
    * **D is Incorrect:** Bedrock cannot automatically generate reliable medical image annotations that meet the accuracy requirements of certified radiologists. Medical imaging annotation requires domain expertise that cannot be fully automated, and compliance standards would likely reject purely AI-generated labels.
    * **E is Incorrect:** Amazon Mechanical Turk is a public marketplace workforce. Workers cannot be reliably verified as certified radiologists, which violates the compliance requirement for certified professionals handling patient data.

    > **Key Takeaway:** For enterprise labeling workflows requiring private, authenticated workforces and minimal operational overhead, SageMaker Ground Truth with private workforce and VPC endpoints is the native AWS solution.

### Question 2 - Labeling Instruction Ambiguity Resolution

A financial services company is building a document classification model using **SageMaker Ground Truth** to route customer support tickets. The annotation team has labeled 10,000 support tickets across 5 complaint categories. After reviewing quality metrics, the ML engineer discovers that two annotators achieve high agreement on most categories but consistently disagree when classifying tickets about "payment disputes" versus "billing errors."

The model's errors cluster specifically at this boundary, resulting in misclassified tickets that are routed to the wrong department.

What is the MOST appropriate action to resolve this labeling quality issue? (Select ONE)

* **A)** Add more annotators to the task to increase annotation throughput.
* **B)** Remove the "billing errors" category entirely since it overlaps with "payment disputes."
* **C)** Review and refine the labeling instructions with clear, mutually exclusive definitions for the two categories, including edge-case examples, then re-label the disputed tickets.
* **D)** Use AWS Glue DataBrew to automatically merge the two categories into one combined class.
* **E)** Implement a majority vote using SageMaker Ground Truth built-in annotation consolidation and accept the current labels.

??? note "Click to reveal Answer & Explanation"
    **Correct Answer:** **C**

    #### Correct Option Analysis
    * **C is Correct:** Persistent inter-annotator disagreement at a specific class boundary signals ambiguous labeling instructions, not annotator error. Refining the instructions with precise, mutually exclusive definitions and providing edge-case examples directly addresses the root cause. Re-labeling the disputed tickets with the clarified guidelines improves label quality, which sets the ceiling for model performance.

    #### Distractor Analysis
    * **A is Incorrect:** Adding more annotators only adds more inconsistent labels if the instructions remain ambiguous. It treats the symptom (disagreement) rather than the root cause (unclear guidelines).
    * **B is Incorrect:** Merging legitimate business categories to avoid ambiguity may distort business processes. Payment disputes and billing errors likely require different routing destinations, so separating them is necessary for correct ticket handling.
    * **D is Incorrect:** AWS Glue DataBrew is a data profiling and cleaning tool for tabular data, not a document classification label resolver. It cannot intelligently decide class boundaries or merge semantic categories.
    * **E is Incorrect:** Majority vote consolidation with the existing ambiguous labels merely averages out the disagreement without resolving the root ambiguity. The model will continue to learn a blurred boundary and produce errors at the same edge cases.

    > **Key Takeaway:** When annotators consistently disagree on specific class boundaries, the labeling instructions—not the annotators—are the root cause; clarify definitions and edge-case examples before relabeling.

### Question 3 - Multi-Modal Dataset Bias Mitigation

An e-commerce platform is training a multimodal product recommendation model using product images, text descriptions, and numeric attributes (price, rating, category). The dataset was collected over 12 months, but due to a marketing initiative, 80% of product reviews come from Q4, and one product category (electronics) appears in only 2% of samples.

The ML engineer needs to prepare the dataset for training to prevent the model from overfitting to seasonal patterns while ensuring the underrepresented category is adequately represented.

Which TWO techniques should the engineer apply? (Select TWO)

* **A)** Shuffle the dataset randomly before splitting to break temporal correlation between collection order and training batches.
* **B)** Apply time-based splitting (e.g., train on months 1-9, validate on months 10-12) to respect chronological order.
* **C)** Apply data augmentation specifically to the electronics category (e.g., synthetic image variations, text paraphrasing) to increase its representation.
* **D)** Apply SMOTE oversampling uniformly across all categories to balance the dataset.
* **E)** Use stratified splitting to ensure the electronics category appears proportionally in both training and validation sets.

??? note "Click to reveal Answer & Explanation"
    **Correct Answers:** **A** and **C**

    #### Correct Options Analysis
    * **A is Correct:** When data is collected in batches with temporal or seasonal correlation (e.g., heavy Q4 representation), shuffling breaks the alignment between collection order and mini-batch sequence, ensuring each training batch contains a representative mix of time periods rather than being dominated by Q4 records.
    * **C is Correct:** Data augmentation (image transformations, text paraphrasing, synthetic variations) adds diversity to the underrepresented electronics category without duplicating identical records, which could cause overfitting to that specific narrow slice.

    #### Distractor Analysis
    * **B is Incorrect:** Time-based splitting is appropriate for time-series forecasting where chronological order matters, but for product recommendation the goal is to generalize across all time periods, making random shuffling and stratified splits more suitable than rigid chronological splits.
    * **D is Incorrect:** SMOTE applied uniformly across all categories would balance the dataset indiscriminately, potentially overrepresenting the majority categories already well-covered and diluting the specific focus needed on the electronics category.
    * **E is Incorrect:** While stratified splitting is a valuable technique for ensuring representation in evaluation sets, it does not address the underlying underrepresentation within the training data itself. The 2% representation needs augmentation or oversampling to improve the model's learning signal.

    > **Key Takeaway:** Match the technique to the specific defect: shuffling fixes temporal ordering biases, stratification ensures balanced evaluation splits, and targeted augmentation addresses underrepresentation for specific groups.

### Question 4 - Class Imbalance in Text Classification

A fraud detection team is building a model to classify financial transactions as "fraudulent" or "legitimate" using a dataset of 1 million transactions, where only 0.5% are fraudulent. A baseline model trained on this data achieves 99.5% accuracy but detects only 12% of actual fraudulent transactions.

The team needs to improve the model's ability to detect fraud (recall) while maintaining reasonable precision (avoiding excessive false alerts).

Which TWO techniques should the ML engineer apply to resolve the class imbalance? (Select TWO)

* **A)** Undersample the majority class (legitimate transactions) to balance the dataset, accepting some loss of information from discarded majority samples.
* **B)** Oversample the minority class (fraudulent transactions) using SMOTE to generate synthetic fraud examples with feature space interpolation.
* **C)** Report overall accuracy as the primary evaluation metric, since it already shows 99.5% performance.
* **D)** Use class weighting in the loss function to penalize misclassifications of fraudulent transactions more heavily during training.
* **E)** Remove all majority class samples that the model correctly classifies, since they add no information to the training process.

??? note "Click to reveal Answer & Explanation"
    **Correct Answers:** **A** and **D**

    #### Correct Options Analysis
    * **A is Correct:** Undersampling the majority class (legitimate transactions) reduces the imbalance and prevents the model from being dominated by the common label. While it discards potentially informative samples, with 1 million records and only 5,000 fraud cases, a balanced undersampled dataset still provides sufficient legitimate examples for training.
    * **D is Correct:** Class weighting adjusts the loss function proportionally to class frequency (or a chosen ratio), penalizing misclassified fraud cases more heavily. This helps the model prioritize minority class detection without needing to modify the dataset itself.

    #### Distractor Analysis
    * **B is Incorrect:** SMOTE is generally not recommended for high-dimensional and mixed-type tabular transaction data, especially with highly imbalanced fraud patterns. Synthetic interpolation between fraud examples may generate unrealistic feature combinations that do not represent actual fraudulent behavior and could degrade precision rather than improve recall.
    * **C is Incorrect:** Accuracy is misleading in imbalanced datasets, as demonstrated by the 99.5% accuracy with only 12% fraud detection. The team should report metrics like precision, recall, F1-score, and PR-AUC that specifically measure minority class performance.
    * **E is Incorrect:** Removing correctly classified majority samples is a specific form of undersampling, but selecting "correctly classified" samples introduces bias by removing only "easy" legitimate cases, potentially overrepresenting difficult legitimate cases that share features with fraud and confusing the model further.

    > **Key Takeaway:** For class imbalance, report precision-recall metrics, not overall accuracy, and apply rebalancing techniques like undersampling, class weighting, or targeted collection of rare-class data.

This optimizes the human labeling budget while maintaining label quality.

### Question 7 - Prompt-Response Pair Validation for Generative AI Fine-tuning

A startup is fine-tuning a foundation model (via **Amazon Bedrock** or **SageMaker JumpStart**) using a custom dataset of customer support conversations. The dataset contains 15,000 prompt-response pairs scraped from historical chat logs. Before submitting the fine-tuning job, the ML engineer must validate the training data integrity.

What are TWO mandatory validation checks the engineer should implement? (Select TWO)

* **A)** Verify that each response is relevant to its prompt and that no prompt-response pair has missing or malformed fields.
* **B)** Run content safety screening (e.g., Guardrails) to detect PII, toxicity, or inappropriate content in both prompts and responses before fine-tuning.
* **C)** Apply data augmentation to the prompt-response pairs to increase dataset size before validation.
* **D)** Shuffle the prompt-response pairs to remove any sequential ordering bias.
* **E)** Use Amazon Comprehend to translate all prompts and responses to English before fine-tuning.

??? note "Click to reveal Answer & Explanation"
    **Correct Answers:** **A** and **B**

    #### Correct Options Analysis
    * **A is Correct:** Structural data integrity requires verifying that each prompt has a corresponding response, no fields are missing or truncated, and the response semantically answers its prompt. Malformed pairs (e.g., empty responses, mismatched prompt-response) teach the model incorrect associations.
    * **B is Correct:** For generative AI fine-tuning, safety screening is critical before customization because unsafe content (PII, toxic language, offensive material) that enters the fine-tuning dataset can be reproduced in model outputs. Amazon Bedrock Guardrails or SageMaker content classifiers can automate this screening.

    #### Distractor Analysis
    * **C is Incorrect:** Augmentation should occur after validation, not before. Validating a dataset after augmenting it means the synthetic examples may not have undergone the same integrity checks, allowing malformed synthetic data into the fine-tuning set.
    * **D is Incorrect:** While shuffling is useful for training batch randomization, it does not validate the structural integrity of each prompt-response pair. Shuffling reordered but still invalid pairs would not fix malformed content.
    * **E is Incorrect:** Amazon Comprehend supports translation only between English and a limited set of primary languages, and translating a multilingual customer support dataset to English would change the domain's semantic characteristics. If the model must serve multilingual customers, retaining the original languages is correct; validation should be done on the original data.

    > **Key Takeaway:** For fine-tuning generative AI models, integrity checks must verify structural completeness (well-formed prompt-response pairs) and content safety (no PII/toxic content) before data reaches model customization.

### Question 9 - Data Deduplication Strategy for Enterprise Knowledge Base

An AI startup is preparing a dataset for fine-tuning a specialized text generation model using historical customer support conversations from multiple sources (Zendesk, Slack, email). The team discovers that some support queries appear multiple times across different sources with slight variations (e.g., "I need to reset my password" vs. "password reset requested"). Some are exact duplicates, while others are near-duplicates with minor wording differences.

The ML engineer needs to reduce redundancy while preserving legitimate variations of similar topics. What is the MOST appropriate deduplication approach? (Select ONE)

* **A)** Apply exact string matching to remove all records with identical text content, then manually review remaining near-duplicates to determine uniqueness based on feature-level differences.
* **B)** Use AWS Glue DataBrew to automatically detect and remove exact and near-duplicate records using its built-in deduplication feature, reviewing auto-suggested thresholds.
* **C)** Remove all records that share common keywords (e.g., "password reset"), keeping only one representative record per keyword.
* **D)** Use AWS Glue ETL jobs to hash each record and remove records with identical hash values, ignoring all near-duplicates.
* **E)** Delete all records from any source except the primary source (e.g., Zendesk) since other sources are redundant.

??? note "Click to reveal Answer & Explanation"
    **Correct Answer:** **B**

    #### Correct Option Analysis
    * **B is Correct:** AWS Glue DataBrew provides a built-in deduplication feature that can detect both exact duplicates and fuzzy/near-duplicates based on configurable matching thresholds (e.g., Levenshtein edit distance). This allows the engineer to remove redundant records while preserving legitimate variations that carry distinct information, with the flexibility to review and adjust the threshold.

    #### Distractor Analysis
    * **A is Incorrect:** Exact string matching only removes identical records but leaves all near-duplicates. Manual review of thousands of near-duplicate records is impractical for large datasets and operational overhead.
    * **C is Incorrect:** Keyword-based removal is overly aggressive: legitimate variations of the same topic may carry distinct context (e.g., different error scenarios for password reset) that the model needs to learn. This approach would collapse valuable distinctions and reduce dataset diversity.
    * **D is Incorrect:** Hash-based exact deduplication has the same limitation as exact string matching: it only identifies records with identical content. Near-duplicates with slight wording differences will have different hash values and remain in the dataset.
    * **E is Incorrect:** Removing entire data sources violates the requirement to preserve legitimate variations. Different communication channels may capture different facets of the same underlying issues (e.g., email may contain long-form context while Slack has brief exchanges), and deleting them reduces the dataset's representational richness.

    > **Key Takeaway:** For deduplication, use DataBrew's fuzzy matching capabilities to distinguish true duplicates from legitimate near-duplicate variations with context-dependent differences, rather than relying on exact matching or keyword heuristics.

### Question 10 - Inter-annotator Agreement Metrics and Ground Truth Quality Metrics

A legal tech company is building a document classification model using **SageMaker Ground Truth** to categorize contracts into 10 types (e.g., NDA, MSA, SOW, etc.). The annotation team consists of 5 legal experts. The ML engineer needs to measure the consistency of annotations to determine if the labeling quality meets the standard for model training.

Which metrics should the engineer use in **SageMaker Ground Truth** to evaluate annotation quality? (Select TWO)

* **A)** Fleiss's kappa or Cohen's kappa to measure inter-annotator agreement across all 5 annotators on multi-class labels.
* **B)** Ground Truth's built-in annotation consolidation metrics, including label confidence scores, to identify low-agreement items for review.
* **C)** Overall model accuracy after training on the labeled data to assess annotation quality.
* **D)** The total number of labels produced per hour per annotator as a proxy for quality.
* **E)** Cross-entropy loss of the trained model on the validation split to measure label correctness.

??? note "Click to reveal Answer & Explanation"
    **Correct Answers:** **A** and **B**

    #### Correct Options Analysis
    * **A is Correct:** Kappa statistics (Fleiss's kappa for multiple annotators, Cohen's kappa for pairwise agreement) measure the degree of agreement beyond chance among annotators. High kappa values (typically >0.7) indicate reliable annotations, while low values suggest ambiguous instructions or label noise.
    * **B is Correct:** SageMaker Ground Truth provides built-in annotation consolidation with confidence scores and quality metrics that show which data items have high disagreement among annotators. Engineers can route low-confidence items to additional review or inspect them for instruction ambiguity.

    #### Distractor Analysis
    * **C is Incorrect:** Overall model accuracy after training is a downstream performance metric, not an annotation quality measure. A model can achieve high accuracy despite poor annotation quality (e.g., by overfitting to noise or learning a majority-class predictor), or low accuracy despite high-quality labels (due to modeling issues).
    * **D is Incorrect:** Annotator throughput (labels per hour) measures efficiency, not quality. Fast labeling may correlate with errors, while slow labeling may indicate thoroughness or difficulty. Quality should be measured by consistency and correctness, not speed.
    * **E is Incorrect:** Cross-entropy loss during model training measures how well the model fits the labeled data, not whether the labels themselves are correct. If the labels are noisy, the model may struggle to reduce loss, but low loss does not confirm label quality—it may simply mean the model overfits to noise.

    > **Key Takeaway:** Label quality is best assessed using inter-annotator agreement metrics (e.g., kappa) and Ground Truth's built-in confidence scores, which flag low-agreement items for review before model training begins.
