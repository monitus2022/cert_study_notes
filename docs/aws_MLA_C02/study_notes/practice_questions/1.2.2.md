### Question 1 - SageMaker Feature Store for Training-Serving Consistency

A financial services company is building a fraud detection model that processes real-time credit card transactions. The data science team has engineered features including transaction velocity (transactions in the last 24 hours), merchant category embeddings, and customer spending z-scores. During development, they discover that the features computed during experimentation differ from those being computed in production, causing model performance degradation. The team needs a solution that ensures training and inference use identical feature definitions with minimal operational overhead.

Which approach should the ML engineer implement to resolve this training-serving skew?

**A)** Store all engineered features in Amazon SageMaker Feature Store, using the same feature groups for both training queries and online inference lookups.

**B)** Refactor the feature engineering codebase into a shared Python library and deploy it as a Lambda layer for both training jobs and inference endpoints.

**C)** Use AWS Glue DataBrew recipes to document the feature transformations, then manually reimplement them in the production inference pipeline.

**D)** Create feature lookup tables in Amazon DynamoDB that store pre-computed aggregates, and use AWS Lambda functions to compute features on-the-fly during inference.

??? note "Click to reveal Answer & Explanation"
    **Correct Answer:** A

    #### Correct Answer Analysis
    **A is Correct:** Amazon SageMaker Feature Store provides a centralized repository for feature definitions, ensuring that features are computed once and reused consistently across both model training and real-time inference. This eliminates training-serving skew by design, with the feature store handling the storage, retrieval, and serving infrastructure.

    #### Distractor Analysis
    * **B is Incorrect:** While a shared code library reduces drift, it still requires the team to maintain deployment infrastructure and ensure the library version is synchronized across training and production environments.     * **C is Incorrect:** Manually reimplementing transformations in production is exactly the practice that introduces training-serving skew. DataBrew recipes document the steps but don't automatically enforce consistency at inference time.
    * **D is Incorrect:** DynamoDB with Lambda functions is a custom implementation that requires the team to build, maintain, and scale the feature serving infrastructure themselves. This is higher operational overhead compared to SageMaker Feature Store's managed online and offline serving.

    > **Key Takeaway:** Use SageMaker Feature Store when the same feature definitions must serve both training and inference workloads, eliminating training-serving skew with minimal operational overhead.

### Question 2 - Streaming Data Transformation with Sliding Windows

A logistics company ingests GPS telemetry data from their delivery fleet through Amazon Kinesis Data Streams. The ML team needs to compute rolling average delivery speeds over the last 15 minutes for each vehicle to feed into a delay prediction model. The transformation must support continuously updating windows that slide with each new record, and the solution must maintain state across events while providing exactly-once processing guarantees.

Which AWS service should the team use to implement this streaming transformation?

**A)** AWS Lambda functions configured with a Kinesis event source mapping and a batch window of 15 minutes.

**B)** Amazon Managed Service for Apache Flink with a sliding window operator over the telemetry stream.

**C)** AWS Glue streaming ETL job running on Apache Spark Structured Streaming.

**D)** Amazon Kinesis Data Analytics with SQL-based sliding window queries.

??? note "Click to reveal Answer & Explanation"
    **Correct Answer:** B

    #### Correct Answer Analysis
    **B is Correct:** Amazon Managed Service for Apache Flink is purpose-built for stateful stream processing with sliding windows. It maintains continuous state across events, supports exactly-once processing semantics, and can compute rolling aggregates (like a 15-minute sliding average) that update as each new record arrives.

    #### Distractor Analysis
    * **A is Incorrect:** AWS Lambda is fundamentally stateless. While Lambda event source mappings can aggregate records into fixed non-overlapping windows, they cannot maintain the continuous sliding window state required for this use case.
    * **C is Incorrect:** AWS Glue streaming ETL with Spark Structured Streaming can process streaming data, but it is primarily designed for batch-oriented ETL workloads. Configuring and managing Spark for stateful sliding windows introduces more operational overhead than the dedicated stream processing of Managed Flink.
    * **D is Incorrect:** Kinesis Data Analytics with SQL (the legacy SQL engine) supports sliding windows but has been superseded by the Flink-based engine in Amazon Managed Service for Apache Flink. The newer service offers better state management, fault tolerance, and exactly-once guarantees.

    > **Key Takeaway:** Amazon Managed Service for Apache Flink is the right choice for stateful stream processing with continuously sliding windows, while Lambda only supports fixed non-overlapping windows.

### Question 5 - Feature Engineering Techniques for Skewed Data

A retail analytics team is building a customer lifetime value prediction model. They analyze the raw features and find that the `total_spend` variable has a right-skewed distribution with a long tail: most customers spend between $50–$500, while a small number of VIP customers spend $50,000+. The team plans to use a linear regression model, which assumes normally distributed features for optimal performance.

Which transformation should the ML engineer apply to the `total_spend` feature before model training?

**A)** Min-max scaling to normalize the values to a [0, 1] range.

**B)** Log transformation to compress the long tail and reduce skewness.

**C)** One-hot encoding to convert the continuous values into categories.

**D)** Z-score standardization to center the distribution at zero.

??? note "Click to reveal Answer & Explanation"
    **Correct Answer:** B

    #### Correct Answer Analysis
    **B is Correct:** Log transformation (typically `log1p` for values that may include zero) is specifically designed to handle heavily skewed distributions. By applying a logarithmic function, extreme values in the long tail are compressed relative to the smaller values, bringing the distribution closer to normal. This helps linear models learn more stable coefficients and improves model performance.

    #### Distractor Analysis
    * **A is Incorrect:** Min-max scaling only rescales values to a fixed range without changing the underlying distribution shape. The skew and long tail would remain, meaning extreme values would still dominate the scaling range.
    * **C is Incorrect:** One-hot encoding is designed for categorical variables, not continuous features. Converting continuous spend values to categories would lose the ordinal information and significantly increase dimensionality without addressing the skewness.
    * **D is Incorrect:** Z-score standardization centers data at zero with unit variance but does not reduce skewness. The long tail of extreme values would still distort the distribution and affect model performance.

    > **Key Takeaway:** Log transformations compress long tails in skewed distributions, while scaling techniques (min-max, z-score) only rescale the range without changing the underlying shape.

Which approach should the ML engineer use to prepare this data for model customization?

**B)** Use Dataset 1 as unlabeled text for continued pre-training, then fine-tune the resulting model using Dataset 2 as prompt-response pairs.

    **Correct Answer:** B

    #### Correct Answer Analysis
    **B is Correct:** Continued pre-training with Dataset 1 (unlabeled domain text) allows the model to absorb legal vocabulary, document structures, and stylistic patterns. ### Question 7 - Data Anonymization Techniques for Compliance

A healthcare startup is preparing a dataset of electronic health records for ML model training in Amazon SageMaker. The dataset contains personally identifiable information (PII) including patient names, social security numbers, and dates of birth. Compliance regulations require that the data be anonymized so that no individual can be identified, while preserving as much analytical value as possible for the ML model.

Which combination of techniques should the ML engineer apply to meet compliance requirements?

**A)** Mask PII fields by replacing characters with asterisks while preserving the format structure.

**B)** Apply data anonymization techniques such as k-anonymity or differential privacy, and remove direct identifiers.

**C)** Encrypt the PII fields using AWS KMS before storing in S3.

**D)** Use Amazon Macie to detect PII and apply client-side redaction in the training script.

??? note "Click to reveal Answer & Explanation"
    **Correct Answer:** B

    #### Correct Answer Analysis
    **B is Correct:** Data anonymization requires techniques that make it impossible to identify individuals from the data. Removing direct identifiers (names, SSNs) and applying techniques like k-anonymity or differential privacy ensures that even indirect identifiers (zip code, age, condition) cannot be combined to re-identify individuals. This is fundamentally different from masking or redaction, which only hide values without guaranteeing anonymity.

    #### Distractor Analysis
    * **A is Incorrect:** Masking hides values but still preserves individual records by keeping same-format placeholders. This may be sufficient for display purposes but does not guarantee data anonymization, as individuals could still be identified through remaining information.
    * **C is Incorrect:** Encryption protects data at rest but does not anonymize it. Once decrypted for model training, the PII becomes visible, and encryption does not prevent an individual from being identified in the dataset.
    * **D is Incorrect:** Amazon Macie detects and reports PII locations but does not perform anonymization. Client-side redaction in the training script adds complexity and does not guarantee anonymization if the original data remains in S3.

    > **Key Takeaway:** Anonymization requires applying techniques like k-anonymity or differential privacy and removing direct identifiers, which is fundamentally different from masking (preserves shape) or encryption (protects at rest).

### Question 15 - Classification vs. Embedding for Text Features

A machine learning team is building a product recommendation model. The dataset includes a `product_category` column with 5 possible values (Electronics, Clothing, Home, Sports, and Beauty) and a `product_description` column containing free-text descriptions of each item. The team needs to transform both features for use in a neural network model.

Which transformation approach should the team apply to each feature?

**A)** Apply one-hot encoding to `product_category` and use an embedding model from Amazon Bedrock for `product_description`.

**B)** Apply one-hot encoding to both `product_category` and `product_description`.

**C)** Use an embedding model for both features since both are textual.

**D)** Assign numeric codes (1-5) to `product_category` and use TF-IDF for `product_description`.

??? note "Click to reveal Answer & Explanation"
    **Correct Answer:** A

    #### Correct Answer Analysis
    **A is Correct:** This follows the fundamental principle: categories get encoded, while meaning gets embedded. `product_category` is a categorical feature with no inherent semantic relationship among values, so one-hot encoding (or label encoding with proper model architecture) is appropriate. `product_description` contains free-text with semantic meaning (products described as "wireless" and "Bluetooth" should be recognized as similar), so using an embedding model from Amazon Bedrock is appropriate.

    #### Distractor Analysis
    * **B is Incorrect:** One-hot encoding for `product_description` would create an extremely high-dimensional feature vector where each unique word becomes a binary column. This approach loses semantic relationships between similar texts and creates prohibitively high-dimensional input for the neural network (e.g., 20,000+ unique words in descriptions).
    * **C is Incorrect:** Using embeddings for `product_category` is unnecessary and potentially counterproductive. Categorical features like product category should be encoded, not embedded for semantic similarity. Embedding a 5-category column would create unnecessary complexity and reduce interpretability.
    * **D is Incorrect:** Assigning numeric codes (1-5) to `product_category` creates an artificial ordinal relationship where Home (3) would appear "greater than" Clothing (2), which may mislead the model. While TF-IDF is a valid text representation, it does not capture contextual meaning with the same effectiveness as modern transformer-based embedding models.

    > **Key Takeaway:** Use encoding (one-hot or label encoding) for categorical features with no semantic relationship, and use embedding models for free-text features where capturing semantic meaning is important.
