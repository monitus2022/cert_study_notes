### The 3 Core Tasks

1. **Choosing Appropriate Modeling Approaches**
    * **Traditional ML vs. Foundation Models (FMs):** Selecting tabular/classical algorithms vs. deep learning or GenAI foundation models based on data and task requirements.
    * **Managed Services vs. Custom Builds:** Weighing fully managed options (e.g., Amazon Bedrock, SageMaker JumpStart) against custom training on SageMaker instances.
    * **Architectural Selection:** Identifying when a scenario requires Retrieval-Augmented Generation (RAG) vs. direct inference or fine-tuning.


2. **Training, Customizing, & Fine-Tuning Models**
    * **Training Operations:** Configuring instance types, distributed training, hyperparameter tuning (HPO), and regularizing to prevent overfitting.
    * **GenAI Customization:** Applying prompt engineering techniques first, followed by Parameter-Efficient Fine-Tuning (PEFT/LoRA) or Supervised Fine-Tuning (SFT) when prompting alone is insufficient.


3. **Analyzing & Evaluating Performance**
    * **Baselines & Tracking:** Establishing performance baselines, logging metrics, and running reproducible experiments (e.g., SageMaker Experiments).
    * **Traditional Metrics:** Evaluating tabular models using Precision, Recall, F1, ROC-AUC, RMSE, etc.
    * **GenAI & FM Metrics:** Evaluating foundation model outputs using specialized benchmarks, human-in-the-loop (SageMaker Clarify/Ground Truth), and automated LLM-as-a-judge metrics (e.g., ROUGE, BLEU, semantic similarity).

### Key Pipeline Architectural Takeaway

* **Sequential Dependency Loop:** Domain 2 decisions build directly on one another:

$$\text{Model Choice} \longrightarrow \text{Training / Customization} \longrightarrow \text{Performance Evaluation}$$


* Skipping or rushing evaluation means deploying an unverified guess.
* Evaluation metrics determine whether the modeling approach and training configuration actually succeeded before pushing to deployment.
