# 1 - Feature Engineering

## Basics
> Applying your knowledge of the data – and the model you’re using - to create better features to train your model with
- Every feature is a new dimension, too many features lead to sparse data
- Feature engineering = select the feature most relevant to problem to be solved
- Unsupervised dimensionality reduction techniques can also be employed to  distill many features into fewer features, e.g. `PCA`, `K-Means`

## TF-IDF

### What is TF-IDF
> Term Frequency x Inverse Document Frequency
- TF (Term Frequency): How often a term appears in a document
- IDF (Inverse Document Frequency): Down-weights common words and up-weights rare, more informative terms.
- Combined: A **numerical vector representation** of text that is useful for classical ML algorithms
- Extension of TF-IDF is not only counting single words but "n-grams" of words. Example:
    - “I love certification exams”
        - Unigrams: “I”, “love”, “certification”, “exams”
        - Bi-grams: “I love”, “love certification”, “certification exams”
        - Tri-grams: “I love certification”, “love certification exams”

### Usage
- Bag-of-words style text classification or similarity tasks.
- Relatively small-to-medium text corpora.
- Situations where interpretability of features (actual words/terms) matters.
- VS embedding or Bedrock foundation models (modern approach), which is for complicated sementic understanding

## Imputing Missing Data

| Technique | Description | When to Prefer | Risks / Limitations |
|-----------|-------------|----------------|---------------------|
| **Dropping** (listwise or pairwise) | Remove rows or columns with missing values | Very small % of missing data; missingness is random (MCAR); high-quality complete cases exist | Loss of information; can introduce bias if data is not missing at random |
| **Simple imputation – Mean / Median / Mode** | Replace missing values with central tendency of the column | Numerical features (mean/median); categorical (mode); quick baseline | Distorts distribution; underestimates variance; ignores relationships between features |
| **Constant / Indicator imputation** | Fill with a fixed value (e.g., 0, –1, “Unknown”) + optional missingness indicator flag | When missingness itself is informative | Can create artificial patterns the model learns |
| **Advanced statistical imputation** | KNN imputation, multivariate imputation (e.g., MICE) | Moderate missingness; relationships between features matter | Computationally heavier; still assumes a certain missingness mechanism |
| **Model-based / ML imputation** | Train a model (regression, tree-based, etc.) to predict missing values | Complex missing patterns; sufficient complete data to train the imputer | Risk of overfitting the imputer; leakage if not done carefully within CV folds |
| **Domain-specific or business-rule imputation** | Use domain knowledge (e.g., “age missing → set to median of similar group”) | Strong domain expertise available | Requires subject-matter input; less generalizable |
| **Collect more data** | Acquire additional complete observations | Feasible and cost-effective; missingness is structural | Often impractical in production or time-constrained projects |

### Missingness mechanisms 
- MCAR (Missing Completely at Random)  
- MAR (Missing at Random)  
- MNAR (Missing Not at Random)  

### Impact on the ML pipeline
- Imputation must be fit only on the training set and then applied to validation/test sets (to avoid data leakage).  
- Missingness can be a useful signal — sometimes creating a binary “is_missing” feature improves performance.  
- After imputation, re-check distributions, correlations, and potential bias (SageMaker Clarify is relevant here).
- Outlier treatment often occurs alongside missing-value handling.  
- Imputed data still needs scaling/normalization, encoding, etc.  
- Data quality validation (Glue Data Quality, DataBrew) should flag high rates of missingness before or after imputation.

### AWS Tools Commonly Used

- **SageMaker Data Wrangler** – Visual interface for detecting missing values and applying simple imputations (mean, median, mode, constant). Good for interactive exploration.
- **AWS Glue DataBrew** – Recipe-based cleaning, including missing-value handling, suitable for larger datasets.
- **AWS Glue / Spark on EMR** – Custom or distributed imputation logic at scale (e.g., using Spark MLlib or custom PySpark).
- **SageMaker Processing jobs** – Run scikit-learn `SimpleImputer`, `KNNImputer`, or custom scripts.
- **SageMaker Feature Store** – Store both the imputed features and optional missingness indicators for consistent use at training and inference time.
- **Glue Data Quality** / **DataBrew** – Profile and validate missing-value rates as part of data quality checks.

## Handling Unbalanced Data

- When one class (usually the positive/minority class) is significantly underrepresented, standard models tend to predict the majority class and achieve high accuracy while performing poorly on the minority class
- This is especially critical in fraud detection, medical diagnosis, churn prediction, anomaly detection, etc. (Detecting appearance of abnormal cases)

### Key metrics and detection

- **Class Imbalance (CI)** – ratio or difference between majority and minority class proportions.
- **Difference in Proportions of Labels (DPL)** – a bias metric used by SageMaker Clarify.
- Always inspect the label distribution **before** training.
- Prefer metrics that are robust to imbalance: **Precision, Recall, F1-score, AUC-ROC, AUC-PR (Precision-Recall curve)**, instead of plain accuracy.

### SMOTE
> Synthetic Miniority Over-sampling TEchnique
- An **oversampling** technique that creates **synthetic** examples of the minority class
- Generates new points by interpolating between a minority sample and its nearest minority neighbors in feature space
- Result: a more balanced training set without exact copies of the original minority instances.

??? note "Math behind"

    Given a minority dataset \( D_{\text{min}} = \{\mathbf{x}_1, \mathbf{x}_2, \dots, \mathbf{x}_m\} \) where \( \mathbf{x}_i \in \mathbb{R}^d \):

    **1. Pairwise Distance Calculation**  
    Compute Euclidean distance to evaluate feature space proximity between minority samples:

    $$
    d(\mathbf{x}_i, \mathbf{x}_j) = \|\mathbf{x}_i - \mathbf{x}_j\|_2 = \sqrt{\sum_{p=1}^d (x_{i,p} - x_{j,p})^2}
    $$

    **2. \( k \)-Nearest Neighbors Identification**  
    Select the \( k \) closest minority instances \( N_k(\mathbf{x}_i) \) for target sample \( \mathbf{x}_i \):

    $$
    N_k(\mathbf{x}_i) = \text{Top-}k \left( \left\{ \mathbf{x}_j \in D_{\text{min}} \setminus \{\mathbf{x}_i\} \;\middle|\; d(\mathbf{x}_i, \mathbf{x}_j) \right\} \right)
    $$

    **3. Linear Interpolation (Synthetic Generation)**  
    Construct a new instance along the line segment connecting \( \mathbf{x}_i \) to a randomly chosen neighbor \( \hat{\mathbf{x}}_i \):

    $$
    \mathbf{x}_{\text{synthetic}} = \mathbf{x}_i + \lambda \cdot (\hat{\mathbf{x}}_i - \mathbf{x}_i)
    $$

    $$
    \text{where } \hat{\mathbf{x}}_i \sim \text{Uniform}\left(N_k(\mathbf{x}_i)\right), \quad \lambda \sim U(0, 1)
    $$
