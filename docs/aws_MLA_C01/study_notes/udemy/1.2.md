# Data Ingestion and Storage - Amazon S3

### S3 Components

#### Buckets
- Region-specific
- Unique name across all AWS accounts

#### Objects
- **Key**: Unique identifier for an object within a bucket

    e.g. `s3://my-bucket/my-folder/my-file.txt`
  * **Prefix**: `my-folder`
  * **Object name**: `my-file.txt`
- There is no "directories" in S3, but you can simulate a folder structure using prefixes and delimiters.

### Security
- User-based
- Resources-based
- Encryption

| Security Type | Description | Example |
|---------------|-------------|---------|
| User-based | Access control based on AWS Identity and Access Management (IAM) users, groups, and roles. | IAM policies, user permissions, and role-based access control. |
| Resource-based | Access control based on resource policies attached to S3 buckets or objects. | - Bucket policies<br> - Object / Bucket Access Control Lists (ACLs) |
| Encryption | Protecting data at rest and in transit using encryption techniques. | - Server-side encryption (SSE) <br> - Client-side encryption (CSE) <br> - SSL/TLS for data in transit |

### Bucket Policies

```JSON
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowReadAccessToSpecificRole",
      "Effect": "Allow",
      "Principal": {
        "AWS": "arn:aws:iam::123456789012:role/MyApplicationRole"
      },
      "Action": [
        "s3:ListBucket",
        "s3:GetObject"
      ],
      "Resource": [
        "arn:aws:s3:::my-example-bucket",
        "arn:aws:s3:::my-example-bucket/*"
      ]
    }
  ]
}
```
* **`Version`**: Set to `"2012-10-17"`, which is the current AWS IAM policy standard version.
* **`Principal`**: Identifies the AWS IAM user, role, or account receiving permission (replace `123456789012` and `MyApplicationRole` with your Account ID and IAM entity).
* **`Action`**: Specifies allowed operations (`s3:ListBucket` to view contents, `s3:GetObject` to read/download files).
* **`Resource`**: Differentiates between bucket-level and object-level permissions:
* `arn:aws:s3:::my-example-bucket` targets the bucket itself (required for `s3:ListBucket`).
* `arn:aws:s3:::my-example-bucket/*` targets objects inside the bucket (required for `s3:GetObject` or `s3:PutObject`).

### Versioning
- Protect against unintended deletion or overwriting of objects
- Easy roll back to previous versions

### Replication
- Must enable **Versioning** in source and destination buckets
- Cross-Region Replication (CRR):
    - Replicates objects across different AWS regions
    - Usage: **Compliance**, disaster recovery, **latency reduction**, and data sovereignty
- Same-Region Replication (SRR): 
    - Replicates objects within the same AWS region
    - Usage: **Live replication** between production and testing environments, data redundancy, and backup solutions
- Replication is asynchronous
- Only new objects are replicated after enabling, can replicate existing objects using S3 Batch Replication
- Can replicate "deletion" by replicating delete markers from source to destination

- Durability: 99.999999999% (11 9's)
- Availability: Depends on storage class

### Lifecycle Rules
- Transition objects to different storage classes based on age or access patterns
- Can be automated using **S3 Lifecycle Rules**

- Transition Actions: 
  - Move objects to a different storage class (e.g., Standard → Glacier)
- Expiration Actions:
  - Permanently delete objects after a specified period (e.g., 365 days)
- Rules can be created for certain prefix (e.g., `logs/`) or tags (e.g., `{"Environment": "Test"}`)
- **S3 Analytics**: help you decide when to transitioni objects to the right storage class (Only works for Standard and Standard-IA!)

### S3 Event Notifications

- Automatically publishing a **JSON notification payload** when specific actions occur inside an S3 bucket
- Enable **event-driven architectures**
- Eliminating the need for applications to continuously poll S3 (`ListObjects` / `HeadObject`).
- Supported Native Destinations:
    * **AWS Lambda:** Triggers code execution for real-time processing (e.g., feature extraction, image resizing, schema validation).
    * **Amazon SQS Queues:** Buffers and rate-limits high-volume incoming uploads to protect downstream processing services. *(Note: **Standard SQS queues only**; SQS FIFO is not natively supported).*
    * **Amazon SNS Topics:** Enables fan-out architectural patterns (broadcasting a single upload event to multiple independent subscriber queues or services).
    * **Amazon EventBridge:** Routes S3 events into an event bus for complex workflows across multiple services or accounts.
- **Filter Scope:** Rules can filter events by key **Prefix** (e.g., `landing-zone/raw/`) and/or **Suffix** (e.g., `.parquet`, `.json`).
* **Event Categories:**
    * **Object Creation:** `s3:ObjectCreated:*` (Put, Post, Copy, CompleteMultipartUpload)
    * **Object Removal:** `s3:ObjectRemoved:*` (Delete, DeleteMarkerCreated)
    * **Restoration:** `s3:ObjectRestore:*` (Post, Completed)
    * **Replication & Lifecycle:** Object replication, S3 Lifecycle expiration, and S3 Lifecycle transition events.

- Native S3 Notifications vs. Amazon EventBridge

| Feature | Native S3 Event Notifications | S3 Events via Amazon EventBridge |
| --- | --- | --- |
| **Targets** | Lambda, SQS (Standard), SNS, EventBridge | 20+ AWS Targets (Step Functions, Kinesis, ECS, API Destinations) |
| **SQS FIFO Support** | No | **Yes** |
| **Pattern Filtering** | Basic Prefix and Suffix matching | Advanced JSON pattern matching (file size, tags, metadata) |
| **Cross-Account** | Requires resource-based topic/queue policies | Native cross-account Event Bus routing |

### Baseline Performance
- Latency: Milliseconds for GET/PUT requests
- GET/HEAD requests: 5500 per second per prefix
- PUT/POST/DELETE requests: 3500 per second per prefix
- Spreading reads across prefixes can increase throughput (e.g., `logs/2024/01/`, `logs/2024/02/`, `logs/2024/03/`)

- Multi-Part uploads: 
    - recommended for >100MB, and required for >5GB 
    - can upload parts in parallel to increase throughput
- S3 Transfer Acceleration: 
    - Uses Amazon CloudFront's globally distributed edge locations to accelerate uploads and downloads to S3 buckets
    - Recommended for long-distance transfers (e.g., from on-premises data centers to S3 in a different region)
    - Compatible with multi-part uploads and can be used with the AWS SDKs and CLI
