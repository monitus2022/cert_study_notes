### Question 1
A company is designing an application that must run in a specific geographic area. The application should be deployed across separate data center locations within that geographic area to improve availability. Which AWS global infrastructure concept best describes the geographic area?

A. AWS Region  
B. Availability Zone  
C. Edge location  
D. AWS Local Zone  

<details>
<summary>Click to view Answer & Explanation</summary>

**Correct Answer:** A

**Explanation:**

* **Why A is correct:** An AWS Region is a separate geographic area that contains multiple Availability Zones.
* **Why distractors are incorrect:**
  * **B (Availability Zone):** An Availability Zone is one or more discrete data centers within an AWS Region.
  * **C (Edge location):** An edge location is a site used to deliver content and services closer to end users.
  * **D (AWS Local Zone):** An AWS Local Zone places selected AWS resources closer to users in a specific metropolitan area, but it is not the broader geographic area containing multiple Availability Zones.

</details>

### Question 2
A financial services company is deploying a web application in the AWS Cloud. The company wants the application to remain available if a data center experiences a power or networking failure. Which deployment strategy best meets this requirement?

A. Deploy the application in multiple Availability Zones within one AWS Region  
B. Deploy the application only in one Availability Zone and use an edge location  
C. Deploy the application in multiple edge locations within one Availability Zone  
D. Deploy the application in one AWS Local Zone  

<details>
<summary>Click to view Answer & Explanation</summary>

**Correct Answer:** A

**Explanation:**

* **Why A is correct:** Deploying resources across multiple Availability Zones provides high availability because the Availability Zones are designed to be isolated from failures in other Availability Zones.
* **Why distractors are incorrect:**
  * **B:** A single Availability Zone remains a potential single point of failure. An edge location does not replace deploying application resources across Availability Zones.
  * **C:** Edge locations are used primarily for services such as content delivery and do not provide a multi-Availability-Zone application deployment.
  * **D:** An AWS Local Zone is designed to provide resources closer to users in a metropolitan area, not to replace a highly available deployment across multiple Availability Zones.

</details>

<summary>Click to view Answer & Explanation</summary>

**Correct Answer:** B

**Explanation:**

* **Why distractors are incorrect:**
  * **A:** Availability Zones are not located in the same physical data center.
  * **C:** Edge locations are used to bring content and services closer to end users; they are not Availability Zones.

D. Move the application to an AWS Local Zone in the same metropolitan area  

<details>
<summary>Click to view Answer & Explanation</summary>

**Correct Answer:** B

**Explanation:**

* **Why B is correct:** Using multiple AWS Regions can support disaster recovery and business continuity if an event affects an entire Region.
