<summary><strong>Question 1</strong></summary>
<br>
A company wants to follow AWS best practices for securing its AWS account. Which action should the company take to protect the AWS account root user?
<br><br>
A. Create an IAM user with administrator permissions and use that user for daily tasks.<br>
B. Share the root user credentials with the security team only.<br>
C. Enable multi-factor authentication (MFA) for the root user and store the credentials securely.<br>
D. Generate a new set of access keys for the root user every 30 days.
</details>

<details>
<summary><strong>Click to reveal answer</strong></summary>
<strong>Correct Answer: C</strong><br><br>
<strong>Explanation:</strong> AWS strongly recommends enabling MFA on the root user and locking away the root credentials. The root user should never be used for daily tasks. Instead, create an administrative user (preferably via IAM Identity Center) for everyday work.<br><br>
<strong>Exam Tip / Trap:</strong> Watch for answers that suggest using or rotating root access keys regularly — AWS recommends deleting root access keys entirely if they exist. Keywords: “protect the root user”, “MFA”, “do not use for daily tasks”.
</details>

<summary><strong>Question 2</strong></summary>
<br>
Which of the following tasks can be performed only by the AWS account root user? (Select TWO.)
<br><br>
A. Change the AWS Support plan<br>
B. Create an IAM user<br>
C. Close the AWS account<br>
D. Attach a policy to an IAM group<br>
E. Launch an Amazon EC2 instance
</details>

<details>
<summary><strong>Click to reveal answer</strong></summary>
<strong>Correct Answers: A and C</strong><br><br>
<strong>Explanation:</strong> Only the root user can change the Support plan and close the AWS account. Creating IAM users, attaching policies, and launching EC2 instances can (and should) be done by IAM users or roles with appropriate permissions.<br><br>
<strong>Exam Tip / Trap:</strong> Memorize the short list of root-only tasks (change account settings, close account, change Support plan, restore IAM permissions if locked out, configure S3 MFA Delete, etc.). Anything related to normal resource management is NOT root-only.
</details>

<summary><strong>Question 3</strong></summary>
<br>
A solutions architect needs to grant a group of developers permission to start and stop Amazon EC2 instances only. Which approach follows the principle of least privilege?
<br><br>
A. Attach the AWS managed policy <code>AdministratorAccess</code> to the developers’ IAM group.<br>
B. Create a custom IAM policy that allows <code>ec2:StartInstances</code> and <code>ec2:StopInstances</code> and attach it to the group.<br>
C. Give each developer the AWS account root user credentials.<br>
D. Attach the AWS managed policy <code>PowerUserAccess</code> to each developer’s IAM user.
</details>

<details>
<summary><strong>Click to reveal answer</strong></summary>
<strong>Correct Answer: B</strong><br><br>
<strong>Explanation:</strong> The principle of least privilege means granting only the minimum permissions required. A custom policy limited to the two EC2 actions is the most restrictive correct option.<br><br>
<strong>Exam Tip / Trap:</strong> “Least privilege” almost always points to a custom or tightly scoped managed policy rather than broad policies like AdministratorAccess or PowerUserAccess.
</details>

<summary><strong>Question 4</strong></summary>
<br>
What is the main difference between an IAM user and an IAM role?
<br><br>
A. An IAM user has permanent long-term credentials; an IAM role provides temporary security credentials.<br>
B. An IAM role can be used only by AWS services; an IAM user can be used only by people.<br>
C. IAM users support MFA; IAM roles do not.<br>
D. IAM roles are billed hourly; IAM users are free.
</details>

<details>
<summary><strong>Click to reveal answer</strong></summary>
<strong>Correct Answer: A</strong><br><br>
<strong>Explanation:</strong> IAM users have long-term credentials (password and/or access keys). IAM roles provide temporary credentials that are assumed by users, applications, or AWS services.<br><br>
<strong>Exam Tip / Trap:</strong> Roles are preferred for applications, cross-account access, and federation because credentials are temporary and automatically rotated.
</details>

<br>
A company wants to give temporary AWS credentials to mobile app users who sign in with their social media accounts or as guest users. Which AWS service should the company use?
<br><br>
A. AWS IAM Identity Center<br>
B. Amazon Cognito identity pools<br>
C. AWS Secrets Manager<br>
D. AWS Directory Service
</details>

<details>
<summary><strong>Click to reveal answer</strong></summary>
<strong>Correct Answer: B</strong><br><br>
<strong>Explanation:</strong> Amazon Cognito identity pools (federated identities) can issue temporary AWS credentials to both authenticated (social or Cognito user pool) and unauthenticated (guest) users.<br><br>
<strong>Exam Tip / Trap:</strong> Cognito User Pools = user directory/authentication. Cognito Identity Pools = temporary AWS credentials. Do not confuse the two.
</details>

Which statement about AWS managed policies versus customer managed policies is correct?
<br><br>
A. Only AWS managed policies can be attached to IAM roles.<br>
B. AWS managed policies are created and updated by AWS; customer managed policies are created and managed by the customer.<br>
C. Customer managed policies cannot be edited once created.<br>
D. AWS managed policies are free; customer managed policies incur a charge.
</details>

<details>
<summary><strong>Click to reveal answer</strong></summary>
<strong>Correct Answer: B</strong><br><br>

</details>
