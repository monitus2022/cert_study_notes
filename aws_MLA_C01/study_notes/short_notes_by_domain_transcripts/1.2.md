# Task 1.2: Transform Data & Feature Engineering (MLA-C01)

## Key Concepts
Prepare raw data for ML training via cleaning, transformation, and feature engineering. Understand data types: numerical (continuous/discrete), categorical, ordinal, binary, text, and temporal. Transformations improve model accuracy by handling scale differences, missing values, and non-numeric inputs.

**Data Cleaning & Transformation**: Detect/treat outliers (e.g., IQR or z-score removal/capping). Impute missing dataâ€”prefer mean/median for numerical, mode for categorical, or advanced methods like MICE (Multiple Imputation by Chained Equations) over simple zero-fill or dropping (which risks bias if >10-15% missing or features are valuable). Combine datasets, deduplicate records. For streaming, use AWS Lambda or Spark on EMR.

**Feature Engineering**: Scale/standardize (z-score) or normalize (min-max to [0,1]) so large-range features do not dominate (critical for distance-based models like KNN or linear learner). Apply log transformation for skewed data, binning for continuous-to-categorical, feature splitting. Dimensionality reduction (e.g., PCA) cuts noise/redundancy. Create features via SageMaker Feature Store for reuse/sharing.

**Encoding Techniques**: Convert categoricals to numeric. One-hot encoding creates binary columns per category (ideal for nominal data; use in Glue DataBrew recipes). Label encoding assigns integers (suits ordinal). Binary encoding is compact; tokenization splits text for NLP. Avoid target encoding if pure binary conversion is needed.

**Annotation/Labeling**: Use SageMaker Ground Truth or Amazon Mechanical Turk for high-quality labeled datasets.

## AWS Tools Comparison
- **SageMaker Data Wrangler** (in Canvas/Studio): No/low-code visual prep, transforms, visualization, analysis. Import from S3/Redshift/Athena; export to Processing/Pipelines/Feature Store or Python scripts. Best for interactive EDA + custom Python.
- **AWS Glue DataBrew**: Visual recipe-based cleaning/transforms (one-hot, imputation, profiling). Strong for tabular summarization without code; integrates with Glue ETL.
- **AWS Glue + Spark (EMR)**: Code-heavy (PySpark) for large-scale/batch/streaming transforms. More flexible than DataBrew/Wrangler for complex jobs but higher effort.
- **Lambda**: Lightweight streaming transforms vs. Sparkâ€™s distributed power.

## Why Transform?
Raw data causes bias, poor convergence, or inaccurate predictions. Encoding enables algorithms; scaling equalizes influence; imputation preserves samples/features.
