# Task 1.1: Ingest and Store Data (MLA-C01 Study Notes)

## Key Concepts
In the ML engineering lifecycle, data collection and storage precede processing. Focus on the data engineering steps of generation (source systems like DBs/IoT) and storage. Choose stores based on data type (structured/semi/unstructured), access patterns, cost, performance, and whether data is batch or streaming. Extract, merge, and ingest into SageMaker for training. Troubleshoot capacity/scalability issues by selecting right services and formats.

## Data Formats and Choices
Common formats: CSV/JSON (row-based, human-readable, flexible but slower for analytics); Apache Parquet/ORC (columnar, compressed, efficient for queries/schema evolution, splittable); Avro (row-based, schema evolution); RecordIO (SageMaker-optimized).  

Choose based on access: Columnar (Parquet) for analytics/scans to reduce I/O/cost; row-based for full-record access. Use compression (GZIP/BZIP2) and validated formats. S3 Select works on CSV/JSON/Parquet (including compressed/encrypted) to filter subsets via SQL, cutting latency/cost.

## AWS Storage Options and Tradeoffs
- **Amazon S3**: Primary for data lakes/unprocessed/unstructured data. Highly available, scalable, integrates with Glue/EMR/SageMaker/Athena. Use classes + lifecycle policies (e.g., Standard for immediate access â†’ Glacier after 6 months; Deep Archive for long-term/12-hour access). Ideal for ML pipelines.
- **Amazon EFS**: Scalable file storage; good for shared access but less ideal than S3 for pipelines (weaker integrations).
- **Amazon FSx for NetApp ONTAP**: High-performance file storage for specific workloads.
- Others: EBS (block, with Provisioned IOPS for performance; EBS-optimized instances separate traffic); RDS/DynamoDB (structured; extract via native tools).

**Comparisons**: S3 (object, cheap/scalable lake) vs. EFS (file, POSIX) vs. EBS (block, instance-attached). S3 + Athena for SQL on unstructured vs. Redshift (but overkill for raw) or DynamoDB (PartiQL only). Prefer S3 for centralized ML repos over EFS.

Extract options: S3 Transfer Acceleration (fast global); S3 Select; EBS Provisioned IOPS.

## Ingestion and Streaming
Batch: DMS (to S3 as CSV/Parquet target, full+CDC); Glue/Spark/EMR (merge/transform multiple sources, MapReduce/partitioning/caching). Lambda for parse/load.  

Streaming: Kinesis Data Streams/Firehose (ingest to S3/others); Managed Flink (real-time SQL/transforms, e.g., with Lambda for GZIPâ†’JSON); Kafka (MSK). Firehose destinations limited (stages to S3 then COPY for Redshift; no direct Redshift streaming ingestion).  

**SageMaker**: Ingest to Data Wrangler (Canvas for feature engineering) or Feature Store (via SDK, Spark connector/EMR batch, or Canvas join/export to S3). Pipe mode accelerates S3â†’SageMaker training (faster/cheaper/less space).
