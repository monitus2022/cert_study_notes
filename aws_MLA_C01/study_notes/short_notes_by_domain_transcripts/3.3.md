## Core AWS Services
- **CodePipeline**: Orchestrates full release (source/build/test/deploy stages). Integrates CodeCommit (source), CodeBuild (compile/unit tests/artifacts), CodeDeploy (EC2/Lambda/ECS rollout). Supports manual approvals and multi-environment (test/prod).
- **CodeBuild**: Builds/tests code; runs unit/integration tests; produces artifacts. Quotas apply to concurrent builds.
- **CodeDeploy**: Handles deployments with rollback. Supports pre/post-traffic hooks for validation.
- **SageMaker Pipelines/SDK**: Native ML CI/CDâ€”automates data prep â†’ train â†’ evaluate â†’ deploy. Integrates steps for model building; use Projects for managed templates.
- **Orchestrators**: Step Functions (state machines, retries, nested workflows, idle-time cost optimization vs. Lambda); MWAA (Managed Airflow for data pipelines); EventBridge (rules to trigger training/inference on SageMaker status changes or schedules).
- **Data/Other**: Data Pipeline/Data Exchange for ingestion (RDS â†’ S3); Glue for ETL tests; SAM/CloudFormation for serverless IaC.

Training jobs specify S3 data URLs, compute, output S3, and ECR training image. Inference uses processing jobs (custom Python in container) or batch transform (endpoint-like).

## Deployment Strategies
- **Blue/Green**: Parallel environments; switch traffic (zero downtime, easy rollback).
- **Canary/Linear**: Gradual traffic shift (e.g., 10% then ramp); monitor alarms for auto-rollback.
- **Others**: All-at-once (serverless default), rolling/immutable (EC2), rolling with extra batch.
CodeDeploy enables these for Lambda/EC2; SAM supports all-at-once/canary/linear. SageMaker endpoints use similar traffic shifting.

## Comparisons
- **CodePipeline vs. SageMaker Pipelines**: CodePipeline for general app/ML code; SageMaker for end-to-end ML (training-focused, SDK-native).
- **Step Functions vs. MWAA/Airflow**: Step Functions for AWS-native, serverless ML workflows (no infra mgmt); MWAA for complex existing Airflow DAGs/data orchestration.
- **CodeCommit vs. GitHub**: Both trigger pipelines; CodeCommit is fully managed AWS-native.
- **Processing Job vs. Batch Transform**: Both for batch inference; processing is flexible script-based, transform extends endpoints.
