# Task 3.2: Create & Script ML Infrastructure (MLA-C01)

## Core Concepts: Scalability & Cost
SageMaker Hosting supports ~100 instance types. Prefer **auto scaling** over static fleets for maintainable, cost-effective endpoints.

**Three Auto-Scaling Policies** (combine for resilience):
- **Target Tracking**: Set a CloudWatch metric target (e.g., CPU utilization 70%, invocations/instance, model latency). SageMaker adds/removes instances automatically.
- **Step Scaling**: You own the CloudWatch alarms; EC2 Auto Scaling executes the policy on breach.
- **Scheduled Scaling**: Recurring scale-in/out based on known traffic patterns (e.g., business hours).

**Scale-up vs Scale-out**: To handle higher RPS on fewer hosts, create a **new production variant** with larger/accelerator instances (G5, Inf1) and shift traffic. You cannot resize an existing instance in-place.

**Serverless Inference**: Ideal for unpredictable traffic. SageMaker + Lambda manage scaling, HA, and fault toleranceâ€”no policies needed.

**Cost levers**:
- Managed Spot Instances for training.
- Multi-model endpoints (auto-scale model replicas).
- Dynamic Spot addition behind real-time endpoints or Lambda.

**Key Metrics to Choose for Scaling**: model latency, CPU utilization, invocations per instance, explanations per instance. Monitor via CloudWatch custom dashboards.

## On-Demand vs Provisioned
- On-demand / Serverless: pay-per-use, instant scale, higher unit cost.
- Provisioned: reserved capacity, lower cost at steady load, requires scaling policies.

## Infrastructure as Code (IaC) Trade-offs
| Tool | Style | Best For | Exam Note |
|------|-------|----------|-----------|
| **CloudFormation** | Declarative (YAML/JSON) | Simple, auditable stacks; native AWS | Version in CodeCommit/S3/GitHub; CI/CD triggers on commit |
| **AWS CDK** | Imperative (Python/TS/Java) | Complex logic, reusable constructs | Compiles to CloudFormation |
| **AWS SAM** | CloudFormation extension | Serverless (Lambda, Step Functions, DynamoDB) | Package & deploy ML inference pipelines fast |

Automate stack communication (exports/imports, nested stacks) and enforce VPC configs inside templates for repeatability.

## Containers & Hosting
- Build/push to **Amazon ECR**.
- Orchestrate with **ECS** or **EKS**.
- **BYOC** (Bring Your Own Container) on SageMaker for custom runtimes.
- Deploy via SageMaker Python SDK (`sagemaker.model.Model.deploy()`).

## Secure VPC Configuration
Place endpoints/notebooks in private subnets. Create **Interface VPC Endpoints** (PrivateLink) for:
- SageMaker API
- SageMaker Runtime
- S3 (Gateway endpoint)

Traffic stays on AWS backboneâ€”no IGW/NAT/VPN required. Elastic Network Interfaces get private IPs in your subnets.

**Trap**: Network ACLs that block outbound internet also break SageMaker control-plane calls. Use security groups + VPC endpoints instead.
