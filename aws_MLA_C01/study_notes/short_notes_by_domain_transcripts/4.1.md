# Task 4.2: Monitor and Optimize Infrastructure and Costs

## Key Concepts: Monitoring & Observability
Monitor ML infrastructure using key metrics: utilization (CPU/memory), throughput, availability, scalability, and fault tolerance. Instrument systems for metrics, logs, and traces to enable observability.

- **Amazon CloudWatch**: Core tool for SageMaker endpoints. Tracks endpoint latency (model + overhead), invocations, CPU/memory utilization, data I/O rates, and PredictCount (by request mode for batch/real-time). Use Logs Insights for interactive log analysis, anomaly detection, Application Insights, and ServiceLens (correlates traces/metrics/logs). Create alarms on thresholds; integrate with EventBridge rules for SageMaker job/endpoint status changes to trigger automation (e.g., re-training).
- **AWS X-Ray**: End-to-end distributed tracing to visualize component interactions, diagnose latency, and optimize performance.
- **CloudWatch Lambda Insights**: Aggregates system-level metrics for serverless Lambda-based ML workflows.
- **AWS CloudTrail**: Logs API calls/actions in SageMaker (user/role/service). Enable log file integrity (hashes per file + hourly digests) for tamper-proof audits. Send trails to CloudWatch Logs; create metric filters/alarms (e.g., S3 policy changes) for notifications. Supports re-training triggers.
- **Amazon EventBridge**: Reacts to events (training status, AWS Health/EC2 maintenance) and routes to SNS/Lambda for alerts or remediation (e.g., terminate low-utilization instances via Trusted Advisor).

Dashboards: CloudWatch dashboards or Amazon QuickSight for performance visualization.

## Instance Types, Rightsizing & Latency
Select families based on workload:
- **Compute-optimized**: Batch processing.
- **Memory-optimized**: Large in-memory datasets.
- **General-purpose**: Balanced needs.
- **Inference-optimized** (e.g., Inf1/Inf2 with Inferentia): Up to 3x throughput, 45% lower cost vs. GPUs.

**Rightsizing tools**:
- SageMaker Inference Recommender: Recommends instance types/configs for real-time/serverless endpoints (best performance/cost).
- AWS Compute Optimizer: Analyzes utilization for cost/performance recommendations.

Troubleshoot SageMaker latency: Monitor model latency, overhead latency, multi-model metrics (load/download/cache hit times). Causes include cold starts (pre-warm with test requests), code delays, infrequent requests, or over-utilization. Mitigate with auto scaling, SageMaker Neo (compile for ~2x speed), or Inferentia. Benchmark outside endpoints first.

Handle capacity: Auto scaling, provisioned concurrency (Lambda), service quotas. Use Elastic Load Balancing for elasticity.

## Cost Optimization & Tools
Follow Well-Architected cost pillars: right-size first, increase elasticity (auto scaling), choose pricing models, match storage, and continually monitor.

**Purchasing options**:
- Spot Instances: Lowest cost for interruptible batch jobs.
- On-Demand: Flexible, no commitment.
- Reserved Instances: Savings for steady-state.
- SageMaker/Compute Savings Plans: Flexible across EC2/Fargate/Lambda/SageMaker (best for non-interruptible with compute variety).

**Tools**:
- AWS Cost Explorer: High-level interactive reports; filter by tags; drill-down analysis.
- AWS Cost and Usage Report (CUR): Granular (hourly/daily) breakdowns by product/tags.
- AWS Budgets + billing alarms: Set quotas/thresholds; free-tier alerts.
- AWS Trusted Advisor: Flags low-utilization EC2, cost/performance/security issues.
- Cost Optimization Hub: Aggregates recommendations across accounts/Regions.
- Tagging strategy: Apply cost allocation tags for tracking; enforce via policies. Essential for Cost Explorer filtering and allocation.

Other: Data Lifecycle Manager/AWS Backup for snapshot cleanup; CloudFront/Direct Connect to cut transfer costs.

## Comparisons
- CloudWatch (metrics/logs/alarms) vs. X-Ray (traces for request flows) vs. CloudTrail (API audit logs).
- Cost Explorer (summary/visual) vs. CUR (raw detailed export).
- Inference Recommender (ML endpoint-specific) vs. Compute Optimizer (general resources).
- Spot (cheap/interruptible) vs. Savings Plans (flexible/commit) vs. Reserved (instance-specific).
