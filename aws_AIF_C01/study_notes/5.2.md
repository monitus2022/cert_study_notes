# Task Statement 5.2: Recognize Governance and Compliance Regulations for AI Systems

> **AWS AIF-C01 Exam Focus**: Task 5.2 covers the organizational, regulatory, and technical controls required to govern AI systems on AWS. You must understand key AWS compliance and audit services (**AWS Config**, **Amazon Inspector**, **AWS Artifact**, **AWS CloudTrail**, **AWS Trusted Advisor**), apply the **Generative AI Security Scoping Matrix**, design end-to-end data governance lifecycles, and establish organizational review protocols and team training standards.

---

## 1. AWS Governance and Regulation Compliance Services

AWS provides dedicated governance tools to automate evidence collection, audit system configurations, and demonstrate compliance with international standards (e.g., ISO, SOC 1/2/3, HIPAA, GDPR).

| AWS Service | Primary Governance Role | Real-World AI Compliance Function |
| :--- | :--- | :--- |
| **AWS Config** | Configuration Tracking & Drift Detection | Continuously evaluates AWS resource configurations against compliance rules (e.g., flagging unencrypted S3 buckets containing training data or public SageMaker endpoints). |
| **Amazon Inspector** | Automated Vulnerability Management | Scans compute infrastructure (EC2 instances, container images in ECR, Lambda functions) hosting ML/AI code for software vulnerabilities and network exposure. |
| **AWS Artifact** | Central Compliance Portal | Provides on-demand access to AWS security and compliance reports (SOC, ISO certifications, PCI-DSS) and allows signing compliance agreements (e.g., Business Associate Addendums [BAA] for HIPAA). |
| **AWS CloudTrail** | API Logging & Audit Trails | Records all API activity across AWS AI services (e.g., `InvokeModel`, `CreateKnowledgeBase`), maintaining immutable logs for forensic analysis and regulatory audits. |
| **AWS Trusted Advisor** | Best Practice Optimization Checks | Evaluates AWS environment configurations against best practices across security, fault tolerance, and cost, flagging exposed resources or open security groups used by AI workloads. |
| **AWS Audit Manager** | Automated Evidence Collection | Maps AWS resource configurations to regulatory frameworks (NIST, GDPR, HIPAA) to continuously gather audit evidence and streamline compliance reporting. |

## 2. The Generative AI Security Scoping Matrix

The **AWS Generative AI Security Scoping Matrix** is a foundational framework that categorizes AI applications into 5 distinct scopes based on organizational ownership and model control. It defines whether an enterprise adopts a **buyer's perspective** or a **builder's perspective**.

### The 5 Scopes of Generative AI Workloads

1.  **Scope 1: Consumer AI Application** *(Buyer Perspective)*
    *   *Examples*: Public Web Chatbots, free external AI assistants.
    *   *Security Responsibility*: Data privacy risk management. Focus on policy enforcement to ensure employees do not submit proprietary corporate data or PII into public third-party tools.
2.  **Scope 2: Enterprise SaaS / Off-the-Shelf AI Application** *(Buyer Perspective)*
    *   *Examples*: Commercial enterprise AI software (e.g., Microsoft 365 Copilot, enterprise AI search).
    *   *Security Responsibility*: Contractual protections and vendor risk assessment. Verifying terms of service ensure customer data is opted out of base model training, and validating vendor SOC/ISO compliance via **AWS Artifact**.
3.  **Scope 3: Pre-Trained / Self-Hosted FM with RAG or Agents** *(Builder Perspective)*
    *   *Examples*: Building custom applications on **Amazon Bedrock** using Knowledge Bases (RAG) or Agents.
    *   *Security Responsibility*: Application-level governance. Managing access control to private data stores, securing vector databases, setting up **Guardrails for Amazon Bedrock**, and enforcing tool execution policies.
4.  **Scope 4: Custom Fine-Tuned Model** *(Builder Perspective)*
    *   *Examples*: Fine-tuning a foundation model on proprietary corporate datasets via **Amazon Bedrock Custom Models** or **SageMaker JumpStart**.
    *   *Security Responsibility*: Model artifact and training data governance. Documenting training data provenance via **SageMaker Model Cards**, managing S3 dataset lifecycles, and securing custom model endpoints.
5.  **Scope 5: Custom FM Trained from Scratch** *(Builder Perspective)*
    *   *Examples*: Pre-training a proprietary foundation model from ground zero using custom compute clusters (**AWS Trainium**).
    *   *Security Responsibility*: Maximum governance and risk management. Pre-training dataset curation, copyright/IP risk management, environmental carbon footprint tracking, and full infrastructure protection.

## 3. Data Governance Strategies Across the AI Lifecycle

Establishing control over data throughout its lifecycle is mandatory for meeting regulatory requirements.

*   **Data Lifecycle Management**: Defining explicit stages (**Ingestion $\rightarrow$ Preprocessing $\rightarrow$ Training/Indexing $\rightarrow$ Retention $\rightarrow$ Archival $\rightarrow$ Disposal**) using **Amazon S3 Lifecycle Policies** to transition aging datasets to S3 Glacier or execute automated, compliant deletion.
*   **Data Residency & Sovereignty**: Configuring AWS service deployments strictly within specific geographic AWS Regions to satisfy data residency laws (e.g., ensuring EU customer data remains within `eu-central-1`).
*   **Audit Logging & Observability**: Capturing operational telemetry, token consumption metrics, and prompt/completion payloads using **Amazon CloudWatch Logs** and **Amazon Bedrock Invocation Logging** with retention periods aligned with legal requirements.
*   **Continuous Compliance Monitoring**: Deploying **AWS Config Rules** to automatically detect and remediate compliance drift (e.g., auto-remediating an unencrypted S3 bucket storing vector embeddings).
*   **Data Retention & Immutable Storage**: Utilizing **Amazon S3 Object Lock (WORM - Write Once, Read Many)** to store audit logs and compliance-critical training datasets in an un-alterable state to prevent tampering during legal discovery.

## 4. Governance Protocols, Frameworks, and Team Readiness

Implementing AI governance requires organizational review strategies and team training alongside technical tools.

*   **Cross-Functional AI Review Committees**: Establishing governance boards comprising legal counsel, security officers, compliance managers, data scientists, and business stakeholders to evaluate risk.
*   **Review Cadence & Strategies**:
    *   *Pre-Deployment Gatekeeping*: Reviewing AI applications prior to production launch to audit accuracy, hallucination risks, bias metrics (**SageMaker Clarify**), and data privacy controls.
    *   *Periodic Audit Cadence*: Scheduling quarterly or semi-annual evaluations of production AI workloads to inspect model drift, latency SLAs, token spend, and regulatory updates.
*   **Transparency Standards**: Enforcing clear user disclosures when interacting with AI systems (e.g., "You are chatting with an AI assistant") and maintaining **SageMaker Model Cards** (for custom models) or reviewing **AWS AI Service Cards** (for managed services).
*   **Team Training & Skill Requirements**: Establishing formal training programs to educate developers, prompt engineers, and business users on responsible AI guidelines, prompt injection risks, PII protection, and internal AI usage policies.

## 5. Exam Decision Rules & Common Pitfalls

### High-Yield Decision Rules
1.  **Select AWS Artifact** when a scenario asks for a **central repository to download AWS SOC, ISO, or PCI-DSS compliance reports or sign HIPAA BAAs**.
2.  **Select AWS Config** when you need to **continuously monitor resource configurations for compliance drift and enforce security rules automatically**.
3.  **Select Amazon Inspector** to **automatically scan compute instances, container images, or Lambda functions for software vulnerabilities**.
4.  **Select AWS Audit Manager** to **automate compliance evidence collection and map AWS resource configurations to regulatory standards (GDPR, HIPAA, NIST)**.
5.  **Select Buyer Perspective (Scopes 1 & 2)** in the GenAI Security Scoping Matrix when **evaluating off-the-shelf consumer or enterprise SaaS AI apps with zero model infrastructure control**.
6.  **Select Builder Perspective (Scopes 3, 4, & 5)** in the GenAI Security Scoping Matrix when **developing custom RAG applications, fine-tuning models, or pre-training custom FMs**.
7.  **Select S3 Object Lock (WORM)** when compliance mandates **preventing compliance audit logs or training datasets from being modified or deleted**.

### Common Exam Traps
*   **Trap 1: Confusing Scope 1 and Scope 2 in the Scoping Matrix**
    *   *Scope 1* = Consumer AI apps (high risk of data submission to public models; buyer perspective).
    *   *Scope 2* = Enterprise SaaS apps (vendor enterprise SLA guarantees data is not used for base model training; buyer perspective).
*   **Trap 2: Using AWS Artifact to Audit Custom Code**
    *   *AWS Artifact* provides compliance reports for *AWS infrastructure and managed services*. To audit vulnerabilities in *your custom application code or container images*, use **Amazon Inspector**.
*   **Trap 3: Confusing AWS Config with AWS CloudTrail**
    *   *AWS Config* tracks *resource state and configuration drift* over time (e.g., Is S3 encryption ON?).
    *   *AWS CloudTrail* tracks *API calls and user activity history* (e.g., Who called `InvokeModel` at 2:00 PM?).
